# Roadmap

Roadmap 是尚未实现工作的动态清单，规定开发顺序，不承诺具体发布日期。每个目标版本只描述剩余能力和退出标准；实现细节由开发者指南约束，Review 只提供证据。

## 维护规则

- 一项工作达到完成定义并通过验收后，立即写入更新日志 `Unreleased`，同时从本页删除；
- 一项工作只完成部分时，拆分后删除已完成部分，只保留可以继续执行的剩余内容；
- 某个目标版本不再有未完成事项时，删除整个版本段落；正式发布时由更新日志保存版本历史；
- 本页不使用完成勾选、删除线、“已完成”小节或完成日期；Roadmap 不是状态看板和历史档案；
- 同一项内容不得同时以“已实现”身份存在于更新日志和 Roadmap。
- `0.x` 目标版本按本页顺序串行推进；前一版本未达到退出标准时，后续版本只能记录问题，不提前实施；
- 一次开发变更只推进当前版本一个可验收切片，包含其必需的迁移、测试和文档。公共输入改变时，以一条最小执行链为单位交付，不能用仅接受新字段、下游忽略其含义代替完成；
- 切片应能独立 Review 和回退；允许迁移同一切片必需的多个消费者，不扩大为无关重构。输入、求解及结果恢复未接通前，不发布完整能力。

## 版本规则

- `0.x`：正式发布前的契约收敛和发布准备；
- `1.0.0`：小范围测试版本；
- `1.x`：小范围测试期间的功能与缺陷修复，自有契约始终固定 `1.0.0`，只维护当前一套；
- `2.0.0`：首个面向公众发布的版本，发布前完善正式兼容与迁移政策，不在此前开发多版本系统。

“二期”“Phase 2”等阶段名不再等同于 `2.0.0`。

## `0.x` 实现主线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 和前端收敛（0.13–0.14）
  → 财务与预测计算收敛（0.14.5）
  → 扩展、运维与发布（0.15–0.17）
```

### 安全范围

- 部署模型是管理员集中部署、普通使用者通过界面和 API 使用；管理员属于受信任运维角色，不把管理员主动越权作为攻击模型。
- 必须防护未登录或低权限使用者、外部请求和恶意输入对认证、项目范围、上传/下载、诊断、命令执行和资源使用边界的突破。
- 管理员权限只做基本的误操作防护：清晰的作用范围、危险操作确认、版本/恢复路径；不引入双人审批、管理员相互隔离、零信任架构或重型安全审计体系。

### 财务输出与附加分析范围

- `1.0.0` 基本财务输出为 NPV、IRR、静态回收期和动态回收期，统一采用项目投资口径，并附单位、计算口径、状态和来源。
- 提供逐年现金流明细表及导出，展示投资、年度净现金流、折现及累计过程；页面、导出和指标使用同一冻结结果。
- 运行起始年归项目计算基线、创建时固定；财务评价总年限（包含建设期）、运营年限、整数年建设期、付款比例计划、维护／换新支出与折现率由用户显式确认并固定到计算快照（确认字段、提交关联与冻结块见财务计算“评价确认与快照冻结”，无默认；自由字典式 `baseline-confirm` 不作参数来源）。不沿用 `0.08`，不塞进 `FinanceProfile` 或封闭 `CalculationConfig`。
- 计算在完整运行时间轴上整体求解；本课题首年启动建设，建设期与支付安排明确，优化建设选择、容量与全周期运行，不优化建设年份，中期扩建另建计算课题。评价现金流包含建设支出及完整运行期，与运行时轴的对应关系明确，不默认立即投产。逐年现金流由同一全周期真实结果按年归集，不以未经等价证明的单年复制、逐年独立求解或预先固定选建方案与容量代替整体模型；内部等价优化遵守生成器契约。年度输入差异由覆盖全期的连续序列直接表达，不设逐年绑定。
- 敏感性计算及其附加参数、批量参数扫描、不确定性分析、资本金评价和额外财务指标安排在 `1.2.0`。


## `0.15.0` — Provider 扩展与工程全流程验收

目标：在现有公开边界上，验证外部扩展无需修改核心模块，并由独立工程用户完成建模、全周期求解、财务评价与导出。工程测试只维护本节一份清单，不另设重复验收阶段。

### Provider 扩展验收

1. 用仓库外测试内容/扩展依次验证设备 YAML、数据 CSV、公共方程 contract、GeneratorProvider、ResultAdapterProvider、ExecutorProvider 和存储扩展。
2. 发布可运行扩展示例、四种文件契约测试工具，以及设备稳定 ID、publication revision 与 provider 精确版本固定规则。

### 工程用户全流程验收

| 验收内容 | 完成依据 |
| --- | --- |

| 独立方案与冻结 | 分别保存并计算各工程方案，核对设备、费用、计量、税务与基准归属；任务固定所选输入和依赖，修改当前草稿不改变历史任务 |
| 全周期计算与状态 | 真实完成构模、排队、Worker 执行及全周期求解，记录耗时、模型规模和资源使用；失败区分输入问题、转换条件不足及实际执行／求解失败，不能停在提交成功或运行中 |

| 结果、导出与交付 | 核对状态、结果页、时序及财务明细、Excel 和项目包的一致性，验证当前契约文档往返与导入后引用、修订和冻结结果；归档操作证据、独立核算及问题关闭结论 |

退出标准：新增或替换 provider 不修改无关业务模块、GUI 映射或通用 runtime，任一注册失败不发布部分状态；独立工程方案使用正式模型和通用约束完成真实求解、同源财务评价、结果核对与导出，阻断问题均已关闭或有明确范围裁决。提交成功、运行中、CI 绿色及阶段归并不单独作为工程验收通过。

### 实测问题与性能优化

多年模型压缩不作为独立前置阶段或预设交付。仅在上述实测发现可复现的构模、内存或求解瓶颈后，定位原因、确定可测目标，再实施针对性优化；不因尚未证实的性能风险阻断验收。

优化必须保持正式模型及原约束语义，用同一输入对照正确性与资源效果；多最优解不要求曲线逐点相同。不能证明运行块等价时保留独立决策，不以近似典型期、私加终期状态或重置状态代替全周期计算。

#### 大规模构模与文件交接整改

针对源码可见的整包文本、参数与字节交接，M3／M4贯通实现及本地验证事实见更新日志。当前交付仍须完成精确提交的云端CI、审查合入及部署核对，然后交测试者进行独立工程完整验收。以下保留本次收口的验收要求，不追加新的优化切片；不再安排没有新线索的求解策略试验，本项不改变数学问题、时间域或用户工程输入。

控制面与计算解释器隔离须独立完成Review、回归与部署核对；它解决长停顿阻塞续租，不作为本项内存优化完成依据。保持租约TTL、过期回收、fencing和阶段资产持久化，不以放宽过期续租、增加重试次数或关闭GC换取通过。

**衔接问题与整改对象**

| 衔接位置 | 当前问题 | 修复落点 |
| --- | --- | --- |
| 最终矩阵 → MPS | 数值矩阵与紧凑列方向索引之外，全部文本行、拼接字符串和编码字节仍相继叠加 | 按列分块writer；转置所需数值缓冲计入预算，不恢复Python矩阵对象图 |
| 结果声明／来源 → 参数文件 | 财务仿射式被复制进多个声明，来源目标和序列列名全量列举，JSON先完整构造再编码 | 共享冻结表达式引用、显式列位置、紧凑来源映射和有序记录写出 |
| Bundle → 检查点 → Runtime／恢复 | `files`和存储接口要求完整`bytes`；落盘后仍整包读回并重写运行目录 | 统一只读分块内容协议；检查点发布后保留对象引用，执行／恢复按块读取 |
| 求解输出 → 结果适配／封存 | 输出分块读后仍join；适配器重扫MPS找列，参数全量解码，结果freeze／thaw／编码叠加 | 按块交付原始输出；消费同次生成的列映射；流式读声明和序列化，保留一次必要的结果表示 |

**共同约束**

- 完整收集关系是语义屏障，不要求先为每个时间步建立一套Python表达式对象。结构共享不意味着共享不同实例／时步的决策、参数或可变推导结果。
- 同一次构模只有一个符号身份分配和一份实际数值关系。关系族是语义来源，紧凑矩阵是其派生表示；分析、writer和结果映射不能分别重建第二份业务模型。
- 内部整数编号仅为槽位；公开实例、模型、关系和对象ID保持不透明。最终求解列顺序由生成器显式分配，内部槽位与求解列位置的映射唯一，不按列名反解。
- 保留逐步系数、完整索引域、初始状态、滞后连接、块间／跨年连续性，以及原税务与财务期间。保留确定性传播顺序、预算和停止语义，精确消元及保守向外舍入不改成无证明的浮点近似。
- 不删除互斥、不加epsilon或假想Big-M、不增加终期状态、不做典型年／年度独立求解，不引入HiGHS专用参数或新的分布式／磁盘图分析框架。
- 不以关闭GC、`gc.freeze`或提高内存额度定义修复成功。大文件落盘不等于大数据离开内存；每一交接都须明确当前所有者和上游释放时点。
- 跨模块只传公开不可变契约、内容协议或对象句柄，不传宿主机路径、裸文件句柄、数据库会话或solver私有对象。生成器继续纯转换，不访问storage、数据库或自行管理临时目录。
- 更新当前唯一的自有`1.0.0`契约和全部配套消费者，不增加版本协商、旧包回退、重复内容校验或hash。公开单关系数学贡献仍可使用小型表达式对象，不要求外部设备／方程provider改用生成器私有数组。
- 类型化可信内部表示不重复运行公开输入校验；实际运算溢出、无法精确转换和真实I/O错误仍在发生处明确报告。不能将删除冗余校验误作删除必要的领域规则或外部进程输出边界。

**交付核对：端到端内容交接与结果恢复（M3 → M4）**

| 切片 | 交付范围 | 独立退出依据 |
| --- | --- | --- |
| M3：端到端分块内容交接 | 先修订Bundle内容、storage读写与runtime输出交接的当前正式契约，再在同片贯通生产者、检查点、恢复、执行器输入、原始输出保存及导出。使用统一只读、可重复分块读取的内容协议，小内容可为同协议的内存实现；不设置旧bytes包／新文件包两种执行模式。MPS从紧凑矩阵按列分块写出，不再`lines→join→encode`。生成器返回确定性内容，application负责消费并落盘，不向生成器注入数据库或存储路径 | 小模型真实生成／执行／适配成功；大合成文件从生成到落盘、恢复、Runtime复制均不整包read／join，峰值由矩阵和有界缓冲解释。发布生成检查点后将生成期内容替换为对象引用并释放矩阵；解与回执持久化成功后才清理运行目录，恢复不重跑已提交的求解 |
| M4：紧凑参数与直接结果恢复 | 参数改为小头部＋明确声明的有序记录文件，冻结表达式只存一份，其使用处保存表达式引用；序列、单位及来源引用同次分配的实际列位置。配套适配器逐记录读取，主解用紧凑数值保存，不为找列重扫MPS，不全量解码巨型参数JSON。结果封存避免全量freeze／thaw／to_dict副本叠加，按已有输出形状分块序列化；不改页面、财务评价和导出的业务含义 | 求解状态、单位、逐步结果、建设状态、全部财务事实及来源与原语义一致；实际表达式求值顺序和数值精度保持。缺声明按当前契约实际错误处理，不回退扫MPS；恢复路径与首次执行使用同一适配路径，不另建“快速但缺事实”的结果 |

M3的内容来源可在生成期由不可变紧凑数据确定性地产生字节块；全部实际字节落盘并提交检查点后，application才用对象引用替换生成期来源。分块读取不得把数据库会话或操作系统文件句柄保存在跨模块契约中。内容实际大小由写入过程取得；中途生成／写入失败不发布阶段成功。恢复以已提交的manifest、回执和对象引用为准，不增加摘要复核；实际文件I/O失败保持可见。

M4只共享同一已冻结表达式和显式映射，不做按数值近似合并、任意符号因式分解或改换浮点累加顺序。参数文件布局属于配套生成器／适配器当前契约；manifest逐项声明全部文件，通用Runtime不解释数学记录。最终业务结果可随输出量增长，但不能同时保留原始大包、巨型参数对象图、多份结果树和整份序列化文本。

**验证、资源目标与交接**

1. 每个切片独立实现、Docker定向验证、Review及提交；M3须包含全部必要消费者的可运行迁移，不交付只接受新协议而下游仍要求整包bytes的半条链。计划本身不批准修改宪法；若具体接口设计确需改变纯生成、模块职责或边界，实施前另行取得裁决。
2. 正确性覆盖：时变正／负／零系数，初始与滞后状态，跨块／跨年连接，多实例别名，零界／单侧／未知界，相关表达式界，冲突与预算耗尽，全部条件转换、建设费用、VAT／所得税结转、结果引用及模型来源。多个最优解不要求轨迹逐点相同；小模型核对原关系和目标，结果数值用已声明容差。
3. 性能按关系数、变量数、非零元数、表达式项数和输出字节分别解释，分阶段报告RSS、cgroup内存、swap、GC总耗时／最大停顿与正常耗时；不把tracemalloc运行与普通运行混作提速对照，也不把不同资源指标直接相加。公开规模递增模型在同环境至少3次普通运行，确认热点及整体资源效果，不仅比较模板编译次数。
4. 资源对照沿用已复现额度，8GiB作为原现场比较点而不是产品硬性容量声明。目标是在该比较点完成原输入构模，不靠扩大额度隐藏回归；以关系分析的实测数值量为基线估算全链预算。若单份必需数据已超过该额度，列明依据和实际所需资源，请用户裁决，不擅自改模型或把增配包装为优化成功。工作内存不承诺常数：实际数值矩阵／界随变量与非零元增长，文件读写的额外缓冲应有界。
5. 最终使用同一冻结输入完成生成、全部文件落盘、检查点恢复及运行前准备，确认不存在把峰值从分析搬到writer、恢复或参数读取的情况。大工程结果适配优先复用已提交的真实解；没有留存解时不伪造工程验收，以公开规模模型验证后交测试者真实求解。
6. 精确SHA的CI通过、部署与镜像核对后，由测试者恢复独立方案全周期验收。开发验证不重复发起小时级求解、不修改原工程草稿／确认数据和旧证据。私有输入与原始日志留在私有验收目录，不进入公开计划、样例或PR评论；构模整改完成不等于0.15全周期验收完成。

### 后续实施纪律

网络、金额、基准与结果继续遵循[架构蓝图](../developer-guide/zh-CN/architecture.md#领域语义与数学表达)及各自正式契约。不借验收或优化扩展税务主体、融资、中期扩建、自动分配政策、汇率系统或专用业务表单。

- 可复用且范围、基线仍适用的既有验收证据直接引用，不重新派修已交付切片，也不因阶段归并重复整套测试；新增问题按实际影响补充回归。
- 同一公共表达式、界分析和生成入口由同一主线维护。算法对照先保持隔离，不直接替换正式执行链。
- 每个改变输入的修复先在所属格式页明确字段、引用、覆盖语义与结果含义，再实现一条最小执行链；不让开发者各自解释新的引用写法，不以不断补充单个案例字段代替公共能力修复。
- 2.0 正式发布前只维护当前一套自有 `1.0.0` 契约，字段、实现、样例和测试一起更新；不让用户协调配套版本。模型发布形成新 revision，旧任务固定旧依赖；修订不得覆盖历史结果或自动清空用户项目。
- 缺陷修复先用小规模通用性质与手算反例验证，再恢复受影响的工程步骤；GUI 按实际变更范围做 Docker 浏览器验收。私有工程数据和敏感信息不进入公共示例、开发输入或 PR 评论。
- 惰性互斥、静态松弛及运行块压缩分别需要证明与实测，不作为必选算法。若候选算法需要改变通用 Runtime 的职责或生成器输入边界，先提交对应 ADR，批准前保持现有宪法边界。
- 文档维护只做相关结构、链接和语义检查，不因纯文档修改重跑完整求解或 Playwright。

## 小范围测试后的 `1.x`

以下顺序来自既定产品意图，具体产品版本可在开发启动前调整；这些功能不触发自有契约逐次升版：

以下 MCP 接入、账号连接与多端同步要求仅在 `1.0.0` 发布后实施，不改变当前生效契约，不作为 `0.x` 或 `1.0.0` 的开发任务与退出条件。

### `1.1.0` — 模型与算法、Provider SDK 与设备扩展

- 新增面向所有已登录用户的一级导航“模型与算法”，固定包含“模型库”“算法插件”“共享园地”三个入口；
- 模型库支持网页结构化表单、在线编辑 YAML 和上传 YAML，三条路径统一生成、校验和保存 `ies.device-model` 不可变 publication，并让已安装设备的稳定 ID、revision、状态和公开描述进入系统建模选择器；
- 算法插件支持上传 `ies.algorithm-plugin` ZIP；包内同时交付装配加工程序、算法程序、依赖锁、输入输出声明和测试样例，由独立容器化隔离运行器执行，并让校验通过的已安装精确版本进入计算配置选择器；
- 所有者可申请把设备不可变 publication 或插件精确版本加入共享园地，管理员批准后其他用户可浏览并安装；安装只新增对既有 publication/object ID 的引用；
- 发布统一设备内容、公共方程 contract、生成器、执行器和结果适配器扩展工作流，以及合法/非法包、契约测试和 ID/revision/provider 版本固定工具；
- 完成设备扩展、算法扩展、财务扩展（多国税务数据等）功能；
- 按验证顺序增加氢能设备、热/冷储能、风电、燃气内燃机、余热锅炉、吸收式制冷机和需求响应；
- 外部数据只形成可审计的候选数据版本。

退出标准：用户可管理自己的模型与算法目录，可申请共享并从共享园地引用安装；只有后端确认 `selectable=true` 的设备 publication 或插件精确版本出现在对应选择器；历史项目和任务继续按固定对象 ID、publication revision 与依赖锁解释；API 和普通 Worker 不加载用户代码，插件只在受限隔离运行器中执行。

### `1.2.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线，以及通过新修订和明确迁移受控变更项目计算基线；
- 场景、稳定性和多目标候选比较；
- 敏感性计算及附加参数配置、批量参数扫描与不确定性分析；
- 在 NPV、IRR、静态回收期和动态回收期基本输出之上，按独立输入契约和验收口径扩展额外财务指标（如 LCOE）；
- 增加资本金评价，独立定义自有资金、贷款、利息与还本安排，并明确区分项目投资与资本金指标；
- 全链路结果与版本差异解释。

### `1.3.0` — MCP 接入与智能化数据准备

- 通过 MCP 向外部 AI 客户端开放项目操作能力，由外部客户端组织交互，不自建 Agent；复用后端业务能力与模型文档，不另建 AI 专用业务规则；
- 本地与远程部署统一由管理员管理账号和系统、工程师持有项目并计算，管理员不直接开展项目计算，MCP 使用工程师身份；
- MCP 连接提供专用网页登录窗口：已初始化实例使用工程师账号登录；首次初始化提供管理员设置／改密与工程师创建流程，最终只为工程师签发连接凭证；
- 登录后将鉴权文件下载至连接端本地供后续连接使用，文件保存可撤销的连接凭证而非账号密码；凭证由连接端使用，不进入 AI 对话，失效后重新认证；
- 允许浏览器多窗口与 MCP 同时连接，不因新连接挤掉原会话；以后端已保存数据为准，通过定时刷新和手动刷新同步项目参数、任务状态与结果；未保存编辑不被自动覆盖，保存版本冲突明确提示；
- 新建面向当前项目待计算方案的确认网页，现有项目页面继续用于查看和编辑完整参数；两者使用同一后端事实，不维护第二份参数；具体页面交互在实施时设计；
- AI 生成候选输入，用户确认关键参数，发起计算时才创建任务并冻结输入；刷新不改变历史任务输入与结果；
- 不绕过 schema、单位、权限和校验。
