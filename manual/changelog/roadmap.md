# Roadmap

Roadmap 是尚未实现工作的动态清单，规定开发顺序，不承诺具体发布日期。每个目标版本只描述剩余能力和退出标准；实现细节由开发者指南约束，Review 只提供证据。

## 维护规则

- 一项工作达到完成定义并通过验收后，立即写入更新日志 `Unreleased`，同时从本页删除；
- 一项工作只完成部分时，拆分后删除已完成部分，只保留可以继续执行的剩余内容；
- 某个目标版本不再有未完成事项时，删除整个版本段落；正式发布时由更新日志保存版本历史；
- 本页不使用完成勾选、删除线、“已完成”小节或完成日期；Roadmap 不是状态看板和历史档案；
- 同一项内容不得同时以“已实现”身份存在于更新日志和 Roadmap。
- `0.x` 目标版本按本页顺序串行推进；前一版本未达到退出标准时，后续版本只能记录问题，不提前实施；
- 一次开发变更只推进当前版本一个编号事项中的一个可验收切片，只改一个公开 contract、一个模块或一条用户流程，并包含该切片必需的迁移、测试和文档；
- 同一编号事项涉及多个消费者时，一次只迁移一个消费者；切片如果仍不能独立 Review 和回退，必须先继续拆分，不以超大变更包合并。

## 版本规则

- `0.x`：正式发布前的契约收敛和发布准备；
- `1.0.0`：首个正式稳定版；
- `1.x.0`：向后兼容的新功能；
- `1.x.y`：对应功能线的缺陷修复；
- `2.0.0`：保留给不兼容的架构或公开契约重构。

“二期”“Phase 2”等阶段名不再等同于 `2.0.0`。

## `0.x` 实现主线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 和前端收敛（0.13–0.14）
  → 扩展、运维与发布（0.15–0.17）
```

### 安全范围

- 部署模型是管理员集中部署、普通使用者通过界面和 API 使用；管理员属于受信任运维角色，不把管理员主动越权作为攻击模型。
- 必须防护未登录或低权限使用者、外部请求和恶意输入对认证、项目范围、上传/下载、诊断、命令执行和资源使用边界的突破。
- 管理员权限只做基本的误操作防护：清晰的作用范围、危险操作确认、版本/恢复路径；不引入双人审批、管理员相互隔离、零信任架构或重型安全审计体系。

### 财务输出与附加分析范围

- `1.0.0` 基本财务输出为 NPV、IRR、静态回收期和动态回收期，统一采用项目投资口径，并附单位、计算口径、状态和来源。
- 提供逐年现金流明细表及导出，展示投资、年度净现金流、折现及累计过程；页面、导出和指标使用同一冻结结果。
- 运行起始年归项目计算基线、创建时固定；财务评价总年限（包含建设期）、运营年限、整数年建设期、付款比例计划、维护／换新支出与折现率由用户显式确认并固定到计算快照（确认字段、提交关联与冻结块见财务计算“评价确认与快照冻结”，无默认；自由字典式 `baseline-confirm` 不作参数来源）。不沿用 `0.08`，不塞进 `FinanceProfile` 或封闭 `CalculationConfig`。
- 计算在完整运行时间轴上整体求解；本课题首年启动建设，建设期与支付安排明确，优化建设选择、容量与全周期运行，不优化建设年份，中期扩建另建计算课题。评价现金流包含建设支出及完整运行期，与运行时轴的对应关系明确，不默认立即投产。逐年现金流由同一全周期真实结果按年归集，不以单年结果复制、逐年独立求解或预先固定选建方案与容量代替整体模型。年度输入差异由覆盖全期的连续序列直接表达，不设逐年绑定。
- 敏感性计算及其附加参数、批量参数扫描、不确定性分析、资本金评价和额外财务指标安排在 `1.2.0`。


## `0.13.0` — 项目版本与恢复 GUI

目标：只补齐项目版本、恢复、结果应用和项目包导入的用户可见闭环，不重复建设现有后端 API。

2. 让候选方案“应用”调用项目结果应用用例，实际创建新版本；历史结果页明确绑定其任务快照（来源接线、参数预览与来源版本基线应用已随 S3-A/S3-B 交付待复审）。
3. 提供项目包上传、校验提案、冲突展示和确认恢复 GUI，并按实际控件同步使用者指南。

退出标准：用户可在 GUI 中完成“创建版本 → 应用方案 → 查看历史结果 → 恢复/导入”，且新旧版本和审计记录可见。

## `0.14.0` — 前端严格契约与验收收尾

目标：只清理认证、数据、财务配置、计算、分析、结果和导出界面中的兼容猜测和未验收边界，不重复建设已经贯通的用户流程。

1. 前端按 feature 垂直切分，分离 contract、领域模型、表单和 mapper；删除跨 feature 内部导入、模块级业务缓存和响应形状猜测。
2. 删除财务旧扁平字段回退与静默默认，统一服务器状态、错误、离线、并发保存、刷新和深链接行为。
3. 补齐项目版本/恢复、首发范围内的基本结果评估与帮助中心的 Docker 浏览器验收，修复帮助中心当前未通过的 Markdown 场景；结果页与导出验收覆盖 NPV、IRR、静态回收期和动态回收期的数值、口径和异常状态，两种回收期分别展示，并提供与指标一致的逐年现金流明细表及导出；敏感性等附加分析按 `1.2.0` 验收；画布拖放由人工验收，其他 GUI 使用 Playwright。

退出标准：从登录到导出的关键流程无兼容猜测、假资源或错误空数据降级；桌面/移动、中英文界面和简体中文帮助中心通过验收。

## `0.15.0` — Provider 扩展验收

目标：在公开边界完成后，用仓库外视角验证扩展不需修改核心模块。

1. 用仓库外测试内容/扩展依次验证设备 YAML、数据 CSV、公共方程 contract、GeneratorProvider、ResultAdapterProvider、ExecutorProvider 和存储扩展。
2. 发布可运行扩展示例、四种文件契约测试工具，以及设备稳定 ID、publication revision 与 provider 精确版本固定规则。

退出标准：新增或替换 provider 不修改无关业务模块、GUI 映射或通用 runtime；任一注册失败不发布部分状态。

## `0.16.0` — 运维、备份与故障演练

目标：在功能与扩展边界冻结后，验证实例可判断、证据可观测、数据可恢复。

1. 建立独立聚合的 health/readiness，纳入 API、Worker、数据库、队列、存储和全部必需 provider；缺失依赖的实例不承接流量或任务。
2. 完成日志、追踪和配额验收，使请求、任务、attempt、Bundle、receipt 和结果可以互相定位。
3. 完成数据库/对象备份恢复、容量故障、对象缺失或不可读、中断写入和 provider 故障注入演练。

退出标准：不可正确处理请求或任务的实例不 ready；数据库与对象故障不产生静默成功；备份可恢复到可解释的任务快照。

## `0.17.0` — `1.0.0` 候选

目标：功能冻结，只处理发布阻断和文档偏差。

1. 完成 Docker 全量测试、数据迁移演练和独立系统浏览器验收。
2. 完成第三方攻击面复审、对外入口权限、版本、镜像、许可、更新日志、备份与回滚核对；不以管理员相互隔离或额外审批作为发布门槛。
3. 冻结公开 contract 和 `1.0.0` 使用者指南；对全部当前限制给出已解决证据或明确范围裁决。

退出标准：所有发布门禁通过，且候选期没有新增功能或公开契约变更。

## `1.0.0` — 首个正式版本

发布条件：`0.17.0` 候选无未关闭阻断，正式文档与实际 GUI 一致，历史任务可追溯，升级与恢复可执行。

## 正式发布后的 `1.x`

以下顺序来自旧 Phase 2 路线图的稳定产品意图，具体版本可在开发启动前调整，但必须遵循“新功能升 MINOR”：

### `1.1.0` — 模型与算法、Provider SDK 与设备扩展

- 新增面向所有已登录用户的一级导航“模型与算法”，固定包含“模型库”“算法插件”“共享园地”三个入口；
- 模型库支持网页结构化表单、在线编辑 YAML 和上传 YAML，三条路径统一生成、校验和保存 `ies.device-model` 不可变 publication，并让已安装设备的稳定 ID、revision、状态和公开描述进入系统建模选择器；
- 算法插件支持上传 `ies.algorithm-plugin` ZIP；包内同时交付装配加工程序、算法程序、依赖锁、输入输出声明和测试样例，由独立容器化隔离运行器执行，并让校验通过的已安装精确版本进入计算配置选择器；
- 所有者可申请把设备不可变 publication 或插件精确版本加入共享园地，管理员批准后其他用户可浏览并安装；安装只新增对既有 publication/object ID 的引用；
- 发布统一设备内容、公共方程 contract、生成器、执行器和结果适配器扩展工作流，以及合法/非法包、契约测试和 ID/revision/provider 版本固定工具；
- 完成设备扩展、算法扩展、财务扩展（多国税务数据等）功能；
- 按验证顺序增加氢能设备、热/冷储能、风电、燃气内燃机、余热锅炉、吸收式制冷机和需求响应；
- 外部数据只形成可审计的候选数据版本。

退出标准：用户可管理自己的模型与算法目录，可申请共享并从共享园地引用安装；只有后端确认 `selectable=true` 的设备 publication 或插件精确版本出现在对应选择器；历史项目和任务继续按固定对象 ID、publication revision 与依赖锁解释；API 和普通 Worker 不加载用户代码，插件只在受限隔离运行器中执行。

### `1.2.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线，以及通过新修订和明确迁移受控变更项目计算基线；
- 场景、稳定性和多目标候选比较；
- 敏感性计算及附加参数配置、批量参数扫描与不确定性分析；
- 在 NPV、IRR、静态回收期和动态回收期基本输出之上，按独立输入契约和验收口径扩展额外财务指标（如 LCOE）；
- 增加资本金评价，独立定义自有资金、贷款、利息与还本安排，并明确区分项目投资与资本金指标；
- 全链路结果与版本差异解释。

### `1.3.0` — 智能化数据准备

- 通过本地 AI 问答补齐项目输入；
- AI 只生成候选内容，关键参数由用户确认；
- 不绕过 schema、单位、权限和校验。

### `1.4.0` — Excel 数据标准化

- 通过本地 AI 将受控 Excel 输入转换为候选标准数据集；
- 保留原始文件、转换说明、质量诊断和确认记录；
- 防止公式注入、资源耗尽和不受控代码执行。

### `1.5.0` — 一键生成完整规划报告

- 通过本地 AI 基于冻结的项目快照和计算证据生成完整报告；
- 数值、单位和结论引用结构化结果；
- 报告保留版本、来源和人工确认。

## `2.0.0`

仅在确需不兼容的系统重构或公共契约重设时启动。必须先有 ADR、迁移计划、回滚方案和主版本发布说明；不能把普通新功能集合命名为 `2.0.0`。
