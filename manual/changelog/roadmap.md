# Roadmap

Roadmap 记录尚未交付的功能规划、版本顺序与退出标准。已通过验收并合入主线的功能统一记入[更新日志](README.md)并从本页移除。

## 版本规划约定

- `0.x`：正式发布前的契约收敛、工程验收与发布准备；
- `1.0.0`：小范围测试发布版本；
- `1.x`：测试期间的功能扩展与迭代（2.0 正式发布前自有契约标记固定为 `1.0.0`）；
- `2.0.0`：首个面向公众发布的版本（发布前制定兼容与迁移规则）。

## `1.1.5` 已交付基线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 与前端收敛（0.13–0.14）
  → 财务与预测计算收敛（0.14.5）
  → 全流程工程测试、正式打包与版本发布（1.0.0）
  → 求解器内建结构加速与大规模长周期求解优化（1.1.0）
  → 临时计算容器流水线、统一插件契约与后端资源调度收敛（1.1.5）
```

*(注：`0.2.0`～`1.1.5` 已完成开发与工程验收，变更记录详见[更新日志](README.md)。)*

### `1.1.5` 已交付里程碑（`S1`–`S4`）

- [x] `S1` 独立计算契约与最小 SDK：已交付零后端依赖的 `pies-sdk`（`1.1.5`）及统一 `ies.algorithm-plugin@1.0.0` 契约，通过四类运行时模块化门禁。
- [x] `S2` `job_runner` 与容器生命周期：已交付暴露 5 个固定业务操作的 `job_runner` 容器代理、`--network=none --read-only` 隔离、宿主机 NCPU 钳位及重启后基于数据库的权威核对恢复与非阻塞 detach。
- [x] `S3` 迁移官方计算链：已交付 `pies-builtin-stages:1.1.5` 镜像、`frozen_series_inputs` 直读与 `os.link` 硬链接零拷贝交接，以及 14 字段 `CalculationConfig` 支持。
- [x] `S4` `1.1.5` 整体验收与切换：已完成 `backend` 嵌入式调度收敛、冷启动与全量验收，并正式退役旧常驻 `io_worker`/`compute_worker` 守护进程，常驻服务收敛为 5 容器（`postgres`、`redis`、`job_runner`、`backend`、`web`）。

## `1.1.5` 后的 `1.x` 演进规划

### `1.2.0` — 开放模型与算法插件生态与 pIES Market

- 基于 `1.1.5` 统一插件契约与临时计算容器底座，统一支持全部五类插件（`predictor` / `generator` / `solver` / `evaluator` / `algorithm`，其中 `algorithm` 严格等价替代 `generator + solver` 而不跨越上下游边界）免重启动态安装与选用；插件安装期经 `job_runner` 基于 `pies-plugin-base` 自动构建计算镜像（支持可选 pip 镜像/内网源配置，无额外依赖直接零联网复用基础层），并在有声明 `tests` 时强制在 `--network=none` 容器内通过自检门禁后方可启用；卸载时经新增白名单操作 `delete_plugin_image` 受控清理 `pies-plugin/*` 镜像；零后端依赖的 `pies-sdk` 保持极简，仅补充覆盖全部五类插件的通用 `validate` 与 `pack` 命令；
- 拆分独立公共市场仓库 `ThermalEng/pIES-Market` 与主程序 `ThermalEng/pIES` 解耦，采用“GitHub 仓库静态 JSON 索引（`index.json`）+ 同源免登录纯静态浏览/下载页 + 可自托管极薄无状态投稿网关（FastAPI + SMTP 验证码校验 → 自动创建 GitHub PR → 人工 PR Review → Actions 自动校验发布）”架构，公共市场不作为 pIES 本地计算的运行依赖；
- 升级 `/custom` 为统一单页“模型与算法”，内部设「市场与已安装」（支持按设备模型与五类插件筛选、同 ID 多精确版本/修订并存切换，以及基于实例级共享缓存 + 成员级安装状态的 `远端` / `本地（未安装）` / `本地（已安装）` 三态标识）与「我的创作/草稿」（自定义设备模型常用字段双向同步表单 + 在线 YAML + `.device.yaml` 导入/导出，以及个人本地上传记录）两个平级页签；管理后台 `/admin` 统一管理**本地模式** / **联网模式**切换、市场与投稿网关地址、pip 镜像源、**本地上传审批开关（`local_upload_requires_approval`）**与待审批队列（开启时普通成员本地上传经静态校验进入待审，批准后上架构建）；
- 建立基于命名空间（`ies.*` / `user.<public_namespace>.*` / `<publisher>.*`）的跨实例稳定标识、外部下载/导入边界一次性 SHA-256 校验（内部持久化与快照不存储或重复复核）、无热加载安装与不可变输入/`CalcSnapshot` 提交冻结机制；
- 按切片推进落地：`M1` 公共契约与市场索引定稿 → `M2` 本地模型/插件管理、自动镜像构建/断网自检门禁、五类插件动态执行与极简 `pies-sdk`（`validate`/`pack`）→ `M3` `pIES-Market` GitHub 仓库、静态 JSON 索引与同源纯静态浏览/下载页流水线 → `M4` 可自托管极薄无状态投稿网关（邮箱验证码投稿、自动提 PR 与人工审核衔接）→ `M5` pIES 双页签市场与 `/admin` 审批集成及个人联网/企业本地双场景验收 → `M6` 精选工程参考设备模型（CHP、蓄热/蓄冷水罐、吸收式制冷机、风电）与 3 个参考 Python 插件（`predictor`、带 `iteration` 的 `algorithm`、含 `requirements.txt` 消费 `.mps` Bundle 的外部 `solver`）。

### `1.3.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线与受控基线迁移；
- 敏感性计算、批量参数扫描、不确定性分析与多目标候选比较；
- 在基础财务指标上扩展 LCOE 等指标与独立资本金评价模型。

### `1.4.0` — MCP 接入与智能化数据准备

- 通过 MCP 向外部 AI 客户端开放项目操作能力，由专属登录页签发可撤销连接凭证，支持多端并发连接与草稿冲突提示；
- 提供待计算方案确认页面，AI 辅助生成候选输入后仍须由人工核对确认再创建冻结任务。

### `1.5.0` — Excel 数据标准化

- 借助外部 AI 通过 MCP 将非标准 Excel 数据转换为符合契约的标准数据集，保留转换说明与质量诊断，防止公式注入。

### `1.6.0` — 一键生成完整规划报告

- 基于冻结的项目快照与结构化计算证据生成可追溯的规划报告，保留版本来源与人工确认记录。

### `1.7.0` — 全量输入项说明与格式指引

- 所有填写项（表单输入框、选择器、数值及文本域）均提供统一的说明按钮；
- 支持鼠标长时间悬停（hover）或点击查看；
- 浮层清晰说明该项的业务内涵、计算口径、单位量纲、有效取值范围及填写格式规范；
- 具备完整的键盘可达性与无障碍（aria）支持，不影响原生表单输入与快捷操作。
