# Roadmap

Roadmap 是尚未实现工作的动态清单，规定开发顺序，不承诺具体发布日期。每个目标版本只描述剩余能力和退出标准；实现细节由开发者指南约束，Review 只提供证据。

## 维护规则

- 一项工作达到完成定义并通过验收后，立即写入更新日志 `Unreleased`，同时从本页删除；
- 一项工作只完成部分时，拆分后删除已完成部分，只保留可以继续执行的剩余内容；
- 某个目标版本不再有未完成事项时，删除整个版本段落；正式发布时由更新日志保存版本历史；
- 本页不使用完成勾选、删除线、“已完成”小节或完成日期；Roadmap 不是状态看板和历史档案；
- 同一项内容不得同时以“已实现”身份存在于更新日志和 Roadmap。
- `0.x` 目标版本按本页顺序串行推进；前一版本未达到退出标准时，后续版本只能记录问题，不提前实施；
- 一次开发变更只推进当前版本一个编号事项中的一个可验收切片，只改一个公开 contract、一个模块或一条用户流程，并包含该切片必需的迁移、测试和文档；
- 同一编号事项涉及多个消费者时，一次只迁移一个消费者；切片如果仍不能独立 Review 和回退，必须先继续拆分，不以超大变更包合并。

## 版本规则

- `0.x`：正式发布前的契约收敛和发布准备；
- `1.0.0`：首个正式稳定版；
- `1.x.0`：向后兼容的新功能；
- `1.x.y`：对应功能线的缺陷修复；
- `2.0.0`：保留给不兼容的架构或公开契约重构。

“二期”“Phase 2”等阶段名不再等同于 `2.0.0`。

## `0.x` 实现主线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 和前端收敛（0.13–0.14）
  → 扩展、运维与发布（0.15–0.17）
```

### 安全范围

- 部署模型是管理员集中部署、普通使用者通过界面和 API 使用；管理员属于受信任运维角色，不把管理员主动越权作为攻击模型。
- 必须防护未登录或低权限使用者、外部请求和恶意输入对认证、项目范围、上传/下载、诊断、命令执行和资源使用边界的突破。
- 管理员权限只做基本的误操作防护：清晰的作用范围、危险操作确认、版本/恢复路径；不引入双人审批、管理员相互隔离、零信任架构或重型安全审计体系。

### 财务输出与附加分析范围

- `1.0.0` 基本财务输出为 NPV、IRR、静态回收期和动态回收期，统一采用项目投资口径，并附单位、计算口径、状态和来源。
- 提供逐年现金流明细表及导出，展示投资、年度净现金流、折现及累计过程；页面、导出和指标使用同一冻结结果。
- 评价年限和折现率由用户显式填写、计算前确认，并固定到计算快照；界面提供字段说明和示例。
- 运行计算与财务评价覆盖相同年份、相同年限，逐年现金流使用对应年份的运行结果。
- 敏感性计算及其附加参数、批量参数扫描、不确定性分析、资本金评价和额外财务指标安排在 `1.2.0`。

## `0.6.5` — 组装前置契约与装配输入口径

目标：在进入 `0.7.0` 规范装配前固定项目共同计算口径与装配输入引用边界，发布规划/财务公共输入契约，并退役旧装配前物化路径；计算阶段物化与两阶段求解的实际实现属于后续计算阶段项目。该阶段不生成 Solver Bundle，也不启动求解器。

1. 发布财务三件套与规划配置契约：地区 `FinanceProfile`（已注册、可复用的地区财务基准：币种/基准年/金额口径、按 `finance_type` 的时间口径成本分量、能源购售价格）、项目 `FinanceOverrides`（引用 Profile 稳定 ID，只对既有成本/价格做原子稀疏覆盖）与 `PlanningConfig`（目标函数、规划变量、边界和约束）；Profile 与 Overrides 在用户输入边界校验，合并器的公开输出在进入业务事实前校验，生成不可变 `EffectiveFinanceConfig`，三件套在项目包内固定为 `.yaml`，装配/规划/财务计算只消费已经通过边界校验的 `EffectiveFinanceConfig`。
2. 将三件套与规划配置接入项目/版本的持久化与 API，以稳定 ID、revision 和对象引用固定同一份 `EffectiveFinanceConfig` 供规划与财务计算消费；保存、复制、导入导出和并发冲突必须保持引用关系完整，禁止静默默认或部分发布。
3. 固定装配输入序列口径：原始来源与项目基线使用相同分辨率并保持各自 `step` 连续，但物化前不要求彼此同点数；`data_repeat` 的完整来源序列可为完整日、周或年，整体作为重复基线且不另设周期字段；`data_predict` 的覆盖范围由预测目标和算法契约规定。装配用户输入进入业务事实时只校验、规范化并固定来源引用，后续内部交接不重复校验；不重采样、插值、聚合、融合或补齐；全周期序列在计算阶段统一物化后才要求同点数、`step` 一一对应。已在 master 合入的旧序列预备实现（不同步长固定重采样、装配前展开并替换模型实例引用、`ies.predict.ridge@1.0.0` 固定预测）与上述口径冲突，属已实现待迁移路径，按本条目退役，不保留新旧双轨。
4. 退役与清理收尾：`0.6.5` 只交付契约、输入口径与旧路径退役（条目 3），从装配校验、持久化与项目存储移除装配前物化/替换引用的残余（旧训练与预备产物、`ies.predict.ridge@1.0.0` 专用实现注册），不保留新旧双轨；`constant` / `data_repeat` / `data_predict` 在计算阶段的物化与阶段一/二求解的实际实现不属于本版本交付，见 `0.8.0` 第 6 条与 `0.12.0` 第 2 条。

退出标准：项目基线、`EffectiveFinanceConfig` 与规划配置通过各自公开边界校验后形成不可变 revision 和可审计回执；规划与财务计算使用同一 `EffectiveFinanceConfig`；所有装配输入均满足各自来源模式的覆盖要求、与项目基线同分辨率、文件内 `step` 连续并固定引用；装配前不再存在物化或引用替换路径（旧路径退役，迁移回执与清理证据完整）。计算阶段物化与两阶段求解的实现归属见 `0.8.0` 与 `0.12.0` 条目，仅作归属说明、不构成 `0.6.5` 完成条件；任一边界校验、写入或引用固定失败都不发布部分状态。

## `0.8.0` — 设备纯技术契约、GeneratorProvider 与 Solver Bundle

目标：在 `0.7.0` 规范装配和 `0.6.5` 组装前置契约稳定后，把旧设备目录迁移到纯技术统一契约，再把规范装配到 solver 输入的转换收敛为确定性纯生成边界。

1. 发布 `ies.device-model` `2.0.0` schema、受限方程语法、规范化规则和合法/非法样例；完成模型顶层只保留 `schema/schema_version/device/properties/interfaces/equations`，设备不带独立语义版本、计算精度、价格或成本。
2. 一次性替换内置设备、解析器、目录 descriptor、设备数据 CSV、装配、API/前端 contract 和测试；建立“候选校验成功后才分配 `_N` 编号并原子保存”的项目模型门禁，五类 interface 与装配中的三种 predefined 来源均有确定校验。设备模型 `1.0.0` 是未发布开发草案，直接删除其 schema、迁移器、迁移回执、兼容路径、旧模板和迁移专用测试，不运行期双读，也不提供离线迁移入口。
3. 让系统装配只组合已固定的项目计算基线、已校验并以对象 ID/revision 固定的模型实例与数据、连接、规划配置和不可变 `EffectiveFinanceConfig`（装配使用精确引用，不内联完整财务配置）；生成 Solver Bundle 时再选择独立 `CalculationConfig`，固定 generator、solver、精度、算法选项、种子和输出请求。
4. 建立 GeneratorProvider 公开契约、独立原子注册和能力描述。
5. 发布 `ies.solver-bundle` `1.0.0` 的 schema、规范化规则、结构化命令、输出声明和合法/非法样例。
6. 将当前 solver 的问题构造迁入 generator；其只从 `ValidatedAssemblyArtifact`、已校验的 `CalculationConfig` 和固定资源生成 Bundle，在此完成 solver 内部单位换算，并按项目基线物化 `constant` / `data_repeat` / `data_predict` 全周期连续 `step` 序列（物化结果只进入 Bundle 与回执，不写回装配或项目引用；预测算法由计算配置选择，不固定唯一实现）。

退出标准：所有可选设备均使用纯技术 `2.0.0` 且不依赖旧字段；非法候选不能进入项目正式模型目录、占用正式编号或参与装配；设备参数中的数据关键字只引用项目路径内 CSV，并在用户输入边界校验；项目基线创建后不可修改，装配只固定输入引用，预定义序列按基线在计算阶段生成完整周期连续 `step`；规划与财务计算固定同一 `EffectiveFinanceConfig`，装配中不存在计算选项；相同 artifact、`CalculationConfig`、资源和 provider 版本产生逐字节相同的 Solver Bundle；generator 不访问数据库、网络、对象服务或进程环境，不启动 solver。

## `0.9.0` — SolverRuntime 与受控执行

目标：用通用 runtime 替代当前按 Python 函数名启动子进程的执行边界。

1. 建立 ExecutorProvider、SolverRuntime 和 ExecutionReceipt 公开契约及独立原子注册。
2. runtime 只执行 Bundle 中通过 allowlist 的 executable ID 和参数数组，强制工作目录、路径、环境、网络和资源限制。
3. 覆盖命令注入、路径逃逸、取消、超时、OOM、异常退出、日志和输出边界。

退出标准：runtime 无设备、generator 或 solver 业务分支；被拒绝的 Bundle 不启动进程，每次尝试都产生可解释回执。

## `0.10.0` — ResultAdapter 与统一结果

目标：在 Bundle 与执行回执稳定后，将 solver 输出解释与业务结果分离。

1. 建立 ResultAdapterProvider 独立原子注册，稳定带 schema/version 的 `ComputeResult` 契约。
2. 将当前 solver 的状态、输出、非有限值和反向单位换算迁入 result adapter；达到时间限制时报错。
3. 在不经过 API、数据库或 Worker 的契约测试中，跑通一个当前 solver 的“artifact → Bundle → receipt → result”算例。
4. 按上文“财务输出与附加分析范围”，分切片接入基本财务指标与逐年现金流明细，明确评价输入、计算口径、单位和状态，以可复核算例验证明细与指标一致。

退出标准：result adapter 只凭 Bundle、ExecutionReceipt 和声明输出即可解释结果；不读取当前项目或最新 provider。基本财务评价使用固定输入与结果，指标和逐年现金流通过一致性验收。

## `0.11.0` — Application 用例与 API 边界

目标：让 HTTP 层只做传输适配，事务与跨模块编排只属于用例层。

1. 按项目、数据、配置、任务、结果和导出顺序，逐个将现有 `services` 编排迁入明确 application 用例。
2. 事务只由用例层提交或回滚，repository 只 flush、使用 savepoint 或返回错误。
3. 依次删除 API 中现有的 ORM 与跨模块内部导入；API 只处理传输 DTO、认证/授权和 HTTP 语义。

退出标准：每个对外用例都有一个明确事务所有者；API 契约测试不依赖 ORM 或领域模块私有实现。

## `0.12.0` — 快照、Worker 与证据切换

目标：基于现有任务幂等、租约、fencing 和迟到写入拒绝，将其执行载荷切换到新计算链。

1. 在已经固定规范文本与校验回执二件套的现有 `CalcSnapshot` 上，继续以对象 ID 固定资源，并固定 generator/solver/executor/result adapter 精确版本、单位、种子、选项和容差。
2. Worker 启动时验证快照所需依赖，任务执行只编排 generator/runtime/result adapter；删除当前命令拼接、`assembly.plan` 和函数名子进程旁路；实现多 `data_predict` 的阶段二循环（0 或 1 个时阶段一结果即最终结果；多于 1 个时以首轮结果重建预测目标与计算模型并迭代求解，按公开容差与最大迭代数收敛）。
3. 每个 attempt 封存 Solver Bundle、ExecutionReceipt、必要的 stdout/stderr 日志节选、声明输出记录和统一结果；历史结果只按该快照解释。

退出标准：至少一个当前 solver 通过 Docker 任务端到端算例；未校验输入、缺失依赖和旧计算路径都不能进入执行。

## `0.13.0` — 项目版本与恢复 GUI

目标：只补齐项目版本、恢复、结果应用和项目包导入的用户可见闭环，不重复建设现有后端 API。

1. 提供项目版本创建、列表、详情和恢复 GUI。
2. 让候选方案“应用”调用项目结果应用用例，实际创建新版本；历史结果页明确绑定其任务快照。
3. 提供项目包上传、校验提案、冲突展示和确认恢复 GUI，并按实际控件同步使用者指南。

退出标准：用户可在 GUI 中完成“创建版本 → 应用方案 → 查看历史结果 → 恢复/导入”，且新旧版本和审计记录可见。

## `0.14.0` — 前端严格契约与验收收尾

目标：只清理认证、数据、财务配置、计算、分析、结果和导出界面中的兼容猜测和未验收边界，不重复建设已经贯通的用户流程。

1. 前端按 feature 垂直切分，分离 contract、领域模型、表单和 mapper；删除跨 feature 内部导入、模块级业务缓存和响应形状猜测。
2. 删除财务旧扁平字段回退与静默默认，统一服务器状态、错误、离线、并发保存、刷新和深链接行为。
3. 补齐项目版本/恢复、首发范围内的基本结果评估与帮助中心的 Docker 浏览器验收，修复帮助中心当前未通过的 Markdown 场景；结果页与导出验收覆盖 NPV、IRR、静态回收期和动态回收期的数值、口径和异常状态，两种回收期分别展示，并提供与指标一致的逐年现金流明细表及导出；敏感性等附加分析按 `1.2.0` 验收；画布拖放由人工验收，其他 GUI 使用 Playwright。

退出标准：从登录到导出的关键流程无兼容猜测、假资源或错误空数据降级；桌面/移动、中英文界面和简体中文帮助中心通过验收。

## `0.15.0` — Provider 扩展验收

目标：在公开边界完成后，用仓库外视角验证扩展不需修改核心模块。

1. 用仓库外测试内容/扩展依次验证设备 YAML、数据 CSV、公共方程 contract、GeneratorProvider、ResultAdapterProvider、ExecutorProvider 和存储扩展。
2. 发布可运行扩展示例、四种文件契约测试工具，以及设备稳定 ID、publication revision 与 provider 精确版本固定规则。

退出标准：新增或替换 provider 不修改无关业务模块、GUI 映射或通用 runtime；任一注册失败不发布部分状态。

## `0.16.0` — 运维、备份与故障演练

目标：在功能与扩展边界冻结后，验证实例可判断、证据可观测、数据可恢复。

1. 建立独立聚合的 health/readiness，纳入 API、Worker、数据库、队列、存储和全部必需 provider；缺失依赖的实例不承接流量或任务。
2. 完成日志、追踪和配额验收，使请求、任务、attempt、Bundle、receipt 和结果可以互相定位。
3. 完成数据库/对象备份恢复、容量故障、对象缺失或不可读、中断写入和 provider 故障注入演练。

退出标准：不可正确处理请求或任务的实例不 ready；数据库与对象故障不产生静默成功；备份可恢复到可解释的任务快照。

## `0.17.0` — `1.0.0` 候选

目标：功能冻结，只处理发布阻断和文档偏差。

1. 完成 Docker 全量测试、数据迁移演练和独立系统浏览器验收。
2. 完成第三方攻击面复审、对外入口权限、版本、镜像、许可、更新日志、备份与回滚核对；不以管理员相互隔离或额外审批作为发布门槛。
3. 冻结公开 contract 和 `1.0.0` 使用者指南；对全部当前限制给出已解决证据或明确范围裁决。

退出标准：所有发布门禁通过，且候选期没有新增功能或公开契约变更。

## `1.0.0` — 首个正式版本

发布条件：`0.17.0` 候选无未关闭阻断，正式文档与实际 GUI 一致，历史任务可追溯，升级与恢复可执行。

## 正式发布后的 `1.x`

以下顺序来自旧 Phase 2 路线图的稳定产品意图，具体版本可在开发启动前调整，但必须遵循“新功能升 MINOR”：

### `1.1.0` — 模型与算法、Provider SDK 与设备扩展

- 新增面向所有已登录用户的一级导航“模型与算法”，固定包含“模型库”“算法插件”“共享园地”三个入口；
- 模型库支持网页结构化表单、在线编辑 YAML 和上传 YAML，三条路径统一生成、校验和保存 `ies.device-model` 不可变 publication，并让已安装设备的稳定 ID、revision、状态和公开描述进入系统建模选择器；
- 算法插件支持上传 `ies.algorithm-plugin` ZIP；包内同时交付装配加工程序、算法程序、依赖锁、输入输出声明和测试样例，由独立容器化隔离运行器执行，并让校验通过的已安装精确版本进入计算配置选择器；
- 所有者可申请把设备不可变 publication 或插件精确版本加入共享园地，管理员批准后其他用户可浏览并安装；安装只新增对既有 publication/object ID 的引用；
- 发布统一设备内容、公共方程 contract、生成器、执行器和结果适配器扩展工作流，以及合法/非法包、契约测试和 ID/revision/provider 版本固定工具；
- 完成设备扩展、算法扩展、财务扩展（多国税务数据等）功能；
- 按验证顺序增加氢能设备、热/冷储能、风电、燃气内燃机、余热锅炉、吸收式制冷机和需求响应；
- 外部数据只形成可审计的候选数据版本。

退出标准：用户可管理自己的模型与算法目录，可申请共享并从共享园地引用安装；只有后端确认 `selectable=true` 的设备 publication 或插件精确版本出现在对应选择器；历史项目和任务继续按固定对象 ID、publication revision 与依赖锁解释；API 和普通 Worker 不加载用户代码，插件只在受限隔离运行器中执行。
