# Roadmap

Roadmap 是尚未实现工作的动态清单，规定开发顺序，不承诺具体发布日期。每个目标版本只描述剩余能力和退出标准；实现细节由开发者指南约束，Review 只提供证据。

## 维护规则

- 一项工作达到完成定义并通过验收后，立即写入更新日志 `Unreleased`，同时从本页删除；
- 一项工作只完成部分时，拆分后删除已完成部分，只保留可以继续执行的剩余内容；
- 某个目标版本不再有未完成事项时，删除整个版本段落；正式发布时由更新日志保存版本历史；
- 本页不使用完成勾选、删除线、“已完成”小节或完成日期；Roadmap 不是状态看板和历史档案；
- 同一项内容不得同时以“已实现”身份存在于更新日志和 Roadmap。
- `0.x` 目标版本按本页顺序串行推进；前一版本未达到退出标准时，后续版本只能记录问题，不提前实施；
- 一次开发变更只推进当前版本一个可验收切片，包含其必需的迁移、测试和文档。公共输入改变时，以一条最小执行链为单位交付，不能用仅接受新字段、下游忽略其含义代替完成；
- 切片应能独立 Review 和回退；允许迁移同一切片必需的多个消费者，不扩大为无关重构。输入、求解及结果恢复未接通前，不发布完整能力。

## 版本规则

- `0.x`：正式发布前的契约收敛和发布准备；
- `1.0.0`：小范围测试版本；
- `1.x`：小范围测试期间的功能与缺陷修复，自有契约始终固定 `1.0.0`，只维护当前一套；
- `2.0.0`：首个面向公众发布的版本，发布前完善正式兼容与迁移政策，不在此前开发多版本系统。

“二期”“Phase 2”等阶段名不再等同于 `2.0.0`。

## `0.x` 实现主线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 和前端收敛（0.13–0.14）
  → 财务与预测计算收敛（0.14.5）
  → 扩展、运维与发布（0.15–0.17）
```

### 安全范围

- 部署模型是管理员集中部署、普通使用者通过界面和 API 使用；管理员属于受信任运维角色，不把管理员主动越权作为攻击模型。
- 必须防护未登录或低权限使用者、外部请求和恶意输入对认证、项目范围、上传/下载、诊断、命令执行和资源使用边界的突破。
- 管理员权限只做基本的误操作防护：清晰的作用范围、危险操作确认、版本/恢复路径；不引入双人审批、管理员相互隔离、零信任架构或重型安全审计体系。

### 财务输出与附加分析范围

- `1.0.0` 基本财务输出为 NPV、IRR、静态回收期和动态回收期，统一采用项目投资口径，并附单位、计算口径、状态和来源。
- 提供逐年现金流明细表及导出，展示投资、年度净现金流、折现及累计过程；页面、导出和指标使用同一冻结结果。
- 运行起始年归项目计算基线、创建时固定；财务评价总年限（包含建设期）、运营年限、整数年建设期、付款比例计划、维护／换新支出与折现率由用户显式确认并固定到计算快照（确认字段、提交关联与冻结块见财务计算“评价确认与快照冻结”，无默认；自由字典式 `baseline-confirm` 不作参数来源）。不沿用 `0.08`，不塞进 `FinanceProfile` 或封闭 `CalculationConfig`。
- 计算在完整运行时间轴上整体求解；本课题首年启动建设，建设期与支付安排明确，优化建设选择、容量与全周期运行，不优化建设年份，中期扩建另建计算课题。评价现金流包含建设支出及完整运行期，与运行时轴的对应关系明确，不默认立即投产。逐年现金流由同一全周期真实结果按年归集，不以未经等价证明的单年复制、逐年独立求解或预先固定选建方案与容量代替整体模型；内部等价优化遵守生成器契约。年度输入差异由覆盖全期的连续序列直接表达，不设逐年绑定。
- 敏感性计算及其附加参数、批量参数扫描、不确定性分析、资本金评价和额外财务指标安排在 `1.2.0`。


## `0.15.0` — Provider 扩展验收

目标：在公开边界完成后，用仓库外视角验证扩展不需修改核心模块。

1. 用仓库外测试内容/扩展依次验证设备 YAML、数据 CSV、公共方程 contract、GeneratorProvider、ResultAdapterProvider、ExecutorProvider 和存储扩展。
2. 发布可运行扩展示例、四种文件契约测试工具，以及设备稳定 ID、publication revision 与 provider 精确版本固定规则。
3. 按下节完成通用建模与计算升级，再恢复独立工程方案全周期实测、结果核对与导出；不以不断补充单个案例字段替代公共能力收敛。

退出标准：新增或替换 provider 不修改无关业务模块、GUI 映射或通用 runtime；任一注册失败不发布部分状态。工程方案使用正式模型和通用约束完成真实求解、同源财务评价与导出，不以已提交任务或运行中代替完成。

| 阶段 | 剩余交付 | 验收依据 |
| --- | --- | --- |
| P3-N：端口级网络 | 端口边界、理想连接与受限传输、同载体设备两侧隔离及必要分配 | 不发生非法母线合并；直接来源限制与替代负荷的间接影响可区分；同载体与跨载体模型均验证 |
| P3-F：通用财务与评价 | 命名费用、统一金额引用、支付/资本化/折旧分离、税额派生、显式基准与计税口径 | 同驱动多明细可独立计税；基准冻结且不随候选优化；现金、税额、资产与有无项目差额逐期手算对账 |
| P4：多年模型规模优化 | 测量贯穿前述阶段；语义稳定后实现有证明条件的运行块压缩及结果恢复 | 与小规模完整模型目标及原约束一致，多最优解允许曲线不同；不满足条件保留独立决策，不私加终期状态；约定规模满足实测资源预算 |
| P5：用户链与独立验收 | 通用文档编辑、冻结、状态、结果、导出与迁移对齐；恢复私有工程盲测 | 实际完成求解、评价与导出，独立核对物理与财务事实；提交成功、运行中、CI 绿色不单独作为工程验收完成 |

P1 的关系汇集、结构复用和来源链，以及 P2 的统一界分析、建设及金额关系、精确转换、资源与策略评估和公共结果出口，已完成阶段退出，证据见[更新日志](README.md)与对应 PR 审查。不重新派修已交付切片，也不将 P1/P2 收口等同于完整工程验收。建设激活遵循[装配字段](../developer-guide/zh-CN/formats/assembly-yaml.md#建设激活目标语义)、[金额来源与残值](../developer-guide/zh-CN/formats/finance-yaml.md#金额来源与折旧期间)及[单一当前契约](../developer-guide/zh-CN/file-formats.md#建设激活配套版本与迁移)。剩余工作按上表推进。

### P3范围与切片闸门

网络输入唯一正文为[网络边界与系统方程](../developer-guide/zh-CN/formats/network-relations.md)，财务输入为[金额关系](../developer-guide/zh-CN/formats/finance-relations.md)，比较输入为[评价范围](../developer-guide/zh-CN/contracts.md#评价范围与冻结基准)，同次恢复为[Bundle结果声明](../developer-guide/zh-CN/formats/solver-bundle.md)。这些是目标契约；只有对应执行链通过审查与CI后才能记录已交付，不能以本轮文档完成代替功能验收。

| 切片 | 本片范围与依赖 | 退出证据 |
| --- | --- | --- |
| N1 已完成 | PR #46：真实端口理想母线，公共分区及受限传输原方程；不重开 | 同载体传输两侧不短接，容量/效率实际约束结果，端口分区一致 |
| N2 网络边界 | 未连接可连接端口关闭；显式源汇；同一分区/关闭关系贯通检查、构模及来源 | 悬空进/出/双向端口不能凭空取能或排放；predefined/blind不置零；仅源/仅汇可为零；2+3供给5的不同端口域不强求相交；不按类别/峰值估计误判不可行；旧项目不自动补边 |
| N3 系统关系与分配 | 依赖N2；system_equations的局部变量、真实引用、初值及同次系统序列 | 双源双汇总量守恒；直接外送与替代效应区分；双向分解不虚构循环；两步/跨年储存来源账户与实际总状态一致；量纲/索引失败指向原字段 |
| F1 命名项与金额引用 | 基础财务链不重开；items、amounts、范围及参数覆盖；已支持来源的一条完整求值/恢复链 | 同driver多项独立计税；两实例不串用；按年/按月/标量单位正确；闲置定义不产生现金；未接通来源明确拒收 |
| F2 发生、支付、资产与派生税 | 依赖F1；cash_movements、assets、derived_tax及相关VAT/CIT引用 | 分期付款与基础/折旧分离；固定/比例残值及零资产继续正确；换新时点、重复扣除、实缴与应计税基逐期对账；现金只发生一次 |
| F3 冻结基准与评价 | 依赖F1/F2；absolute/reference/difference，已封存任务或用户声明来源；金额/结果/目标同源 | 基准与候选独立，修改草稿不改旧结果；分别计税后差额与差额计税反例；原候选/基准/差额可区分；缺数据不补零 |

N2/N3与F1/F2可在明确公共文件负责人后并行，F3不早于其引用和税务事实。所有片均复用同一关系汇集、模板、统一界查询、单位转换和来源链。每片完成输入→保存/包往返→冻结→实际构模→同次恢复的可用子集；不支持的输入在真实公开边界拒收，不在Worker层增加复核。

每片的必测公共性质还包括：重排不改变含义；0、空/未知侧与单侧界不被误作大数；状态不重置且时变系数不丢失；物理量恢复业务单位、金额保持本币；取消、不可行、转换条件不足与资源超时不混报。新UI入口按变化范围做Docker浏览器验收；这些测试不借用私有案例，也不把提交成功当成求解成功。

P3明确不做：来源白名单、每设备/费用专用表单、自动分配政策或按比例追踪、自动基准求解、独立简化增量税盾算法、企业税务申报/融资/中期扩建、汇率系统、任意脚本或通用非线性求解器、辅助LP预检、惰性求解协议、P4时域压缩及P5盲测。来源账本由用户方程定义，不承诺自动证明策略完整；需完全混合比例等非线性语义时不能伪装成MILP。若要扩展这些排除项，先审查所属正式契约及范围，不借“顺手修复”进入实现。

契约收口先独立文档PR审查，不改生产代码或宣称新增能力。上述未完成切片在契约获准后逐片执行、独立提交和CI验收；修改字段归所属格式正文，实施交接不得自创同义写法。阶段退出必须覆盖N/F联动的物理与财务手算，不以各片CI绿色代替完整P3验收。

执行与集成纪律：

- P3-N、P3-F 在明确接口与冲突文件后可分工并行；同一公共表达式、界分析和生成入口由同一主线维护。算法对照先保持隔离，不直接替换正式执行链。
- 每个改变输入的切片先在所属格式页完整定义字段、精确版本、覆盖语义、迁移与结果含义，再实现一条最小执行链。P0 的语义示例不是可提交 YAML；不让开发者各自解释新的引用写法或复用旧字头。
- 2.0 正式发布前只维护当前一套自有 `1.0.0` 契约，字段、实现、样例和测试一起更新；不让用户协调配套版本。模型发布形成新 revision，旧任务固定旧依赖；修订不得覆盖历史结果或自动清空用户项目。
- 阶段内使用小规模通用性质与手算反例，性能使用逐级合成负载。界面链交付时做 Docker 浏览器验收；完整工程盲测留至集成后，私有数据不进入开发输入或公共示例。
- 惰性互斥、静态松弛及运行块压缩分别需要证明与实测，不作为必选算法。若候选算法需要改变通用 Runtime 的职责或生成器输入边界，先提交对应 ADR，批准前保持现有宪法边界。
- 文档维护只做相关结构、链接和语义检查，不因纯文档修改重跑完整求解或 Playwright。

### `1.1.0` — 模型与算法、Provider SDK 与设备扩展

- 新增面向所有已登录用户的一级导航“模型与算法”，固定包含“模型库”“算法插件”“共享园地”三个入口；
- 模型库支持网页结构化表单、在线编辑 YAML 和上传 YAML，三条路径统一生成、校验和保存 `ies.device-model` 不可变 publication，并让已安装设备的稳定 ID、revision、状态和公开描述进入系统建模选择器；
- 算法插件支持上传 `ies.algorithm-plugin` ZIP；包内同时交付装配加工程序、算法程序、依赖锁、输入输出声明和测试样例，由独立容器化隔离运行器执行，并让校验通过的已安装精确版本进入计算配置选择器；
- 所有者可申请把设备不可变 publication 或插件精确版本加入共享园地，管理员批准后其他用户可浏览并安装；安装只新增对既有 publication/object ID 的引用；
- 发布统一设备内容、公共方程 contract、生成器、执行器和结果适配器扩展工作流，以及合法/非法包、契约测试和 ID/revision/provider 版本固定工具；
- 完成设备扩展、算法扩展、财务扩展（多国税务数据等）功能；
- 按验证顺序增加氢能设备、热/冷储能、风电、燃气内燃机、余热锅炉、吸收式制冷机和需求响应；
- 外部数据只形成可审计的候选数据版本。

退出标准：用户可管理自己的模型与算法目录，可申请共享并从共享园地引用安装；只有后端确认 `selectable=true` 的设备 publication 或插件精确版本出现在对应选择器；历史项目和任务继续按固定对象 ID、publication revision 与依赖锁解释；API 和普通 Worker 不加载用户代码，插件只在受限隔离运行器中执行。

### `1.2.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线，以及通过新修订和明确迁移受控变更项目计算基线；
- 场景、稳定性和多目标候选比较；
- 敏感性计算及附加参数配置、批量参数扫描与不确定性分析；

### `1.3.0` — MCP 接入与智能化数据准备

- 通过 MCP 向外部 AI 客户端开放项目操作能力，由外部客户端组织交互，不自建 Agent；复用后端业务能力与模型文档，不另建 AI 专用业务规则；
- 本地与远程部署统一由管理员管理账号和系统、工程师持有项目并计算，管理员不直接开展项目计算，MCP 使用工程师身份；
- MCP 连接提供专用网页登录窗口：已初始化实例使用工程师账号登录；首次初始化提供管理员设置／改密与工程师创建流程，最终只为工程师签发连接凭证；
- 登录后将鉴权文件下载至连接端本地供后续连接使用，文件保存可撤销的连接凭证而非账号密码；凭证由连接端使用，不进入 AI 对话，失效后重新认证；
- 允许浏览器多窗口与 MCP 同时连接，不因新连接挤掉原会话；以后端已保存数据为准，通过定时刷新和手动刷新同步项目参数、任务状态与结果；未保存编辑不被自动覆盖，保存版本冲突明确提示；
- 新建面向当前项目待计算方案的确认网页，现有项目页面继续用于查看和编辑完整参数；两者使用同一后端事实，不维护第二份参数；具体页面交互在实施时设计；
- AI 生成候选输入，用户确认关键参数，发起计算时才创建任务并冻结输入；刷新不改变历史任务输入与结果；
- 不绕过 schema、单位、权限和校验。
