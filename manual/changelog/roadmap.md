# Roadmap

Roadmap 记录尚未交付的功能规划、版本顺序与退出标准。已通过验收并合入主线的功能统一记入[更新日志](README.md)并从本页移除。

## 版本规划约定

- `0.x`：正式发布前的契约收敛、工程验收与发布准备；
- `1.0.0`：小范围测试发布版本；
- `1.x`：测试期间的功能扩展与迭代（2.0 正式发布前自有契约标记固定为 `1.0.0`）；
- `2.0.0`：首个面向公众发布的版本（发布前制定兼容与迁移规则）。

## `1.1.5` 已交付基线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 与前端收敛（0.13–0.14）
  → 财务与预测计算收敛（0.14.5）
  → 全流程工程测试、正式打包与版本发布（1.0.0）
  → 求解器内建结构加速与大规模长周期求解优化（1.1.0）
  → 临时计算容器流水线、统一插件契约与后端资源调度收敛（1.1.5）
```

*(注：`0.2.0`～`1.1.5` 已完成开发与工程验收，变更记录详见[更新日志](README.md)。)*

### `1.1.5` 已交付里程碑（`S1`–`S4`）

- [x] `S1` 独立计算契约与最小 SDK：已交付零后端依赖的 `pies-sdk`（`1.1.5`）及统一 `ies.algorithm-plugin@1.0.0` 契约，通过四类运行时模块化门禁。
- [x] `S2` `job_runner` 与容器生命周期：已交付暴露 5 个固定业务操作的 `job_runner` 容器代理、`--network=none --read-only` 隔离、宿主机 NCPU 钳位及重启后基于数据库的权威核对恢复与非阻塞 detach。
- [x] `S3` 迁移官方计算链：已交付 `pies-builtin-stages:1.1.5` 镜像、`frozen_series_inputs` 直读与 `os.link` 硬链接零拷贝交接，以及 14 字段 `CalculationConfig` 支持。
- [x] `S4` `1.1.5` 整体验收与切换：已完成 `backend` 嵌入式调度收敛、冷启动与全量验收，并正式退役旧常驻 `io_worker`/`compute_worker` 守护进程，常驻服务收敛为 5 容器（`postgres`、`redis`、`job_runner`、`backend`、`web`）。

## `1.1.5` 后的 `1.x` 演进规划

### `1.2.0` — 开放模型与算法插件生态与 pIES Market

- **框架零拷贝单向流水线、底座还原与并联自描述评价**：基于 `1.1.5` 临时容器底座，收敛 13 字段 `CalculationConfig`（移除 `convergence` 并升级为并联 `evaluators[]`）：上游 `predictions[]` 按插件同层分组单趟执行（支持多目标同源联合预测）；分步模式 `solver` 输出标准原变量解后由**平台底座自动结合 `variable_map` 还原出业务单位标准工程解**（与一体化 `algorithm` 完全同构，两种模式均支持 `evaluators: []`）；跨环节只读上下文统一由**调度框架经硬链接零拷贝组装进 `/work/in`**（插件不承担文件搬运职责）；下游支持 `0..N` 个评价器并联执行（官方财务评价器复用同源财务规则对标准工程解做全量正向评价，第三方评价器按自描述 `metrics`/`charts`/`tables` 协议由前端通用渲染解耦）；安装期经 `job_runner` 零业务凭证受控构建（无依赖强制 `--network=none`，配置 `pip_index_url` 时作为优先源并允许回退默认 PyPI，离线失败明确弹窗指引联系管理员），声明 `tests` 时强制通过 `--network=none` 自检才转 `ready`；停用/卸载与新任务提交共用事务行锁，零未终结任务引用时经 `delete_plugin_image` 清理 `pies-plugin/*` 镜像；`pies-sdk` 仅补充通用 `validate` 与 `pack`；
- **独立静态公共市场与无状态隐私投稿**：拆分 `ThermalEng/pIES-Market` 与主程序解耦，发布统一公开契约 `ies.market-index@1.0.0`（`index.json`，设备模型用 `revision`、算法插件用 `version`，由同源免登录纯静态浏览/下载页与 pIES 客户端共同消费，远端下架不影响本地已装实例）；配套可自托管极薄无状态投稿网关（SMTP 验证码 + HMAC 挑战凭证 → 短期无状态投稿凭证 → 归档/契约及市场统一 `MARKET_HMAC_SECRET` 计算的 `publishers.yaml` 邮箱摘要归属核对 → 幂等自动提 PR，零明文邮箱入库；PR 触发只读断网隔离自检，人工审核合并裁决首次并发抢注并自动构建发布）；
- **统一双页签市场页面与正交管理开关**：升级 `/custom` 为统一单页“模型与算法”，内设「市场与已安装」（三态标识 `远端` / `本地（未安装）` / `本地（已安装）`、种类筛选与同 ID 多精确版本切换）和「我的创作/草稿」（常用字段双向同步表单 + 在线 YAML + `.device.yaml` 导入/导出，以及带后台构建状态的本地提交记录）；`/admin` 维护**正交双开关**——`market_mode`（本地/联网模式）与 `local_upload_requires_approval`（在两种模式下统一拦截非管理员自行上传/离线导入，防绕过）；
- **稳定命名空间与外部三分校验边界**：本地草稿用 `user.<public_namespace>.*`，投稿市场统一收敛为可读 `<publisher>.*`；跨实例原样保留 ID 与发布 `revision`/`version`（同版本不同内容 `409` 拒绝）；外部入口按“市场下载强验 `sha256` / 带摘要离线包核验所给 `sha256` / 普通裸离线包仅验归档与契约”三分处理，入库后内部永不存储或重算 `sha256`；
- **按切片推进落地**：`M1` 13 字段计算配置、框架零拷贝交接、标准工程解/自描述评价块、`ies.market-index@1.0.0` 与无状态投稿公共契约定稿 → `M2` **先完成单向计算协议切换、底座还原、同源正向财务评价及最小第三方 `solver`/`algorithm`/`evaluator` 替换与并联真实任务测试，再完成**本地模型/插件管理、受控构建自检、事务安全卸载与极简 `pies-sdk`（`validate`/`pack`） → `M3` `pIES-Market` 仓库、只读隔离自检 CI、`index.json` 与同源纯静态浏览/下载页流水线 → `M4` 可自托管极薄无状态投稿网关（HMAC 挑战/投稿凭证、`publishers.yaml` 邮箱摘要绑定与幂等自动提 PR）→ `M5` pIES 双页签市场、前端自描述评价块通用渲染、`/admin` 正交审批集成及个人联网/企业本地双场景浏览器验收 → `M6` 精选工程参考设备模型（CHP、蓄热/蓄冷水罐、吸收式制冷机、风电）与可替换参考 Python 插件（多目标联合 `predictor`、带 `iteration` 的 `algorithm`、含 `requirements.txt` 消费 `.mps` 的外部 `solver` 及自描述碳排放/可靠性参考 `evaluator`）。

### `1.3.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线与受控基线迁移；
- 敏感性计算、批量参数扫描、不确定性分析与多目标候选比较；
- 在基础财务指标上扩展 LCOE 等指标与独立资本金评价模型。

### `1.4.0` — MCP 接入与智能化数据准备

- 通过 MCP 向外部 AI 客户端开放项目操作能力，由专属登录页签发可撤销连接凭证，支持多端并发连接与草稿冲突提示；
- 提供待计算方案确认页面，AI 辅助生成候选输入后仍须由人工核对确认再创建冻结任务。

### `1.5.0` — Excel 数据标准化

- 借助外部 AI 通过 MCP 将非标准 Excel 数据转换为符合契约的标准数据集，保留转换说明与质量诊断，防止公式注入。

### `1.6.0` — 一键生成完整规划报告

- 基于冻结的项目快照与结构化计算证据生成可追溯的规划报告，保留版本来源与人工确认记录。

### `1.7.0` — 全量输入项说明与格式指引

- 所有填写项（表单输入框、选择器、数值及文本域）均提供统一的说明按钮；
- 支持鼠标长时间悬停（hover）或点击查看；
- 浮层清晰说明该项的业务内涵、计算口径、单位量纲、有效取值范围及填写格式规范；
- 具备完整的键盘可达性与无障碍（aria）支持，不影响原生表单输入与快捷操作。

## `2.0.0`

首个面向公众发布的版本。发布前完成公开边界冻结、兼容与数据迁移政策、回滚方案及公开验收。
