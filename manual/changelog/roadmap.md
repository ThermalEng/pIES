# Roadmap

Roadmap 记录尚未交付的功能规划、版本顺序与退出标准。已通过验收并合入主线的功能统一记入[更新日志](README.md)并从本页移除。

## 版本规划约定

- `0.x`：正式发布前的契约收敛、工程验收与发布准备；
- `1.0.0`：小范围测试发布版本；
- `1.x`：测试期间的功能扩展与迭代（2.0 正式发布前自有契约标记固定为 `1.0.0`）；
- `2.0.0`：首个面向公众发布的版本（发布前制定兼容与迁移规则）。

## `0.x` 开发主线

```text
第三方攻击面与公共边界（0.2–0.4）
  → 输入与装配契约（0.5–0.7）
  → 生成—执行—结果（0.8–0.10）
  → 应用编排与追溯切换（0.11–0.12）
  → GUI 与前端收敛（0.13–0.14）
  → 财务与预测计算收敛（0.14.5）
  → 扩展、运维与发布（0.15–0.17）
```

*(注：`0.2`～`0.14.5` 及通用建模/财务/紧凑构模与分块交接整改主线已交付并记入更新日志。)*

## `0.15.0` — Provider 扩展与工程全流程验收

目标：在现有公开边界上验证仓库外扩展无需修改核心模块，并由独立工程用户完成端到端建模、全周期求解、财务评价与导出交付。

### Provider 扩展验收

1. 使用独立于核心仓库的外部扩展依次验证设备 YAML、数据 CSV、公共方程、GeneratorProvider、ResultAdapterProvider、ExecutorProvider 与存储适配器。
2. 发布可运行的扩展示例、文件契约测试工具与 Provider 版本固定规范。

### 工程用户全流程验收

| 验收维度 | 完成依据 |
|---|---|
| 部署与账号 | 记录代码基线及实际部署各组件状态；工程师可正常登录建项 |
| 案例与数据准备 | 核对连续 `step`、分辨率、点数、单位、技术与财务口径；确认无缺失输入 |
| 真实用户建模链 | 在 Docker Playwright 中完成建项目、数据上传绑定、画布连线、通用 YAML/约束编辑、保存与重开 |
| 独立方案与冻结 | 分别保存并计算各方案，核对设备、计费、税务与基准归属；草稿修改不改写历史任务 |
| 全周期计算与状态 | 真实完成构模、排队、Worker 执行与全周期求解，记录耗时、模型规模与资源观测 |
| 物理与运行结果 | 独立核对能量平衡、容量/功率界、效率、状态初值与连续性、端口流向及来源约束 |
| 财务与方案比较 | 独立核对建设支付、运维维护、需量费、VAT、所得税、折旧、现金流及 NPV/IRR/回收期与基准差额 |
| 结果、导出与交付 | 核对结果页、时序、Excel 报表与项目包导入导出一致性，归档独立核算与验收证据 |

退出标准：新增或替换 Provider 不修改无关业务模块、GUI 或运行时核心；独立工程案例使用正式模型完成真实求解、同源财务评价、结果核对与交付导出，阻断问题全部关闭。

### 实测性能与等价优化原则

- 仅针对工程全周期验收中实测复现的构模、内存或求解瓶颈实施针对性优化，不提前建设未验证的压缩系统。
- 任何优化必须保持正式模型约束与目标等价，不得擅自删减互斥关系、缩减时域或引入未证明的近似假设。

## `0.16.0` — 运维、备份与故障演练

目标：完善运行可观测性与数据安全恢复能力。

1. 完善聚合 `healthz`/`readyz` 探针，将 API、Worker、数据库、队列、存储及必需计算 Provider 纳入就绪判定。
2. 完成全链路追踪日志（request / task / attempt / bundle / receipt / result 互查）验收。
3. 完成数据库与对象存储联合备份恢复演练及常见故障注入验证（对象缺失、写入中断、Provider 失效）。

## `0.17.0` — `1.0.0` 发布候选

目标：功能冻结，完成发布前质量门禁与文档收敛。

1. 完成 Docker 全量回归、数据库迁移演练与端到端浏览器验收。
2. 复审对外入口权限、镜像配置、开源许可与回滚预案。
3. 冻结公开契约与 `1.0.0` 使用者指南，清理全部已知阻断项。

## `1.0.0` — 小范围测试版本

交付条件：`0.17.0` 候选门禁全部通过，正式文档与实际界面一致，历史任务可追溯且升级恢复演练可执行。

## 小范围测试后的 `1.x` 演进规划

### `1.1.0` — 模型与算法、Provider SDK 与设备扩展

- 新增面向登录工程师的一级导航“模型与算法”，包含“模型库”“算法插件”与“共享园地”；
- 模型库支持表单、在线 YAML 与上传 YAML 统一生成不可变 `ies.device-model` 发布；
- 算法插件支持上传 `ies.algorithm-plugin` ZIP，在独立容器化隔离运行器中执行，确保 API/普通 Worker 不加载用户源码；
- 支持所有者申请共享、管理员审核及用户目录引用安装；
- 发布扩展 SDK 与验证工具，并逐步补充氢能、热/冷储能、风电、燃气内燃机、余热锅炉、吸收式制冷机及需求响应等设备与扩展财务规则。

### `1.2.0` — 规划—运行闭环与场景分析

- 典型工况容量规划与全年运行校核；
- 多场景项目计算基线与受控基线迁移；
- 敏感性计算、批量参数扫描、不确定性分析与多目标候选比较；
- 在基础财务指标上扩展 LCOE 等指标与独立资本金评价模型。

### `1.3.0` — MCP 接入与智能化数据准备

- 通过 MCP 向外部 AI 客户端开放项目操作能力，由专属登录页签发可撤销连接凭证，支持多端并发连接与草稿冲突提示；
- 提供待计算方案确认页面，AI 辅助生成候选输入后仍须由人工核对确认再创建冻结任务。

### `1.4.0` — Excel 数据标准化

- 借助外部 AI 通过 MCP 将非标准 Excel 数据转换为符合契约的标准数据集，保留转换说明与质量诊断，防止公式注入。

### `1.5.0` — 一键生成完整规划报告

- 基于冻结的项目快照与结构化计算证据生成可追溯的规划报告，保留版本来源与人工确认记录。

### `1.6.0` — 全量输入项说明与格式指引

- 所有填写项（表单输入框、选择器、数值及文本域）均提供统一的说明按钮；
- 支持鼠标长时间悬停（hover）或点击查看；
- 浮层清晰说明该项的业务内涵、计算口径、单位量纲、有效取值范围及填写格式规范；
- 具备完整的键盘可达性与无障碍（aria）支持，不影响原生表单输入与快捷操作。

## `2.0.0`

首个面向公众发布的版本。发布前完成公开边界冻结、兼容与数据迁移政策、回滚方案及公开验收。
