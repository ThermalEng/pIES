# Device Data CSV

> Contract ID: `ies.device-data`; Target `schema_version`: `"1.0.0"`; Recommended Filename: `<dataset-id>.data.csv`

Device Data CSV supplies time-series inputs with explicit sampling interval, units, and contiguous `step` indices to device `predefined` interfaces. Users MUST ensure data completeness, absence of gaps, and resolution consistency with the project before uploading; the platform strictly validates at import and assembly boundaries without implicit interpolation, resampling, or padding.

## File Structure Example

```csv
# schema: ies.device-data
# schema_version: 1.0.0
# dataset_id: campus_electric_load_2025
# device_id: acme.device.electric_load
# source_mode: data_predict
# resolution: 1h
# unit.electric_demand: kW
step,electric_demand
0,48.3
1,46.7
2,45.9
```

*(Note: This excerpt shows only the first 3 rows; production files MUST satisfy the full row count required by their `source_mode`.)*

## File Layout and Metadata

From top to bottom, the file contains `# `-prefixed metadata lines (each key at most once), one CSV header row, and data rows (no comments may appear inside the data section; general notes use `# note.<name>:` in the metadata header):

| Metadata Key | Description |
|---|---|
| `schema` | Fixed to `ies.device-data` |
| `schema_version` | Fixed to `"1.0.0"` |
| `dataset_id` | Stable dataset identifier |
| `device_id` | Stable base device type ID (without the project model's `_N` suffix) |
| `source_mode` | Source mode: `data_repeat`, `data_full`, or `data_predict` (`constant` enters scalar values directly in assembly with no CSV) |
| `resolution` | Sampling interval (e.g., `15min`, `30min`, `1h`); MUST match the project baseline |
| `unit.<column>` | Explicit unit for each data column; MUST be dimensionally compatible with the target device interface |

## CSV Dialect and Header Requirements

- **Encoding and formatting**: UTF-8 (no BOM), LF line endings, comma-delimited (RFC 4180 quoting), period decimal separator; booleans as `true`/`false`.
- **No missing or non-finite values**: Empty cells, `NaN`, `Inf`/`Infinity`, localized thousands separators, and spreadsheet formulas are prohibited.
- **Header and step contiguity**: The first column MUST be `step`, incrementing strictly by `+1` starting from `0`; subsequent column names MUST match `predefined` interface IDs on the target device model, rejecting unknown or duplicate columns.

## Source Mode Coverage and Materialization Alignment

Each source mode satisfies distinct coverage rules across assembly and materialization:

| Mode | File Input Coverage Requirement | Materialization Behavior in Computation |
|---|---|---|
| `constant` | No CSV file; scalar value supplied directly in assembly binding | Expands into a constant contiguous series over the full horizon |
| `data_repeat` | Complete contiguous day, week, or year sequence (no separate period field; the whole file is the repeat baseline) | Tiles cyclically from `step=0` to total operating-period steps |
| `data_full` | MUST cover every operating-period step derived from `start_year` and `operation_years` starting at `step=0` (checked at task submission) | Consumed verbatim without tiling, truncation, or extrapolation |
| `data_predict` | Satisfies historical training/input requirements of the chosen prediction target type (`target_type` declared in assembly binding) | Trained and generated by the selected prediction algorithm during computation to yield a full-horizon series and receipt |

Prior to materialization, sources for different devices do not need equal row counts; upon materialization during computation, all series align onto the project baseline resolution and full operating-horizon contiguous `step` axis.

## Upload Endpoint Recognition (`POST …/datasets/{id}/versions`)

The dataset upload endpoint automatically detects step CSVs when the first line declares `# schema: ies.device-data` (files without `# schema:` follow the generic timestamp CSV pipeline; unknown `# schema` is rejected with `DATA-META-003`):

- Checks `# resolution` matches the upload request, `step` is contiguous from `0`, cells are non-empty and finite, and every column declares `unit.<col>` (violations return `400` `DATA-VAL-001`).
- Generic form `fields` metadata does not apply to self-describing step CSVs and records a non-blocking warning `DATA-FILE-005` if passed.
- Specific device, interface, and `source_mode` matching is verified when binding instances in project assembly.

## Common Rejection Causes and Remedies

| Issue | Remedy |
|---|---|
| `step` gaps, duplicates, or non-increasing order | Blocked with offending line number; fix source file and upload a new version |
| `data_repeat` is not an exact full day, week, or year length | Blocked; complete the periodic baseline and re-upload |
| Resolution mismatches project baseline, or values fall outside device `valid_range` | Blocked; preprocess externally and upload a new version |
| Column unit dimensionally incompatible with interface (e.g., `kWh` provided for `kW`) | Blocked; align units with device interface |
| Extra comment columns inside data rows | Move notes into `# note.*:` metadata lines |
