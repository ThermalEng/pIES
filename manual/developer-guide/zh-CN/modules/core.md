# Core 基础能力

> 代码边界：`backend/iesplan/core/`；上位规范：[架构宪法](../ARCHITECTURE_CONSTITUTION.md)

`core` 为所有后端业务模块提供无业务状态的公共基础语言，使各模块在不相互依赖的情况下交换语义一致的基础值对象与错误结构。判断一项能力是否属于 `core` 的标准是：**在不知道项目、设备、任务或用户概念的前提下是否仍然成立**。

## 能力范围

| 领域 | 公开能力 | 关键不变量 |
|---|---|---|
| 基础值对象与错误 | `AppError` 子类体系、稳定 ID 类型 | 不可变；对外 ID 不参与算术 |
| 结构化诊断 | `Diagnostic` 与集中登记的诊断码 | 只承载 `code`、`message_key`、`params` 与位置，不写死用户文案；未登记码立即报错 |
| 单位与量纲 | 单位规范化、量纲检查与线性换算 | 不支持隐式猜测；不相容量纲直接拒绝 |
| 序列时间轴 | 连续 `step` 轴、分辨率与公历推导 | 拒绝 `NaN`/`Infinity`、不连续 `step` 与时区隐式偏移 |
| 安全 YAML 与规范序列化 | YAML 1.2 安全子集解析与确定性 JSON 编码 | 禁止任意对象构造；相同语义产生相同规范字节 |
| 基础安全原语 | 密码哈希、密码学安全随机令牌 | 不保存或输出明文秘密 |

## 约束与验证

- **纯依赖约束**：`core` 只能依赖 Python 标准库及明确批准的基础库，严禁导入任何业务模块或读取环境变量、数据库及对象存储。
- **错误表达**：面向批量输入的结构化校验应聚合 `Diagnostic` 集合；违反编程契约或无法继续的调用直接抛出明确的 `AppError`。
- **测试要求**：所有公开纯函数均须覆盖正常边界、非法输入（非有限数、非法单位、断续步长）与输出确定性。
