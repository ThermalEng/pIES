# 建模命令

> 文档状态：生效蓝图；代码边界：`backend/iesplan/modeling/`

## 作用

`modeling` 把“设备具有什么能力”翻译为“计算生成器如何取得该设备的数学贡献”。它通过版本化 `ModelCommand` 隔离设备描述和具体实现，使 assembly 与 generators 不需要知道设备目录文件或实现函数位置。

命令是可执行模型的公开协议，不是任意 Python callable 的包装。

## 边界

模块负责：

- 命令 ID、版本、输入、输出、单位、状态和确定性声明；
- 机理、周期复用和预测等建模方法的标准接口；
- 命令 provider、独立注册状态和原子发布；
- 从公开设备描述构造或验证命令；
- 在 GeneratorProvider 提供的受限 builder contract 上调用命令，并规范化声明式数学贡献。

模块不读取设备目录路径，不拥有项目图、任务、数据库或求解器选择，也不将命令结果直接写入证据。

## 输入

| 来源 | 输入 | 进入条件 |
|---|---|---|
| devices | `DeviceDescriptor` | 描述已通过设备模块校验 |
| 命令 provider | `ModelCommand` 候选 | ID、版本、能力与依赖完整 |
| GeneratorProvider | 命令调用输入与受限 builder | 字段、单位、时间轴、连接和状态满足 command schema |

命令输入应表达设备参数、时间序列、控制量和前一状态等计算必需信息；不能把数据库对象、HTTP DTO 或前端表单直接作为输入。

## 输出

命令目录向装配模块输出命令描述，向生成器输出规范数学贡献。贡献至少包含：

- 变量、目标项、约束和与端口对应的流量；
- 明确业务单位、时间轴和索引关系；
- 状态变量、初值要求和跨步关系；
- 结果字段与反向单位映射元数据；
- 结构化诊断；
- 实际命令 ID 和版本。

调用失败不能返回形状正确但内容为空的伪结果。

## 开发思路

```text
设备 descriptor
    ↓ 选择建模方法
构造 ModelCommand 候选
    ↓ 校验输入/输出/单位/状态/版本
原子发布命令目录
    ↓
assembly 固定命令版本 → generator 在规范装配上调用
```

命令描述与命令执行分开：描述可在启动和装配时检查，执行只在输入完整后发生。这样缺失能力会在任务运行前被发现。

## 增加或修改命令

1. 定义稳定命令 ID 和语义版本；
2. 列出每个输入、输出、单位、形状和是否必需；
3. 声明状态迁移、确定性、随机种子和资源要求；
4. 提供公开执行入口，不暴露实现模块路径给调用方；
5. 用参考输入输出和容差做命令协议测试；
6. 验证相关设备描述能够解析该命令；
7. 验证 assembly 能固定版本且 generators 不需要增加设备类型分支。

## 失败语义

- 命令未注册或版本不匹配：装配阻断或 Worker 不 ready；
- 输入缺字段、单位不符或数组长度错误：返回完整命令输入诊断；
- 状态不完整：拒绝执行，不创建默认初始状态；
- provider 集合部分失败：整批不发布；
- 实现抛出内部异常：生成器失败且不发布部分 Bundle；保留追踪信息，对外使用标准诊断。

## 必须遵循的规范

- `modeling` 只消费 devices 的公开 descriptor；
- 命令目录与设备目录是两个独立事实源，不共享可变注册表；
- 命令 ID 不包含 Python 模块或文件路径；
- 命令不访问数据库、网络、对象存储，不写求解器文件，也不启动进程；
- 命令返回声明式公共 contract，不把 solver 私有对象跨给 generator；
- 输入输出 schema 必须能序列化并被快照固定；
- 数据预测模型必须声明模型版本、训练来源和适用范围；
- 任何随机行为必须接收显式种子。

## 完成标准

- 描述校验、注册原子性、调用、错误和版本不匹配均有测试；
- 新命令不需要调用方导入实现函数；
- 同一命令和输入在确定性声明下产生可复核结果；
- 命令版本写入计算快照和证据；
- 没有全局兼容表、旧函数名转发或运行期热加载。

代码阅读从 `modeling` 公开门面、命令 contract 和构造入口开始，再阅读各建模方法；对应测试以建模模块协议测试为入口。
