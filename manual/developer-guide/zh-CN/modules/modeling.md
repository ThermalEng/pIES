# 技术方程建模

> 文档状态：生效目标蓝图；目标代码边界：`backend/iesplan/modeling/`

## 作用

`modeling` 把设备 YAML 中受限声明式 `equations` 转换为计算生成器可消费的公共数学贡献。它隔离设备技术语义与具体求解器实现，使 assembly 和 generators 无需读取设备目录文件，也不需要按设备 ID 维护命令映射。

设备方程是设备定义的一部分，不是独立的 `ModelCommand`，没有独立命令 ID、设备语义版本或运行入口。设备具体内容由统一 `schema_version`、规范内容摘要和发布回执固定。

## 边界

模块负责：

- 受限方程表达式的词法、语法和语义校验；
- 把表达式解析成版本化公共 AST，禁止 `eval` 或动态导入；
- 校验变量、properties、interfaces、单位、索引和状态引用；
- 将方程 AST 规范化为变量、关系、状态迁移、接口流和结果映射；
- 向 GeneratorProvider 提供与 solver 无关的只读数学贡献；
- 维护方程语法/AST contract 的兼容性与确定性。

模块不读取设备目录路径，不拥有设备发布、项目图、规划经济输入、计算精度、任务、数据库或求解器选择，也不写求解器文件、不启动进程。

## 输入

| 来源 | 输入 | 进入条件 |
|---|---|---|
| devices | `DeviceDescriptor` | schema、内容摘要、properties/interfaces/equations 已校验 |
| assembly | 实例化上下文 | 属性覆盖、序列绑定、连接、时间轴和状态初值完整 |
| GeneratorProvider | 公共数学贡献请求 | 目标方程 contract 版本和所需能力受支持 |

输入只包含公开不可变 contract。规划价格、设备投资、运维成本、计算精度和算法选项由装配/计算配置直接交给生成器，不得伪装成设备 property 或 equation。

## 输出

公共数学贡献至少包含：

- 稳定命名的变量、索引域和取值边界；
- 等式、不等式、状态迁移和接口平衡关系；
- 与 `in/out/bidirectional/predefined/blind` 接口对应的序列引用；
- 明确业务单位、时间轴和广播规则；
- 结果字段与反向单位映射元数据；
- 结构化诊断；
- 设备内容摘要、方程 contract 和规范 AST 摘要。

设备技术方程不得包含价格或成本目标项。规划经济目标由计算配置与设备实例身份共同形成，生成器在系统合并阶段加入。

## 开发思路

```text
DeviceDescriptor.equations
    ↓ 安全解析
规范 AST
    ↓ 名称/类型/单位/索引校验
设备级数学贡献模板
    ↓ 按实例、时间轴、数据与连接绑定
规范数学贡献
    ↓
GeneratorProvider 合并技术贡献与规划经济配置
```

解析、语义校验和实例绑定分开：设备发布时即可发现非法方程；装配时证明具体数据与连接完整；生成器只处理已经规范化的数学贡献。

## 方程语言约束

- 仅允许公开白名单中的字面量、标识符、索引、算术、比较和受控函数；
- 名称只能引用当前设备声明的 property、interface 或 equation variable；
- 禁止函数/模块路径、反射、文件、网络、环境变量、shell 和任意代码；
- 禁止以显示名、数组位置或设备类型分支决定语义；
- 所有随机行为必须位于计算层并接收显式种子，设备方程本身保持确定；
- 方程语言或 AST 的破坏性变化提升其公共 contract MAJOR，而不是给每个设备增加版本。

## 增加或修改方程能力

1. 先确认现有语言能否由组合表达，避免增加设备专用操作符；
2. 定义操作符或函数的输入类型、单位、索引、边界和失败语义；
3. 更新解析器、AST schema、规范化和稳定摘要规则；
4. 增加合法、非法、单位冲突、越界、循环引用和复杂度上限测试；
5. 验证 assembly 能在运行前完成数据、连接和状态检查；
6. 验证至少一个 GeneratorProvider 能消费公共贡献且无需设备 ID 分支；
7. 若语义不兼容，先走 ADR 和 contract MAJOR 迁移，不增加旧命令兼容表。

## 失败语义

- 语法非法、未知标识符或循环引用：设备发布/装配阻断；
- 单位、形状、索引或接口类型不兼容：返回完整定位诊断；
- `blind` 接口被连接或 `predefined` 缺少合法数据源：装配阻断；
- 方程 contract 与 generator 能力不匹配：任务创建前阻断；
- 转换内部异常：不发布部分贡献或 Solver Bundle，保留追踪信息并对外返回标准诊断。

## 必须遵循的规范

- `modeling` 只消费 devices、assembly 和 core 的公开 contract；
- 方程内容随设备 descriptor 一同进行内容寻址，不存在独立命令目录；
- 不访问数据库、网络、对象存储和当前时间；
- 不返回 solver 私有对象，不写文件，不启动进程；
- 相同 descriptor、实例绑定和 contract 版本产生相同规范贡献；
- 业务单位到 solver 内部单位的实际换算只发生在 GeneratorProvider 边界；
- 数据预测算法的模型版本、训练来源和适用范围属于数据/算法快照，不进入设备技术定义。

## 完成标准

- 解析、语义校验、规范化、摘要、错误与兼容性均有协议测试；
- 新设备只提交统一 YAML/CSV 即可形成技术贡献，不新增命令 provider；
- generator 不导入设备实现函数，也不按设备 ID 分支；
- 设备内容摘要、方程 contract 和 AST 摘要进入装配依赖锁与计算证据；
- 没有 `ModelCommand`、设备专用命令版本、动态执行或运行期热加载旁路。

代码阅读从 `modeling` 公开方程 contract、parser、semantic validator 和 canonicalizer 开始；对应测试以设备方程协议测试为入口。
