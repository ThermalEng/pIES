# API 适配

> 文档状态：生效蓝图；代码边界：`backend/iesplan/api/`

## 作用

`api` 把 HTTP 世界中的路径、方法、Cookie、请求体和状态码，翻译成 application 可以理解的主体与用例命令；再把应用结果翻译成稳定响应。

API 是传输适配层，不是业务服务层。判断标准是：同一用例改成后台任务或命令行调用时，核心业务不需要从路由中复制出来。

## 边界

模块负责：

- 路由、HTTP 方法、媒体类型和请求大小；
- 认证依赖及 `ActorContext` 建立；
- Pydantic 请求/响应 DTO；
- HTTP 状态码、成功信封、错误信封和下载响应；
- 调用 application 用例并传递 request/trace ID。

模块不查询 ORM、不拼对象路径、不执行设备/财务/分析规则，不提交跨模块事务，也不返回兼容响应并集。

## 输入

| HTTP 输入 | 适配动作 |
|---|---|
| path/query/header | 解析资源 ID、游标、revision、幂等键和协商信息 |
| Cookie/认证信息 | 验证后形成主体上下文，原始秘密不进入业务层 |
| JSON | 严格解析成请求 DTO，不接受未声明字段或多形态值 |
| multipart | 校验媒体类型、大小和摘要，流式交给应用用例 |

请求 DTO 只负责结构与传输级约束；需要读取业务状态才能判断的规则属于 application 或领域模块。

模型 YAML 和算法插件 ZIP 上传遵守同一原则：API 只完成认证、限流、媒体类型、大小、流式摘要和 multipart 适配，不解析设备业务语义，也不 import 或执行插件。共享申请、管理员审核、安装和卸载分别调用一个明确 application 用例；共享园地列表不能泄露未共享条目。

## 输出

- 资源成功：`{"data": ..., "meta": ...}`；
- 创建资源：201；
- 接受异步任务：202；
- 无正文动作：204；
- 失败：标准 `error` 信封和统一 HTTP 状态；
- 下载：受控字节流或短期授权及真实摘要。

返回 DTO 与前端 contract 字段一一对应。ORM、堆栈、内部路径、provider 凭证和临时实现状态不得出现。

## 路由开发流程

```text
HTTP 请求
    ↓ DTO 结构校验
认证依赖 → ActorContext
    ↓
构造 Application Command
    ↓ 调用一个明确用例
Application Result
    ↓ DTO 序列化 / 错误映射
HTTP 响应
```

一个路由通常只做一次业务用例调用。若路由中连续组织多个业务 service、直接 commit 或出现设备/任务状态判断，应把逻辑上移到 application。

## 增加端点

1. 先确认用户场景和 application 用例已经定义；
2. 选择符合资源语义的路径、HTTP 方法和状态码；
3. 定义唯一请求和响应 DTO；
4. 明确认证、授权主体、幂等和并发条件；
5. 映射 application 的已知错误，不捕获宽泛异常伪装 200；
6. 生成并检查 OpenAPI；
7. 增加 DTO、权限、状态码、错误信封和关键值往返测试；
8. 同步前端 contract 与使用者指南中的用户可见行为。

## 失败语义

| 情况 | HTTP 结果 |
|---|---|
| 未认证或会话无效 | 401，不返回目标资源信息 |
| 已认证但无权限 | 403 |
| 资源不存在 | 404 |
| revision/幂等或生命周期冲突 | 409 |
| 结构或领域校验失败 | 项目统一的 400/422 与结构化诊断 |
| 内部异常 | 标准 500，客户端不含堆栈，日志关联 request ID |

## 必须遵循的规范

- 字段使用 `snake_case`，ID 作为不透明字符串；
- 一个字段只有一种未标记形态；
- GET 只读，写请求的重试语义明确；
- 列表使用稳定 cursor 和 `meta`；
- 上传下载不暴露存储路径；
- 前端展示换算不回流到 API，后端仍校验规范单位和范围；
- OpenAPI/schema 是具体字段的生成事实源，手册不复制整张字段表。

## 完成标准

- 路由只依赖认证/DTO/application 公开入口；
- 正常和全部标准错误状态有契约测试；
- OpenAPI 与前端 contract 的关键字段往返一致；
- 没有裸 ORM、响应并集、静默空列表或内部异常泄漏；
- 端点可在不理解前端组件的情况下独立说明。

代码阅读从目标路由的请求/响应 DTO 开始，继续到它调用的 application 用例；对应测试以各领域 API 测试和安全回归测试为入口。
