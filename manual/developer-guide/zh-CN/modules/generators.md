# 计算生成器

> 文档状态：生效目标蓝图；目标代码边界：`backend/iesplan/computation/generators/`。

## 作用

生成器负责把通过校验的装配产物转换成某类求解器能够消费的计算输入文件和运行命令。每个生成器聚焦一种稳定的问题表达与求解器组合；系统通过多个 GeneratorProvider 并列扩展，而不是在一个函数中按算法名称堆叠分支。

生成器是“编译器”，不是“执行器”。它完成语义降级、单位换算和文件生成，但不运行命令。

## 边界

模块负责：

- GeneratorDescriptor、Provider protocol、能力查询和独立注册状态；
- 直接消费装配产物、设备数学贡献、物化序列、有效财务快照、计算配置及冻结评价确认，不设外层包装；
- 按规范设备方程贡献收集变量、约束、状态、接口流和索引；
- 按规划配置形成目标、变量边界和规划约束，并从 `EffectiveFinanceConfig` 取得经济参数；价格或成本不得写回设备技术语义；
- 将税务关系纳入同一次模型：预合并系数、建立当期关系与跨期余额约束，目标与结果评价使用同一规则。业务口径及公式以[财务计算](finance.md#税务参与规划与现金流)为准；
- 将规范业务单位显式转换为求解器内部单位；
- 生成求解器输入文件、结构化命令、输出声明和 ResultAdapter ID；
- 规范化 Bundle。

模块不负责数据库查询、对象下载、网络访问、provider 发现、任务状态、进程启动、重试、日志采集和业务结果发布。

用户算法插件把加工程序与算法程序放在同一个不可变包内时，系统注册的是通用 `SandboxedAlgorithmGeneratorProvider`，而不是每个用户包。该 provider 基于上述直接输入构造包内加工请求，交独立 runner 只执行包内加工入口，再把生成文件、结构化命令和输出声明封装成标准 Solver Bundle；算法入口仍由 SolverRuntime 通过通用 ExecutorProvider 执行。不得因二者同包而合并生成与执行边界，或允许加工程序读取项目数据库、网络和当前草稿。

## 输入

| 输入 | 进入条件 |
|---|---|
| `ValidatedAssemblyArtifact` | 已由装配模块签发，零阻断诊断；实例、参数覆盖、连接拓扑、规划、财务/计费绑定、项目基线 |
| `models` | 装配实例 ID 到设备数学贡献的映射（键为实例，不是设备类型） |
| `materialized` | 已物化的运营期输入序列集合及物化元数据（`MaterializedSet`；`constant`/`data_repeat`/`data_full`/`data_predict` 统一为 `MaterializedSeries` 只读序列） |
| `finance` | 不可变 `EffectiveFinanceConfig`（地区及项目财务规则、价格和成本参数来源；评价确认另行直传） |
| `CalculationConfig` | 在计算阶段选择，包含预测算法与参数、generator、solver、精度、求解选项、收敛条件、种子和输出请求 |
| `evaluation` | 财务模块公开的不可变评价确认，来自同一任务冻结块；年限、折现率、付款与维护字段见[公共契约](../contracts.md#快照与异步契约)，不混入其余输入 |
| GeneratorDescriptor | 支持装配 schema、所选计算能力和 solver，且与 `CalculationConfig` 一致；属 provider 静态事实，不作为每次生成参数 |

各项输入均来自可信上游，生成器不重复验证已签发的装配、设备贡献、财务快照、序列或评价确认，不做内容摘要。Generator 只接收已完成物化的集合（`pending_predict` 为空，由上游在预测产物合并后构成，此处信任类型化交接，不复核）；完整运营时域由装配基线起始年/分辨率与评价确认的 `operation_years` 推导，`series` 为空的项目仍得完整时域，不回退单年。付款计划与维护费用按财务时点消费，不放进物化集合，不建立外层输入包装。

### 税务提交能力

需量计费能力使用同一描述符机制：`finance.monthly_demand` 表示能构造真实自然月峰值、需量费用及其同次解事实。任务实际绑定需量费时必须同时具备该能力和 `finance.financial_facts`；没有需量绑定时不因目录内闲置费项拒绝。现有税务能力覆盖新增的显式需量费税务范围，不另建注册表；具体数学实例所需有限界仍由生成器构模报告，不复制到提交预检。

税务支持复用 `GeneratorDescriptor.capabilities`，不另建生成器白名单或注册表。`finance.vat`、`finance.construction_input_vat`、`finance.income_tax` 分别声明对应已定义税则种类，`finance.credit_pools` 声明抵扣池，`finance.financial_facts` 声明同次解财务事实输出。采用税则或抵扣池的任务还要求财务事实输出能力；空税则且空池不因缺少税务能力标记而拒绝。

任务提交用已解析的所选生成器描述符核对所需能力，缺失时返回 `TASK-REQ-007` 并标明缺失项，不静默按税前执行，也不按provider名称或版本字符串猜测支持。维护引用、评价期间及财务规则自身约束仍在原公开入口核对一次。类别支持不承诺每个数学实例均可降级；具体表达式、有限界和正残值等建模能力限制仍由生成器实际构模时报告，不在API生成计算包或复制模型预校验。

### 逐步技术约束能力

`technical.step_constraints` 表示生成器能把[逐步技术约束](../formats/assembly-yaml.md#逐步技术约束)的显式引用绑定到同一项目模型的真实端口变量，并在完整运营时域逐步施加关系。规划变量保持决策量，单位转换沿用生成器唯一边界。启用关系参与同一次求解，不能只在求解后检查或按样例设备名补约束。

配套内置生成器目标为 `ies.generator.highs_milp@7.0.0`，消费装配 `5.0.0`；该版本扩展输入可行域语义，只有输入到执行链完整接通后才发布能力。母线守恒、财务三件套 `6.0.0` 和现有结果映射不变，适配器仍为 `ies.result-adapter.highs@6.0.0`；solver、executor 和通用 Bundle 不随输入版本机械升版。相同端口的结果继续使用既有步序列映射，不另建约束专用结果协议。

## 输出

成功输出 [Solver Bundle](../formats/solver-bundle.md)，包含：

- `bundle.yaml`；
- 一个或多个只读输入文件及媒体类型；
- 结构化 command；
- 允许写入的输出清单；
- 配套 ResultAdapter 的精确 ID 与版本；
- assembly、`CalculationConfig`、generator、solver 和依赖版本追溯信息。

失败输出结构化诊断，不发布临时目录或半份 manifest。

步序列的求解引用由生成器在建立实际变量时显式声明，形状以 [Bundle 步序列结果映射](../formats/solver-bundle.md#步序列结果映射) 为唯一正文。业务单位恢复和统一结果发布归 ResultAdapter；不得把生成器内部列命名规则交给 application 或前端反解。

## 内部开发分层

一个生成器建议按以下纯步骤组织：

```text
接收已签发输入
  ↓
收集变量与关系：设备、网络、规划、财务
  ↓
解析引用、单位与时间索引
  ↓
汇集完整关系并分析所需上下界
  ↓
等价转换条件关系、互斥与分段关系
  ↓
按时间结构实例化稀疏系数与结果映射
  ↓
求解器格式 writer
  ↓
command/output manifest builder
  ↓
Bundle 规范化与原子发布
```

各步骤使用不可变中间 contract。求解器格式 writer 不应重新读取设备模型；command builder 不应重新解释装配业务。

上述为生成器的目标组织方式，不新增外层业务事实或强制所有 provider 使用同一私有中间类型。先完成相关关系的收集，再消费其边界；不能因遍历设备的先后顺序决定某关系是否可转换。结构不变的表达式复用转换模板，时变输入填入对应系数；状态首步、跨期和条件变化仍按原语义处理。

公开单关系降级与项目模板绑定复用同一求值语义；模板只复用结构，不共享不同实例的参数或不同时步的运行决策。分块展开继续引用全局相邻状态，不在块首或年首重置；稀疏行与结果映射使用同次构模分配的实际列，减少中间表达的复制。性能对照分别记录正常耗时和内存追踪结果，区分构模、文件写出及求解，不以模板编译次数下降推断完整链路提速。

### 统一上下界

用户定义业务范围，模型定义有效域，生成器推导计算所需的界。统一遵循：

1. 模型声明的有效域与项目边界共同约束决策量。各来源取交集，下界取最大、上界取最小；缺席或 `null` 只表示该来源未提供该侧有限界。模型域随规划接管保留，不以技术属性当前值或模板参考值代替规划边界。
2. 派生界是已有等式、不等式和状态关系的推论，不是新增业务约束。记录到足以定位来源关系的程度即可，不建立摘要、重复校验或全局注册表。只有被证明冗余的收紧才可加入模型。
3. 额定容量、实际流量、状态量和金额表达式分别求界。流量有限不自动推出装机容量有限；不同变量的独立区间不能替代已知关联关系。容量为零、上界为零均是合法边界。
4. 互斥、最大值、选建关联和税务分段关系消费同一次构模中的界分析结果，按实际转换需要取得界；普通线性变量允许无有限上界。需要的表达式可有界而其单个变量无界。
5. 先采用代价与模型规模相适应的推导；未取得有限界时报告具体关系的转换条件不足，不声称数学问题已经无界。禁止猜 Big-M、最小建设量或以未经证明的目标偏好收缩可行域。
6. 已有输入校验负责显式范围冲突，生成阶段报告由组合关系发现的冲突与转换能力不足。提交层只查公开能力类别，不复制模型构建或界推导。

模型模板中每个有限域都应有技术定义依据。仅为编辑方便设定的大数不应作为模型硬上界；更正模板属于显式模型修订。改变规划接管后的有效域语义须升级受影响的生成器及公开契约，不在旧版本下悄悄裁剪历史输入。

合成例：`C = 3 hour × P` 且 `0 <= P <= 4 kW`，可推出 `0 <= C <= 12 kWh`；仅有“实际输出不超过负荷 4 kW”不能推出额定功率不超过 4 kW。`x-y=0` 时差值为零，也不要求 x 和 y 各有有限界。这些规则不依赖设备类别。

### 精确转换与求解策略

固定费用使用模型明确的建设激活或无条件发生关系，见[建设激活目标语义](../formats/assembly-yaml.md#建设激活目标语义)。互斥、峰值与税务状态均保持其原始含义；正电价、低于一的效率或非负费用单独不构成删除约束的证明。

按需增加互斥是一种可选的精确求解策略，不是默认删除关系。其正确性要求：中间模型是原问题的松弛；已加入的原约束保持有效；最终候选满足全部原关系；最优性由候选目标与有效界共同支持。发现新的违规关系后继续加入并求解，达到资源限制时保留实际状态，不宣称收敛。数值可行性使用与单位、尺度及计算精度相符的容差，不把容差内满足称为数学精确等式。

策略比较使用完整精确模型作小规模对照；记录重求次数、实际整数变量数与总资源消耗，不能预设大多数时步均可省略。求解后可行性检查若属于该算法的终止条件，由算法实现负责，不扩散为 Worker、存储或结果读取的重复复核。生成器仍不启动 solver，通用 Runtime 仍不解释业务；需要迭代执行的 provider 必须先明确其版本化执行协议，不能临时加入运行期业务分支。

### 时间结构与等价优化

运行步、税务结算期和财务年度是不同索引。它们按冻结基线和评价参数显式映射；输入序列重复不表示优化变量、状态或各期税额重复。全运营期与全评价期的含义不因内部压缩而改变，结果映射必须能恢复原时域所声明的事实。

优先复用表达式结构、输入表示和稀疏生成，减少中间副本；这些优化不减少独立决策。共享运行决策或压缩年份则须证明对完整约束与目标等价，覆盖状态连续性、初值、月边界、税务余额和年度边际收益。不能仅凭 `data_repeat`、相同价格或已知税率认定等价，不能增加用户未声明的年末状态闭合约束。

无法证明压缩等价时保留独立运行块；求解时间预算不足时报告资源状态。小规模对照核对原模型可行性、目标与同次解财务关系，允许多个最优解产生不同调度。近似典型期模型属于另行声明的计算方法，不作为精确全周期结果输出。

## 项目级线性模型与 MPS writer

本节和下文具名 provider 描述已有版本的精确协议。上文编译、边界与等价优化是扩展目标；端口网络升级以[端口级网络语义](assembly.md#端口级网络语义)为准，不能在既有 provider 版本下重新解释母线。

显式财务目标入口按[装配规划契约](../formats/assembly-yaml.md#规划表达式中的财务分量标识符)识别。生成器以同一组建设、运行及财务关系构建逐年现金流表达式，再按冻结折现率组合 NPV 目标，不先求解另一税前方案。现金流保留建设付款时点、年度固定运维、实际运行量对应年度的可变运维与能源收支及维护清单，不把全期合计均摊为年值；税额关系按[财务模块](finance.md#税务参与规划与现金流)接入。

`build_project_model` 把各项直接输入装配成项目级 `LinearModel`（变量声明、约束行、目标表达式与 min/max 方向）、单位映射与目标业务单位，不设包装层：按基线展开全部连续 `step`，实例与时步确定命名；技术关系经现有 lowerer 逐降（`t`/`t-1`、Big-M，有限界来自值域数值或实例额定引用）；公开原语 `step_duration` 以基线导出的 SI 秒注入；连接只定义连通性，按 carrier + 无向连通分量逐 step 生成一条母线守恒式（out/bidirectional 为正，in 为负），无边载体不建平衡式；负荷需求经可连接输入口与 serve 方程进入母线；规划目标/变量/约束与财务/计费分量按绑定展开；物理量归 SI、金额守币种；计费支持 constant、time_series 与 monthly_daily（时变价格由第三项价格区逐点 `price[t]×e[t]` 计价，`constant` 同一逐点语义；未知价格类型明确拒绝）。`write_mps` 只序列化已完成的 `LinearModel`（稳定 ROWS/COLUMNS/RHS/BOUNDS/整数标记/OBJSENSE，目标常数以偏移量单独报告），同一模型逐字节相同。

## 首个内置 provider 与完整 Bundle 聚合

首个内置 provider 为 `ies.generator.highs_milp@7.0.0`（见“首个内置链”）：mode 只要 `planning`、精度只要 `medium`、solver 只要 `ies.solver.highs@1.7.2`；options 只接受空对象；输出请求支持 `solution` 与 `metrics`（`metrics` 为 ResultAdapter 后处理请求，不对应求解器第二个原始文件，未知输出明确拒绝）；只消费装配实际绑定的 constant/time_series/monthly_daily 计费价格（快照中未绑定的价格条目不触发拒绝），未知价格类型明确拒绝；`seed` 为 null 时使用固定种子 `0`，种子同时固定进求解命令与元数据，不读取随机全局状态。

`generate` 返回唯一完整聚合：manifest（即 `bundle.yaml` 内容）加按规范相对路径索引的只读输入文件字节映射（`input/problem.mps` 与 `input/parameters.json`）。`input/parameters.json` 为最小规范 JSON 元数据，只保存 ResultAdapter 后续必需的 `unit_map`、`objective_offset`、`objective_unit`（目标业务单位，按编译期根量纲确定：金额取财务币种，无量纲取 `"1"`，单一物理量纲取 SI 基准单位）、财务分量求值声明 `components`（分量 ident → `{unit, caliber, constant, terms}`，与目标同一分量展开路径，不依赖目标写法）、请求 outputs、固定 seed、precision 与装配/引用追溯，不复制完整装配、模型与财务，不写 hash。结构化命令按真实 HiGHS CLI 语法逐项存储（非 shell），`time_limit_seconds` 同时进入硬资源声明与求解器选项且语义一致；同一组直接输入与 provider 版本逐字节相同，不写临时目录，不启动 solver。

注册表注册真实 provider 实例：`ref` 与描述符引用单一来源；`resolve` 完成通用门禁后返回可调用 provider，快照与目录只公开描述符数据；任一候选不符即整体构建失败。组合根显式注册内置 provider，不动态扫描。

### 生成阶段协作停止

稳定 `generate` 接口保持原有业务输入。需要在生成过程中响应停止的 provider 可提供 `generate_with_stop` 扩展，接收同组业务输入及关键字停止探针 `stop`。探针返回 `None` 表示继续，`cancelled` 或 `fenced` 表示停止；生成器以对应 reason 的 `ComputationUnavailableError` 结束，不返回半成品 Bundle，也不自行管理任务状态或进程。

内置 HiGHS 在模型展开和 MPS 输出期间检查探针。未提供该扩展的 provider 仍按稳定接口调用，应用层在生成前后检查停止，不保证生成过程可即时中断。

## GeneratorDescriptor

descriptor 至少声明：

- 稳定 generator ID 和版本；
- 支持的 assembly schema MAJOR/MINOR、计算 mode、precision 和问题能力；
- 兼容 solver ID/版本及所需 executor 能力；
- 支持的输出请求 `outputs`，请求集合必须是声明集合的子集；
- 支持的方程 contract、AST 和数学贡献能力；
- options schema（完整 Draft 2020-12 对象，根描述 object 且 `additionalProperties` 显式 false；无选项用显式空对象 schema，不用空 `{}`）、默认语义和资源上界；
- 内部单位体系、确定性承诺和种子语义；
- 生成的媒体类型、ResultAdapter ID 和版本关系。

计算配置保存入口通过生成器公开目录统一核对精确引用、mode、precision、solver、outputs 和 options schema；不支持时返回字段诊断与可用能力，不追加配置 revision。API 不生成 Bundle、不复制具体数学模型检查；具体模型的降级能力仍在生成阶段判断。装配阶段不选择或锁定 generator 与 solver。非法选项直接拒绝，不回退其他生成器，不删字段、不补默认；schema 内 `default` 只作描述。

## 设备方程如何参与

设备 descriptor 内的声明式方程是设备到数学贡献的公开边界。生成器消费 modeling 已解析、校验和规范化的贡献，并接收：

- 实例 ID、已校验 properties 和状态初值；
- 已由当前计算阶段按项目基线物化为连续 `step` 的预定义接口数据和连接接口；
- 存量/新增身份、规划配置以及不可变 `EffectiveFinanceConfig`；
- 由 generator 提供的能力受限 builder contract。

方程贡献提供声明式变量、技术约束、状态关系、接口流和结果映射元数据，不直接操作具体 solver 私有对象，不写文件，不运行进程。目标及规划边界来自规划配置，成本分量、O&M 与能源价格等共用经济参数来自 `EffectiveFinanceConfig`；预测算法、计算精度及求解选项由 `CalculationConfig` 决定。预测训练与序列生成由上游物化完成；生成器每次消费本轮完整运营期序列并构建技术／财务模型。耦合预测的反馈与重求解流程由 Worker 经 application 阶段命令编排。

## 单位与数值

装配阶段证明单位和量纲兼容，生成器执行唯一实际换算：

- 每个输入字段有来源业务单位、目标内部单位和换算记录；
- 禁止根据字段名猜单位；
- 同一 quantity 的内部单位由 GeneratorDescriptor 固定；
- 比例统一为 `0..1`；财务金额带币种和基准年语义；
- 非有限数、溢出和病态缩放在写求解器文件前失败；
- 结果映射元数据保留反向换算所需信息。

单位换算不得散落在设备方程解析和格式 writer 的常量中。

## 纯度与确定性

生成器必须满足：

- 不读取进程环境、当前时间、随机全局状态和机器 locale；
- 不访问网络、数据库、对象存储和用户目录；
- 不启动进程或动态下载 solver；
- 文件顺序、变量名、约束名、数字格式和归档元数据稳定；
- 随机性只能来自显式种子；
- 同一输入产生逐字节相同的规范 Bundle。

Bundle 以规范 manifest 与全部输入文件作为身份，不另放随机 ID 破坏确定性。attempt ID 属于执行回执，不参与 Bundle 内容。

## 增加一个 GeneratorProvider

1. 选择新的稳定 ID，列出 mode、solver、方程 contract 能力和输入媒体类型；
2. 定义 options schema、内部单位和 ResultAdapter；
3. 建立最小合法装配、边界装配和已知答案；
4. 先实现数学中间表示与确定性命名，再实现 solver writer；
5. 生成结构化 command，不接受用户 shell 片段；
6. 完成 manifest 和原子发布；
7. 用 fake runtime 验证 Bundle contract，用真实 solver 容器做独立集成验证；
8. 注册 provider 并验证缺依赖、重复 ID 和半失败不会发布。

## 首个内置链

首个内置 provider 为 `ies.generator.highs_milp@7.0.0`，兼容求解器 `ies.solver.highs@1.7.2`，结构化命令执行器前向引用 `ies.executor.local_process@1.0.0`，结果适配器前向引用 `ies.result-adapter.highs@6.0.0`。技术模型支持可证明的仿射关系，以及有限非负上下界下 `x*y=0` 的确定性二进制 Big-M 转换；设备状态仅允许 `t` 与 `t-1`；公开规划变量为连续变量。生成器可为受支持的互斥关系及[财务税务关系](finance.md#求解能力边界)引入必要的内部离散变量，所需界由业务参数和变量边界推导。电池“规划容量参与 SOC 分母”一类双线性明确不支持。

独立评价确认是必需生成输入，不提供默认评价值。生成器、结果适配协议与通用 Bundle manifest 分别按自身契约独立版本化。

显式全周期 NPV 目标消费完整现金流；金额及期间以财务契约为准。未支持的关系类别在公开提交能力检查中拒绝；具体模型的转换条件不足在生成阶段定位报告。

增值税关系按财务文件声明构建经营进销项、建设进项及共享抵扣池的连续月度状态，将实缴与退款到账纳入同次 NPV 目标；进项确认、财务年度映射及终期余额以财务契约为准。金额系数预合并，余额和分段税额由精确约束确定，不依赖目标函数压紧。

所得税关系依财务配置将计税基础、直线折旧及先到期先用的亏损结转纳入同次求解，所得税按对应财务年度进入现金流；折旧与亏损使用不作为现金支出重复扣除，税额与抵扣顺序不依赖规划目标压紧。

配套财务三件套为 `6.0.0`：年度固定项与线性项按同一年率单位进入计算；折旧按明确的初建／维护来源构建，不按财务类别合并掉不同来源；显式净现金项目按时点加入完整现金流。具体字段与金额、期间语义以[财务格式](../formats/finance-yaml.md)为准。配套适配器恢复来源身份与净现金明细，不在求解后追加金额；能力未完整接通前，不以旧 provider 版本接受新版输入。

生成器声明与模型同源的实际现金及税务事实，使配套适配器恢复完整年度现金流；已有财务分量和求解序列保持原有用途，不以新增通用分量口径或解析命名替代结构化财务映射。字段以[财务事实映射](../formats/solver-bundle.md#同次解财务事实映射)为准。

## 月份日价格能力

`finance.monthly_daily_prices` 表示生成器能够消费月份日价格已物化的完整运营期序列。只有实际计费绑定使用该来源时，提交才要求此能力；未使用条目不触发能力拒绝。内置 `ies.generator.highs_milp@7.0.0` 声明此能力，配套 `ies.result-adapter.highs@6.0.0`；来源扩展不改变既有财务事实输出形态。其他生成器精确版本是否支持按其公开能力声明判断，不依赖名称或版本字符串猜测。

生成器保留来源类型，识别新来源后进入既有已物化价格逐点计价路径，不改写冻结财务为 `time_series`，不再展开公历规则、不读来源对象或重复核对点数。计价、VAT、所得税及财务结果继续消费同一逐点价格关系。

## 关联年度维护能力

生成器声明 `finance.affine_maintenance`，并与配套适配器共同完成金额恢复，表示支持规模／建设成本关联维护金额及同源现金、税务和结果恢复。金额输入见[年度维护金额来源](../contracts.md#年度维护金额来源)，同次解声明见[关联维护金额协议](../formats/solver-bundle.md#关联维护金额协议)。提交含关联项时必须核对该完整能力；仅确定金额的输入不要求此能力。

## 失败语义

互斥关系中的零上界是合法边界。若某一因子已由有效边界证明恒为零，乘积为零的关系恒成立，不生成互斥二元变量，也不为另一因子要求互斥专用的有限上界。其余独立约束照常保留。不能证明恒为零时，沿既有非负性与有限界规则精确降级；不猜 epsilon、扩大边界或删除实际互斥关系。

| 问题 | 结果 |
|---|---|
| 非法装配输入 | 装配/application 边界阻断，不进入生成 |
| 必需直接输入不完整 | 调用方输入不完整，不生成 Bundle |
| 方程 contract 或 solver 能力不匹配 | 兼容诊断，执行前阻断 |
| 超出已声明精确降级能力的非仿射关系（变量×变量、变量作除数、非常数幂等） | 明确拒绝，不近似、不回退 |
| 所选转换需要的非负性或有限界未能证明 | 生成能力诊断，定位原关系及所需条件；不猜 Big-M，不称为已证明无界或内部错误 |
| 组合关系推出互相矛盾的界 | 报告约束冲突及来源，不通过扩大边界继续 |
| solver 证明不可行或无界 | 保留对应数学状态，不混同于生成器未能推导界 |
| 达到时间或内存预算 | 保留资源终止状态；如有候选，分别报告原模型可行性与最优性状态 |
| `[t-k]`（k>1）时间引用 | 设备发布输入边界拒绝 |
| 单位无法换算或出现非有限数 | 数值输入诊断，定位字段/实例 |
| writer 中途失败 | 临时产物废弃，不发布 Bundle |
| 相同输入不稳定 | 确定性契约失败，provider 不 ready |

禁止捕获异常后改用另一生成器、删去约束、零填数据或生成“尽力而为”Bundle。

## 必须遵循的规范

- 只消费装配、规范方程贡献和 core 的公开 contract；
- 一个 provider 拥有自己的注册候选，组合根原子发布；
- 所有相对路径由 Bundle builder 生成并校验；
- command 只能引用受信任 executor/executable ID；
- `CalculationConfig` 的 generator 版本、options、seed、依赖锁和输出进入任务证据；
- 日志不输出完整业务数据、凭证或宿主机路径。

## 完成标准

- 不启动 solver 即可完成全部单元与契约测试；
- 最小装配的变量、约束、单位和输入文件可人工复核；
- 相同输入逐字节可重复；
- 非法装配、资源、能力和数值均在生成边界阻断；
- 通用 SolverRuntime 不包含该 generator 的专用分支。

代码阅读从 GeneratorDescriptor/Protocol 开始，再看规范中间表示、单位转换、具体 writer 和 Bundle builder；测试按“纯生成 → Bundle contract → 容器内 solver 集成”分层。
