# 装配与检查

> 文档状态：生效目标蓝图；代码边界：`backend/iesplan/assembly/`；文件契约：[装配 YAML](../formats/assembly-yaml.md)。

## 作用

`assembly` 是从可编辑业务状态进入计算世界的唯一同步闸门。它把不可变项目计算基线、已校验的预定义来源声明与固定输入引用、项目模型实例、连接、规划配置和装配前合并的不可变有效财务快照整理为标准装配 YAML，证明这份业务输入完整、引用稳定且具备规划与财务计算所需信息，然后签发不可变 `ValidatedAssemblyArtifact`。

装配确认业务输入、引用和领域约束合法，再交给生成器判断具体数学转换能力。装配通过不是数学可行性或有限时间求解的证明；它不是可选的 GUI 预检查，也不应提前混入某个 solver 的对象和命令。

## 边界

模块负责：

- `ies.assembly` schema、解析、规范化和版本兼容；
- 把公开项目图导出为可手写、可审查的装配 YAML；
- 校验结构、项目计算基线、接口类型、载能、量纲、单位、预定义来源声明与固定输入引用、各来源模式的时间覆盖、分辨率和连续 `step`、方程、规划配置、`EffectiveFinanceConfig` 与整体可解性；不同原始来源的点数只在计算阶段物化后统一；
- 生成稳定规范装配文本；
- 签发依赖版本与校验回执。

模块不读取 ORM、用户会话、任务队列和 BlobStore 私有路径，不生成 MPS/LP 等求解器文件，不生成或执行命令，不选择 generator、solver、精度、算法选项或输出，也不修改项目草稿。

## 输入

装配有两个等价公开入口，最终进入同一 `AssemblySpec`：

| 输入方式 | 来源 | 进入条件 |
|---|---|---|
| 项目导出 | application/project | 设备、连接、数据和配置使用稳定 revision |
| 手写装配 YAML | 插件包、离线交换或开发样例 | 遵守 `ies.assembly` 安全格式 |

校验还需要显式注入：

| 依赖 | 所有者 | 进入条件 |
|---|---|---|
| 设备目录快照 | devices | 设备 ID、统一 schema 版本、descriptor 与发布内容身份完整 |
| 方程 contract | modeling | equations 可安全解析，AST/贡献 contract 版本可支持 |
| 数据版本/资源 | dataset/storage | schema、内容身份、原始采样信息、规范化/变换回执、来源声明、字段和质量明确 |

所有输入是公开 contract 或不可变快照，不是数据库行、前端表单状态和运行目录。

## 输出

成功输出 `ValidatedAssemblyArtifact`，由两部分共同组成：

1. 规范装配文本：schema `ies.assembly`、版本、项目计算基线、预定义来源声明与固定输入引用、内容资源和稳定顺序；
2. 校验回执：校验器 ID/版本、规范化算法版本、依赖版本和零阻断诊断。

产物保留明确业务单位。它保证单位和量纲兼容，但不转换为某个生成器的内部单位。下游 [GeneratorProvider](generators.md) 必须直接消费完整二件套，不能只接受裸 `dict` 或旧项目形状。

失败时输出有顺序、可定位的诊断集合，不产生部分 artifact、临时计划或可被 Worker 执行的对象。

## 四阶段开发思路

### 1. 结构阶段

解析 YAML 安全子集、schema、ID、必需字段、判别联合、内容身份字段和引用形状。重复键、未知核心字段、危险路径和可执行字段在这里拒绝。

### 2. 模型与数据阶段

核对设备内容、properties、equations、状态、接口数据、单位、时间覆盖和固定资源引用。序列接口完全来自公开 descriptor；只有 `predefined` 可绑定 `constant/data_repeat/data_full/data_predict`，`blind` 不得连接也不得作为预定义数据入口。

### 3. 图与系统阶段

校验 `out/in/bidirectional` 连接、载能和量纲兼容、自环、重复边、非法盲端、网络连通、关键负荷供给、平衡和系统约束；同时校验存量/新增身份及求解前必需的投资、O&M 和能源购售价格。

连通性与传输限制是不同关系。装配和生成的平衡方程共同保留模型明确声明的端口边界、流向与传输约束；不以缺少直连边或画布箭头推断来源外送权限。同载体路由的内部守恒在共同母线中抵消时，不能把它解释为已经实现网络隔离。跨实例关系通过公开的系统约束或网络契约表达，不靠设备名称、来源白名单或生成器专用分支。

跨实例逐步关系采用[装配格式的逐步技术约束](../formats/assembly-yaml.md#逐步技术约束)：局部引用绑定真实端口，沿用同一运营时域和设备变量；装配负责公开输入的引用、索引和量纲检查，生成器负责关系降级。逐步约束本身不重新解释连接，不由装配提前生成求解器约束行。

### 端口级网络语义

以下为网络扩展的目标语义，须经装配与生成器的版本化迁移发布，不能静默改写旧装配的连接含义。

- 网络以实例的真实端口为边界。外部连接关系与设备内部转换关系分别声明；两个端口不因属于同一设备、同一载体而自动连通或合并。
- 理想公共母线表示混合能量池，可按明确的理想连接合并端口。具有容量、损耗、方向或隔离约束的传输关系保留独立关系及所需流量；不以设备级无向连通分量替代整个网络。
- 输入、输出和双向端口分别遵守公开符号约定。单向分配关系使用非负流量，端口收发量等于所关联分配流量之和；双向交换保持明确的符号和设备内部约束，不按设备名称自动拆成充放端口。
- 物理连接、定向能量分配、来源追踪和跨端口运行策略具有不同含义。理想母线混合后，不从净流量反推来源；需要来源归属时声明分配或带来源的守恒关系，涉及储存时同时说明跨期来源归属。
- 限制某来源直接外送不等于限制它通过替代负荷而增加其他来源外送。后一类要求用明确的运行策略及必要基准表达，不从缺边推断，也不把某种政策设为全项目默认。

语义示例：两个端口经理想连接汇入同一母线，可共同满足负荷；转换设备的输入、输出属于不同端口边界，由设备方程传递能量。另一例中，既有电源供给 4、负荷 4，新增电源供负荷后既有电源外送 4，仍满足“新增电源无直接外送分配”；要求外送不增加时，需要另行声明对应策略。这些是语义示例，不是现有 schema 的新增字段。

### 4. 规划与财务完整性阶段

确认规划目标、规划变量与边界、规划约束，以及所有同时参与规划和财务计算的公共财务参数完整且相互一致。generator、solver、精度、算法选项和输出请求在从装配产物生成 Solver Bundle 时通过独立计算配置选择，不属于装配校验。

只有当前结构足以可靠支撑下一阶段时才继续；同一阶段应尽可能聚合多个可修复问题。四阶段通过后，解析资源、规范化并签发产物。

## 规范化

规范化是公开纯过程：

- 项目计算基线按固定的 `resolution/scenario_mode/start_year` 规范化（无 `leap_year`）；
- 预定义来源按稳定模式、目标类型和对象输入引用规范化；
- `relative_file` 解析为内容 ID 和媒体类型；
- 映射和无业务顺序集合按稳定键排序；
- 数值使用唯一有限表示；
- 注释、YAML 表示差异和显示空白不进入语义；
- 项目计算基线、设备 revision、方程 contract、规划配置、`EffectiveFinanceConfig` 和所有资源形成完整依赖锁。

相同语义必须产生相同规范文本。规范化算法变化必须版本化；历史 artifact 不能用当前算法悄悄重算后覆盖。

## 增加装配字段或规则

1. 确认字段的唯一所有者；若属于设备模型、CSV、方程 contract、规划配置、财务文件契约或 calculation 配置，先修改其权威 contract；
2. 说明字段的类型、单位、空值、顺序、默认和版本兼容；
3. 判断新规则属于结构、模型与数据、图与系统还是规划与财务完整性阶段；
4. 分配稳定诊断码、严重度、位置和修复提示键；
5. 更新装配 schema、手写示例和规范化测试；
6. 增加合法、单点非法、多点非法和边界拓扑测试；
7. 若核心字段语义不兼容，先走 ADR、升 schema MAJOR 并提供迁移器。

不要用装配字段暴露 generator 的工作路径、solver 参数字符串、精度、输出选择或实现模块名。计算选项由生成 Solver Bundle 时提交的 `CalculationConfig` 承载，并由 GeneratorDescriptor schema 管理。

## 失败语义

| 问题 | 结果 |
|---|---|
| schema、重复键、引用形状或版本错误 | 结构诊断，阻断 |
| 设备内容、方程、属性、接口数据或单位不完整 | 模型/数据诊断，阻断 |
| 接口类型、载能、拓扑或系统约束非法 | 图/系统诊断，阻断 |
| 存量/新增身份、规划配置或公共财务输入不完整 | 规划/财务输入诊断，阻断 |
| 外部导入资源格式不合法，或相对路径逃逸 | 导入诊断，阻断 |
| 非关键质量建议 | warning/info，写入回执后可继续 |

禁止在缺接口时创建默认双向接口、把 `blind` 改成可连接、删除非法边后继续、用零填充缺失数据、把未知 generator 换成内置实现，或在异常后构造 `_direct_plan`。

## 必须遵循的规范

- 边只连接允许连接的真实序列接口，不连接设备抽象类型；
- 损耗、延迟和非同时性通过明确设备或约束建模；
- 业务单位在 artifact 中明确，装配只证明兼容，不执行 solver 内部换算；
- 装配 YAML 不含 shell、executable、函数路径、环境变量、凭证或宿主机路径；
- 项目计算基线、所有设备 revision、方程 contract、schema、规划配置、`EffectiveFinanceConfig` 和资源版本进入依赖锁；
- 参与序列化的顺序唯一；
- artifact 不包含 GUI、HTTP、ORM 和存储 provider 私有形状；
- 只有 `ValidatedAssemblyArtifact` 可以进入 generator。

## 与生成器的交接

装配器承诺“业务输入有效且规范”；生成器承诺“从该规范输入和已校验的 `CalculationConfig` 确定地产生 Solver Bundle”。二者之间不共享可变 builder、solver 对象或进程上下文。

生成器入口直接消费装配器签发的 artifact，不得重新解释原始 YAML、访问最新项目或补做本应由装配阶段完成的业务校验。这样开发 assembly 时只需理解文件 schema 与业务规则，开发 generator 时只需理解规范 artifact 与代码。

## 完成标准

- 手写装配和项目导出进入同一 schema/校验路径；
- 四阶段都有独立、组合和稳定诊断测试；
- 非法输入没有任何旁路进入 generator；
- 相同语义输入产生相同规范文本和依赖锁；
- 新设备只要满足统一设备模型和方程 contract 即可装配，不增加类型分支；
- 装配模块测试不生成求解器文件、不运行命令。

代码阅读从 assembly 公开门面、`AssemblySpec`、诊断和 `ValidatedAssemblyArtifact` contract 开始，再按 parser、validator、canonicalizer、receipt signer 的数据流阅读；文件字段以[装配 YAML 标准](../formats/assembly-yaml.md)为准。
