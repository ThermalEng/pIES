# 结果分析

> 文档状态：生效蓝图；代码边界：`backend/iesplan/analysis/`

## 作用

`analysis` 回答“一个结果是否可信、不同方案如何比较、输入变化会造成什么影响”。它位于计算与财务结果之后，组合公开结果，但不重新解释项目草稿或修改来源证据。

## 边界

模块负责：

- 工程、环境和运行指标；
- 单因素敏感性、多参数批量和场景比较的纯分析逻辑；
- 物理、最优性、财务和可靠性四个独立维度的系统评估；
- 分析输入、输出、适用范围和完整性的版本化 contract。

模块不负责 Worker 租约、任务状态、数据库选择、人工审批和报告持久化。系统评估与人工评估是两个不同用例，不能互相伪装。

## 输入

| 输入 | 进入条件 |
|---|---|
| `ComputeResult` | 状态、版本、连续 step 序列轴和完整性明确 |
| `FinancialResult` | 财务状态与口径完整 |
| 分析命令 | 指标、参数路径、取值或分布及随机种子明确 |
| 证据上下文 | 来源快照、attempt 和适用范围可追溯 |

分析只能使用同一逻辑快照或明确声明可比较关系的结果。不得把当前项目值与历史结果静默拼在一起。

## 输出

- 指标及单位、统计范围和有效样本数；
- 参数变化、结果变化和排序依据；
- 场景/批量结果及每项技术状态；
- 四维评估各自的细分状态、证据和总体摘要；
- 分析算法、版本、随机种子及来源引用。

综合摘要是导航信息，不能覆盖任何独立维度的失败。

## 开发思路

```text
冻结结果与证据
    ↓ 选择明确指标
纯指标函数
    ↓
扫描 / 批量 / 评估编排
    ↓ 完整性和样本检查
版本化分析结果
```

单个指标函数、参数应用和排序应保持纯计算；长时间的重复运行由 Worker/application 编排，analysis 只定义命令和怎样聚合公开结果。

## 增加指标或分析方法

1. 定义指标的物理/财务含义、单位、方向和适用范围；
2. 明确需要的结果字段及缺失时的状态；
3. 用可手算样例验证单个指标；
4. 定义批量或随机分析的种子、样本和失败计数规则；
5. 将输出加入版本化 contract，并保留来源引用；
6. 更新结果页解释，但不在前端重新计算同一指标。

## 失败语义

| 情况 | 处理 |
|---|---|
| 来源结果失败或不完整 | 标记该样本无效并保留原因，不用零替代 |
| 指标所需字段缺失 | 返回指标不可评估状态 |
| 样本不足 | 输出有效数、总数和证据不足状态 |
| 参数路径不存在 | 分析命令校验失败，不静默跳过 |
| 单一维度失败 | 该维度保持失败，综合结果不能改写 |

## 必须遵循的规范

- 历史分析只使用固定快照和证据；
- 指标名称、单位和方向是公开 contract；
- 随机分析显式保存种子和分布；
- 系统评估不可接受人工分数，人工评估不得冒充系统计算；
- 批量结果保留每个样本的技术结局；
- 不依赖 API、ORM、队列或前端缓存。

## 完成标准

- 指标有参考值、边界值和缺失输入测试；
- 扫描、批量和随机结果可重复，失败样本计数正确；
- 四维评估的细分状态不会被综合分数掩盖；
- 输出携带来源、版本、单位和适用范围；
- 用户界面只解释公开分析结果，不复制业务公式。

代码阅读从 analysis 公开门面和结果 contract 开始，再阅读指标、评估、扫描和批量实现；对应测试包括分析、工程环境指标和有效性测试。
