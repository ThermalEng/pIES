# 组合根与启动

> 代码边界：`backend/iesplan/bootstrap/` 与进程入口；上位规范：[架构宪法](../ARCHITECTURE_CONSTITUTION.md)

`bootstrap` 是系统唯一知晓“本次部署采用哪些具体实现”的装配层。它读取部署配置，发现并构造各模块的 Provider 与基础设施连接，完成依赖注入并汇总就绪状态（`readyz`），避免业务模块通过环境变量或隐式全局状态自行发现实现。

## 职责与边界

- **负责**：读取并严格校验进程级 TOML 部署配置；按角色（API / Worker）建立数据库、Redis 与存储连接；发现并交叉验证设备、方程、生成器、执行器、结果适配器与存储候选 Provider；按模块一次性发布各自注册表；停止时逆序释放资源。
- **不负责**：实现领域规则、读取模块私有注册表或将其合并成全局权威表、在启动时篡改业务数据。
- **用户插件边界**：组合根只注册受信任的通用沙箱 Provider 与 `plugin_runner` 客户端（`1.1.0` 目标），具体用户算法包作为不可变任务载荷随快照传递，不参与启动期发现。

## 启动与关闭流程

```text
读取并校验 TOML 部署配置
  ↓
建立数据库 / Redis / 存储连接并验证连通性
  ↓
发现各领域候选 Provider ──→ 交叉核对公开 ID、版本与依赖引用
  ↓
一次性发布各模块独立注册状态
  ↓
装配 application / API / Worker 入口 ──→ 对外暴露 readyz
```

- **数据库初始化分离**：建表、触发器部署与内置管理员播种仅由 API 服务入口在初始化阶段执行；Worker 任务子进程独立装配运行依赖，不重复执行 DDL 初始化，避免阻塞业务事务。
- **原子性与故障语义**：任一必需配置缺失、类型错误或必需 Provider 构造失败时，候选状态整体废弃并阻断启动或就绪，不清空既有状态或静默回退到静态默认实现；可选能力仅在契约明确允许时记录降级状态。
- **停机顺序**：停止接收新请求或新任务 → 等待或取消在途工作 → 释放 Provider 与底层连接池。

## 扩展与测试要求

新增 Provider 类型时，在所属领域模块定义契约与描述符，在 `bootstrap` 补充发现、配置装配与依赖校验，并将就绪状态绑定到其真实服务能力。启动与关闭测试须覆盖缺配置、缺依赖、版本冲突、部分构建失败以及测试替代 Provider 注入。
