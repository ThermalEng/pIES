# 设备目录

> 文档状态：生效蓝图；代码边界：`backend/iesplan/devices/`

## 作用

`devices` 回答“系统认识哪些设备，以及每类设备对外承诺什么”。它发布的是设备能力说明，不是设备在某个项目中的实例，也不执行计算。

设备描述是 GUI、建模、装配和配置校验共同依赖的事实源。公开文件形态固定为 [设备模型 YAML](../formats/device-model-yaml.md)。增加设备时，应扩展 descriptor/provider，而不是在前端、装配或生成器中分别增加同名判断。

## 边界

模块拥有：

- 稳定设备类型 ID、版本、名称键和分类；
- 参数类型、规范单位、范围、默认值和可优化标记；
- 真实端口、载能类型、方向和连接语义；
- 设备能力、状态、建模方法和所需时序字段；
- 设备 provider 的发现、校验和原子发布。

模块不拥有项目设备 ID、画布坐标、用户填写值、连接实例、计算配置和运行结果。设备价格或样例数据只有在成为公开设备规格的一部分时才可由 descriptor 引用，调用方不能读取目录路径。

## 输入

| 来源 | 输入 | 进入条件 |
|---|---|---|
| 内置或外部 provider | 一组 `ies.device-model` YAML 或等价候选描述 | provider ID、版本和依赖明确 |
| 单位规范 | 参数与端口单位 ID | 单位存在且量纲正确 |
| 建模能力约定 | 模型方法、命令引用、状态声明 | 引用格式稳定，可在启动时解析 |
| 数据需求 | 时序字段、分辨率和适用范围 | 字段名、单位和是否必需明确 |

无论 provider 如何发现文件，进入目录前都必须符合相同设备模型 schema；目录路径、远端服务和包入口只是实现选择，不属于其他模块可依赖的输入方式。时序样例使用[设备数据 CSV](../formats/device-data-csv.md)。

用户“模型库”的参数配置、在线 YAML 编辑和 YAML 上传都必须调用本模块同一个安全解析、校验、规范化和 descriptor 入口。用户目录和共享审批不属于 devices；但模型能否发布、是否可用于装配的语义结论必须由 devices 公开门面给出，不能由 application 或前端复制校验。

## 输出

主要输出是不可变 `DeviceDescriptor` 集合。每个描述至少保证：

- 类型 ID 和版本全局稳定；
- 参数、端口和能力 ID 在该版本内唯一；
- 所有单位、范围和枚举可以解释；
- 建模引用和数据需求结构完整；
- 不含目录路径、解析器对象或前端组件信息。

消费者按用途读取同一描述：GUI 生成通用表单和端口，modeling 生成命令，assembly 校验项目实例，application 校验用户提交。

## 初始化与发布流程

```text
发现 provider
    ↓
读取候选设备描述
    ↓
逐项校验 ID / 版本 / 参数 / 端口 / 单位 / 能力 / 引用
    ↓
校验集合内重复与依赖
    ↓
一次性发布新目录快照
```

候选集合验证完成前不能替换现有状态。正式发布前不支持运行期热加载；实例启动后的目录在本次进程生命周期内保持稳定。

## 增加一种设备

1. 按设备模型 YAML 写出可独立校验的设备说明，选择稳定、带命名空间的设备类型 ID；
2. 定义参数、单位、范围、默认值和哪些参数允许规划；
3. 定义每个真实端口的载能与方向，不使用“通用双向端口”省略建模；
4. 声明状态、时间序列和建模方法；
5. 只用稳定 ID 与精确版本引用标准建模命令，不写函数/包/模块路径；
6. 提供合法/非法 YAML、最小/典型数据 CSV 和 provider 契约测试；
7. 用目录 API、GUI schema、装配校验验证同一描述贯通，而不是修改消费者的设备类型表。

## 失败语义

| 情况 | 处理 |
|---|---|
| 设备 ID 或参数 ID 重复 | provider 注册失败，不发布候选集合 |
| 单位、范围或端口方向非法 | 给出精确配置诊断，实例不 ready |
| 建模命令引用不存在 | 启动依赖校验失败 |
| 请求未知设备类型 | 明确“未注册”错误，不返回默认设备 |
| provider 读取失败 | 保留失败原因，不回退静态内置表 |

## 必须遵循的规范

- 外部模块只调用设备公开门面；
- descriptor 不携带项目状态或可变运行对象；
- 设备文件遵守 `ies.device-model`，未知核心字段和可执行入口拒绝；
- 名称和说明使用消息键，领域 ID 不随语言变化；
- 默认值是设备契约的一部分，必须有单位和适用条件；
- 破坏性参数或端口变化提升设备规格主版本；
- 历史任务必须能够解析其固定的设备版本。

## 完成标准

- provider 的成功、重复、缺依赖和半失败均有协议测试；
- 新设备无需修改前端端口规则、assembly 类型表或全局注册表；
- 目录快照确定、排序稳定、可序列化且保留设备模型摘要；
- GUI、建模和装配消费的是同一公开描述；
- 当前未交付的设备只进入 Roadmap，不出现在正式使用者指南。

代码阅读从 `devices` 公开门面和 descriptor 类型开始，再进入 provider、加载与模块私有注册实现；对应测试以设备目录和初始化测试为入口。
