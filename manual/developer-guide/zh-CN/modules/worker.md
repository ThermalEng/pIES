# Worker

> 代码边界：`backend/iesplan/worker/`；上位规范：[架构宪法](../ARCHITECTURE_CONSTITUTION.md)

`worker` 是执行长时后台作业（全周期规划计算、敏感性/批量分析、项目包与大型报表导出）的常驻守护进程，确保任务在并发领取、进程中断、超时、取消及迟到写入等场景下依然保持单次有效提交与完整证据可追溯。

## 职责与边界

- **拥有**：任务队列发现与原子领取；Attempt 租约持有、Fencing Token 校验与管理员解锁恢复；隔离任务子进程控制与停止信号传递；计算任务各阶段编排（物化 → 生成 → 运行 → 适配 → 财务评价）与阶段检查点恢复。
- **不拥有**：修改项目草稿或回读未冻结配置；拼接求解器 Shell 命令或解释装配设备语义；直接操作数据库连接提交事务（所有持久化读写均经 `application.worker` 短事务命令完成）。
- **算法插件载荷边界（`1.1.0` 目标）**：用户算法插件通过通用沙箱 Provider 转交独立容器 `plugin_runner` 执行，Worker 进程本身不解压或 `import` 用户源码。

## 执行状态机与进程隔离

```text
队列提示 / 数据库待排队扫描
  ↓ 原子领取（分配 Attempt + Lease + Fencing Token）
控制进程（负责领取任务、发布心跳、停止监听与监督任务进程）
  │
  └─ 启动独立任务子进程（经组合根装配依赖，无锁加载 CalcSnapshot）
       ↓ [阶段 1] prediction：序列预测物化 ──→ 提交 prediction 检查点
       ↓ [阶段 2] generated：GeneratorProvider 生成 Bundle ──→ 提交 generated 检查点
       ↓ [阶段 3] execution：SolverRuntime 隔离执行 ──→ 提交 execution 检查点后清理临时区
       ↓ [阶段 4] ResultAdapter 适配 + 财务评价
       ↓ 核验租约仍有效（Fencing）
       └─ 原子发布 Evidence、查询投影与任务终态
```

- **控制面与执行面分离**：每个 Attempt 在独立解释器子进程中运行，控制进程负责领取任务、发布心跳与监督任务进程；心跳缺失不改变任务领取状态和槽位，控制面短时不可用时求解继续执行。阶段交接在写盘前无锁探测数据库，断连时退避重试并限频告警，数据库恢复后由当前尝试凭原 Token 发布检查点、结果或原始失败诊断。
- **取消、退出与资源耗尽处置**：用户主动取消、管理员撤销与部署超时通过独立停止通道传递；任务进程异常退出时监督进程记录退出码及最后阶段并收拢尝试与槽位。明确检出 `MemoryError` 或同 cgroup OOM 计数上升的进程终止收口为资源耗尽失败并释放槽位，不自动在相同资源下机械重跑。任务 detail 中展示的 `worker_resources` 反映当前部署容器的 cgroup v2 观测事实，不作为单任务独享配额承诺。

## 阶段检查点与恢复

- **阶段检查点（`ies.worker-checkpoint@1.0.0`）**：`prediction`、`generated` 与 `execution` 产物按阶段经 `storage` 持久化并登记尝试 Owner 引用（写盘期间不持有租约行锁，写入元数据与引用前再锁定核对写入资格）。发生中断并重试后，新建 Attempt 凭新 Token 从已提交检查点恢复：已有 `execution` 产物则直接恢复结果适配，已有 `generated` 产物则跳过构模重跑求解，缺少检查点时按原快照重新执行（不支持恢复求解器内部搜索树）。检查点对象实际丢失或不可读时直接报错，不静默重算或退回草稿。
- **管理员解锁与恢复**：整机停止等导致活动尝试遗留占槽时，由管理员在短事务内解锁以撤销旧 Token、结束旧尝试并释放槽位，随后按原快照重新排队；每次新领取产生新 Attempt 与新 Token，旧 Token 迟到写回一律拒绝。
- **轻量化结果索引**：证据发布同事务建立可重建的 `evidence_projection` 索引，供结果页摘要、财务面板与分窗逐时读取使用；升级后可通过运维命令 `docker compose exec backend python -m iesplan.cli.index_result --evidence-package-id <id>` 为历史大证据补建索引。

## 新增任务类型规范

1. 明确任务输入快照、结果契约、幂等键作用域与资源池归属（`compute` 或 `io`）；
2. 在 `application.worker` 注册短事务状态推进与阶段执行命令；
3. 为长时步骤接入取消与租约 Fencing 检查点；
4. 在 Docker 环境下补齐正常提交、重复消息、取消、超时、进程退出、控制面中断与重试恢复测试。
