# 领域模型与追溯链

> 文档状态：生效蓝图；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)

## 数据生命周期分类

pIES 将全部业务数据按可变性与权威性分为三类：

| 类别 | 典型实体 | 生命周期规则 |
|---|---|---|
| 可编辑工作状态 | 项目草稿、未提交表单 | 允许编辑，每次持久化生成新修订号（`revision`）并受乐观锁保护 |
| 不可变业务证据 | 项目版本、数据集版本、计算快照、执行回执、计算结果、评估记录 | 仅追加、不可原地修改；支持完整历史追溯 |
| 可重建运行状态 | Redis 队列提示、秒级进度、缓存、查询索引投影 | 丢失或损坏后可从权威数据库或原始证据重建 |

PostgreSQL 保存所有结构化事务事实与引用索引；大型不可变文件内容交由对象存储管理，业务表仅持有不透明对象标识（`ObjectId`）和归属引用。

## 项目与工作区聚合

项目承载所有者、币种、不可变计算基线与生命周期状态（进行中 / 已归档）。

- **不可变计算基线**：创建项目时一次性固定时间分辨率、场景模式（当前为 `single`）和运行起始公历年（闰年按公历逐年推导，无独立闰年配置），之后不允许原地修改。
- **草稿与版本**：项目草稿保存当前正在编辑的系统图、数据绑定、财务配置引用、规划配置与模型清单；自动保存仅更新草稿修订，不会产生项目版本。项目版本是对草稿在特定时刻的显式不可变固化；恢复历史版本会派生新版本并将草稿同步回该版本状态，已有的版本与计算任务保持不变。
- **项目模型目录**：项目模型须先通过后端完整的 YAML 安全子集、单位、接口与方程校验，再以原子事务分配项目内唯一编号并写入目录；校验失败的候选内容不会进入正式目录或消耗编号。
- **任务载入草稿**：切换或载入某个历史任务时，将其冻结快照的输入恢复到当前可编辑草稿，不会自动创建新任务；只有用户主动发起计算时才会冻结当前草稿生成新任务。
- **项目包导入**：导入离线项目包（`.zip`）会创建独立的新项目并由导入者拥有。上传阶段完成结构解析并生成暂存提案，只有用户明确确认导入后才在同一数据库事务中重建模型、数据集、历史版本与依赖映射，历史结果以证据来源保留，不伪造本地计算任务。

## 数据集与序列来源

数据集容器管理多次上传形成的不可变数据版本。每个版本记录原始采样间隔、字段定义、单位、质量诊断和对象引用。

设备预定义接口的外部数据绑定在项目装配实例的 `predefined_interfaces` 中显式声明，支持 `constant`、`data_repeat`、`data_full` 与 `data_predict` 四种来源模式。系统在导入和装配边界严格校验分辨率、连续 `step` 递增、有效值域与模式覆盖规则，不在预处理中隐式重采样或插值修补。全周期对齐序列在计算阶段按项目基线与确认运营年限物化生成。

## 规划、财务与计算配置

三类配置各司其职且均按版本化修订管理：

- **规划配置**：声明目标函数、规划变量（绑定实例技术参数与上下界）、建设单元及规划/系统约束。存量设备（`existing`）的历史投入按沉没成本处理，不计入新增建设投资；新增设备（`new`）按显式绑定计费。
- **财务三件套**：地区 `FinanceProfile`（可复用地区基准）、项目 `FinanceOverrides`（对 Profile 已有项做稀疏原子覆盖）与确定性合并生成的不可变 `EffectiveFinanceConfig`。装配、规划与财务评价消费同一 `EffectiveFinanceConfig` 快照，不在运行期动态继承外部价格。
- **计算配置**：定义计算模式、单趟前置预测列表 `predictions[]`、分槽或一体化求解插件引用、精度、时间限制、分槽运行选项、随机种子、`outputs` 与并联后置评价器 `evaluators[]`。计算配置不进入装配产物，而是在提交计算时与规范装配共同冻结进计算快照。

## 模型、算法插件与市场制品（`1.2.0` 已交付）

`1.2.0` 的模型与算法生态采用“可编辑草稿 + 单当前生效版本不可变发布/安装”模型：

- 设备模型通过表单、在线编辑或导入最终收敛为同一 `ies.device-model` YAML 规范对象，按 `(kind, stable_id)` 唯一维护当前生效 `revision`，不单独声明设备语义版本；跨实例市场/导入制品保留原稳定命名空间 ID，个人自建草稿使用随机 `public_namespace`；
- 算法插件通过独立隔离运行器校验与执行，API 与普通 Worker 进程不加载用户源码；已安装插件按 `(kind, stable_id)` 唯一维护当前生效版本与受管镜像，无需重启即可在后续计算配置中被选用（覆盖升级前先校验无在途 `CalcSnapshot` 引用，不建设跨版本兼容层）；
- 本地管理员可在“本地模式”（关闭远端市场）与“联网模式”（浏览、下载安装与邮箱验证投稿）之间切换，并独立配置非管理员本地上传审批开关；安装、停用或卸载只影响后续新发起的计算，提交时一次性冻结进 `CalcSnapshot`（仅外部下载/导入边界校验 SHA-256，内部持久化与快照不存储或复核摘要），不破坏在途或历史任务追溯。

## 快照、任务与结果追溯链

```text
项目版本 + 数据版本 + 规划/财务/计算配置修订
                    ↓
          ValidatedAssemblyArtifact
                    ↓
               CalcSnapshot
                    ↓
              Task → Attempt
                    ↓
       单趟预测 → 物化输入 → 核心求解 → 工程解还原
                    ↓
             并联后置评价器 evaluators[]
                    ↓
        Evidence / Assessment / Export
```

- **不可变快照**：`CalcSnapshot` 在提交时固化规范装配产物、装配校验回执、按实例冻结的设备数学贡献、三类配置修订、预测与求解依赖版本、评价确认与比较基准。任务执行与重试只读取快照，不受后续草稿修改影响。
- **技术状态与业务结局分离**：任务执行完成（`completed`）仅代表运行结束；业务上可能产出最优方案、受限可行解（如超时但有可行解），或无可行方案 / 证据不足。
- **结果选择与应用方案**：选择结果仅标记当前任务下的采纳偏好；**应用方案**则是显式版本操作——以该任务快照所来源的项目版本为基线，写入求解得到的规划变量参数，派生一个新项目版本并设为当前工作区。执行前须向用户展示影响范围并确认，历史证据与来源版本保持不可变。

## 对象生命周期

- 所有大文件通过 `storage` 写入不可变对象，业务模块只持有 `ObjectId` 和明确归属的 `ObjectOwner` 引用。
- 创建、替换或发布资产时同步建立/解除引用；只要仍有有效引用，对象禁止清理。
- 管理员可通过清理预览列出无引用对象；执行清理时，直接删除仍无引用且满足业务保留规则的文件与元数据。

## 身份、权限与审计

- 认证与权限判定完全由后端执行，前端视图控制仅作交互引导。系统区分项目所有者（普通工程师）与受信任运维管理员（负责账号、存储与全局运维审计）。
- 同一账号支持多个独立有效会话：退出只撤销当前会话，改密或管理员停用会统一失效旧会话。会话有效期为空闲期限，可见页面的真实操作通过认证续期端点顺延（后台任务不因会话到期而取消）；已过期、已撤销或凭证版本已变化的会话须重新登录。
- 关键业务操作（权限变更、对象清理、项目与配置发布、版本恢复、系统评估等）生成不可变的脱敏审计日志，记录操作者、操作类型、目标对象和追溯 ID，不保存密码、令牌或大对象正文。管理员可通过只读游标接口分页检索审计记录。

## 建模与设计参考

新增业务数据时，按以下准则决定其存储与版本形态：

1. **需要反复编辑**：设计草稿表与 `revision` 乐观锁；
2. **被任务、审批或外部引用**：必须形成不可变版本并禁止更新；
3. **体积较大或属于文件流**：字节交由对象存储管理，数据库只存 `ObjectHandle`；
4. **丢失可从数据库重算**：归入可重建缓存或投影索引，不作为唯一权威源。
