# 网络边界与系统方程

> 所有者：assembly（边界与引用）、modeling（方程）；上位规范：[架构宪法](../ARCHITECTURE_CONSTITUTION.md)。
> 状态：目标契约，新增部分尚未交付；标记沿用 `ies.assembly@1.0.0`，不增加网络文件类型或版本分支。
> 本页是装配 `system_equations` 及未连接端口边界的唯一字段级正文；理想连接字段仍见[装配 YAML](assembly-yaml.md#连接)。实现顺序与完成状态只见 Roadmap。

## 适用范围

外部连接、设备内部转换、源汇边界、能量分配和来源记账是不同关系。公共母线仍按真实端口的理想连接分区；受限传输用设备 YAML 的内部方程表达，跨实例的分配与来源关系用本页的系统方程表达。两者共用现有变量、方程语言、单位边界及来源链，不建立另一套网络求解器或来源白名单。

系统方程是通用技术关系，不拥有价格、税额或财务目标；费用使用其辅助量时按[金额引用](finance-relations.md#通用金额定义-amounts)的system_quantity声明，而非从结果文件回流或在技术方程混入价格。没有来源记账声明时，结果只能解释端口净交换，不能声称已识别能量来源。

## 完整网络边界

| 对象 | 精确含义 |
| --- | --- |
| 参与 `connections` 的 `in/out/bidirectional` | 在其理想端口分区中各计一次，按实际运营步守恒；同设备不自动合并 |
| 未参与任何连接的 `in/out/bidirectional` | 独立关闭边界，每一步该端口流量等于零；不自动连接其他端口，不成为免费供给或未计量排放 |
| `predefined` | 保持外生数据槽及已声明来源，不参与网络平衡，不因未连线置零 |
| `blind`、内部方程变量 | 保持模型内部语义，不因未连线置零，也不能当成外部可连接口 |

关闭边界是数学关系，不是“悬空即非法”的输入规则。零流量与设备方程冲突时，由实际关系分析或求解结果解释，不能先按设备类别猜不可行。关闭行保留实例、接口、实际步和 `devices.<instance>` 来源位置；不能通过收紧求解列而丢失这条原始关系。

外部供给、购入、排放或外送应由一个**显式源／汇模型**承接：它的连接端口与系统连接，供给能力、计量及必要限制在其技术文档声明，财务交易单独绑定。例如燃料输入连接燃料源，不保留“未连线燃料口自动取能”的旁路；环境驱动数据继续用 predefined。没有设备名、载体名或目录型号豁免。

有符号端口按其模型约定参与守恒：out 为向母线供给，in 为从母线吸收，bidirectional 的正值为供给、负值为吸收。若模型为 in/out 声明了带符号域，仍按原方程解释；需要非负分配时由模型显式建立相应的非负量，不能私自取绝对值。

关闭边界不等于来源防逆流：已连接的共同母线仍会混合能量。已有冻结对象不回写；采用新边界重新计算时，用户显式补齐真正的外部源汇或调整模型，程序不自动补边。

## `system_equations` 字段

装配顶层增加可选 `system_equations` 映射；省略等价于 `{}`。每个键是独立系统方程块的稳定 `lower_snake_case` ID。块只接受下表字段；空内容显式写 `{}` 或 `[]`。

| 字段 | 类型与规则 |
| --- | --- |
| `constants` | 名称到 `{value, unit}` 的映射；value 为有限数值，unit 显式。它们是本块的已知技术系数，不是价格或待优化规模 |
| `references` | 名称到以下判别联合的映射；只绑定已有模型事实，不声明新的端口或复制求解变量 |
| `variables` | 名称到 `{unit, valid_range, initial?}` 的映射；均为完整运营时域上的辅助序列变量，不是新设备或新的规划规模 |
| `relations` | 有序 `[{id, expression}]`；id 在块内唯一，expression 复用设备方程的公开 AST、运算、单位与时间规则 |

引用恰选一种：

| `kind` | 完整结构 |
| --- | --- |
| `interface` | `{kind: interface, instance, interface}`，引用该实例真实 interface；predefined 为同次物化输入，其余为原模型变量 |
| `property` | `{kind: property, instance, property}`，引用实际实例属性；由规划接管时绑定原规划变量，而非模板 value |
| `variable` | `{kind: variable, instance, variable}`，引用该实例 `equations.variables` 的公开声明身份；不得填求解列名或私有生成器变量 |

常数、引用和变量的局部名称互不重名，不得占用 `step_duration`。不同块的同名变量互相独立；块之间不互相读内部变量。共同关系应在同一块声明，避免建立第二套跨块引用规则。已有 `planning.constraints.step_relation` 继续表达不需要局部变量的简单关系；两处声明的关系均生效，不互相覆盖。

`valid_range` 复用设备变量的数值／null／`{property_ref: name}` 边界形态；这里 name 必须是本块的同量纲常数或 property 引用。null 表示未知侧，不是大数。`initial` 复用 `{property_ref: name}` 或 `{expression: ...}`，只引用本块常数及 property 引用，不引用序列、其他状态或 step_duration。

表达式中 property 引用和常数是标量，interface／variable 引用及本块变量按 `[t]` 使用。`[t-1]` 只用于本块具有 initial 的状态变量；在首步替换为该初值，其后引用同一完整时间轴的前一步。引用设备状态的跨步递推由其设备方程拥有，不在本块隐式再建初值。只允许当前步及一阶过去；不增加年末重置、周期闭合、终期 SOC 或参考规模。

方程中的裸数字按现有技术方程 SI 语义解释；带物理单位的常数在 constants 声明，不能另造一套公式语法。变量乘变量与非负互斥的能力区别沿用 modeling/GeneratorProvider，不能把来源混合比例等双线性关系冒充仿射关系。

## 分配与来源的建模责任

定向分配使用模型声明的非负辅助量，例如 `a[t]`，并用完整方程同时连接真实端口的供给与吸收总量。下表是语义关系，不是额外 schema 字段：

| 关系 | 必须明确的内容 |
| --- | --- |
| 供给分配 | 每个来源端口输出等于该来源分配给各去向的量之和 |
| 去向分配 | 每个负荷、充电或外送端口吸收等于各来源分配量之和 |
| 限制直接外送 | 被限制来源的外送分配明确为零，或其供给分解不包含外送分支；不能只遗漏一条公共母线连接 |
| 有符号交换 | 需要分开收发时显式定义非负收发量、净值关系及必要互斥；不能使两者任意同时增大形成虚构分配 |
| 跨载体传输 | 原技术转换方程仍约束实际端口；来源账户也必须使用相同的显式效率和单位关系 |
| 储存来源 | 为每个需要追踪的来源声明能量账户、初值、充放量及损耗；账户之和与物理储能状态、总充放量显式相等 |

平台负责引用、量纲、索引与已声明关系的执行，不猜用户尚未写出的守恒方程，也不把一组合法公式认证为完整防逆流政策。分配是可行的簿记分配，不自动表示唯一物理来源。若要求按完全混合比例放电，须明确相应关系及非线性能力，不能让适配器在解后按比例重分配。

### 完整方程块示例

以下是嵌入装配的完整块，不是独立文件。上下文必须已有实例 s、l，其 `power_out`／`power_in` 为相容的 kW 端口；公共母线连接另在 connections 声明。本例把供给与需求都完全记入同一个分配量，不创建新物理通道：

```yaml
system_equations:
  delivery_account:
    constants: {}
    references:
      supply: {kind: interface, instance: s, interface: power_out}
      demand: {kind: interface, instance: l, interface: power_in}
    variables:
      delivered:
        unit: kW
        valid_range: {minimum: 0, maximum: null}
    relations:
      - {id: source_total, expression: "supply[t] = delivered[t]"}
      - {id: sink_total, expression: "demand[t] = delivered[t]"}
```

多源分配时，供给和去向分别按总量守恒；不能对每条分配边都写“供给端口总量＝需求端口总量”。来源账户的状态公式沿用 `E_i[t] = E_i[t-1] + (eta_c * C_i[t] - D_i[t] / eta_d) * step_duration`，并显式声明 `sum(E_i)=E_actual`、`sum(C_i)=C_actual`、`sum(D_i)=D_actual` 及每个初值。这里的 sum 只是关系说明，文件中展开有限项加法，不新增求和函数。

原来源供给4、负荷4时，新增来源供负荷后原来源外送4，可以满足“新增来源无直接外送分配”。若要求外送不得因新增方案增加，需另写策略及必要的独立基准；平台不会把两种要求混同。

## 保存、冻结与公开输出

完整装配文档保存、草稿修订、项目包当前／历史内容、规范化和任务冻结均保留本块，不按画布字段白名单裁剪。系统方程不进入共享设备文件，不改变设备黑盒的内部事实所有者。输入边界校验一次；内部传递消费类型化关系，不重复解析或做摘要复核。

辅助变量的公开输出选择为 `outputs.system_series: [{block, variable}]`，省略等价于 `[]`；每项必须引用本块真实变量，不接受求解列名。原 `outputs.series` 的设备序列形态不变。所选生成器必须同时支持辅助声明、引用、状态和结果恢复，不能只接受表达式而忽略变量或输出。

Bundle／适配器的输出身份与结构以[系统序列映射](solver-bundle.md#系统序列映射)为准。来源映射保留 `system_equations.<block>`、relation ID、变量 ID、被引用实例及实际 step；关闭端口关系保留端口来源。生成器统一汇集这些原关系后再做界分析与降级，不新增求解前验证器；Runtime 不解释网络。

## 输入、转换和求解失败

| 情形 | 分类与最小定位 |
| --- | --- |
| 未知字段、重名、引用不存在、量纲／索引错误 | 用户输入错误；块、字段路径、relation/variable ID，已有行列时保留 |
| 原关系合法但所选生成器不支持状态或表达形式 | 能力不足；具体关系和所需能力，不静默忽略 |
| 精确转换需要某侧有限界而统一分析未取得 | 转换条件不足；表达式、缺失侧、实际步及来源，不改称无界 |
| 关闭边界或已声明分配使完整问题不可行 | 原关系进入求解器；不为求通过补边、删守恒、填参考上界或加终期状态 |

能力以关系类别声明：`network.closed_ports`、`modeling.system_equations`、`outputs.system_series`。提交只核对实际使用的能力；不按 provider 名称或版本数字猜支持。关闭边界是当前网络语义，存在未连接可连接端口的任务必须由支持该语义的生成器承接。
