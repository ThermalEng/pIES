# 设备数据 CSV

> 契约标识：`ies.device-data`；目标 schema：`2.0.0`；推荐文件名：`<dataset-id>.data.csv`。
> 文档状态：生效目标契约；本页只定义目标文件语义，不声明实现进度。

设备数据 CSV 用于人工准备或工具导出的序列输入。它把“这一列是什么、使用什么单位、一个 step 代表多长间隔”写进文件本身。用户必须在导入前处理好数据的准确性、完整性和对齐关系；系统在装配前只校验，不重采样、插值、聚合、融合或自动补齐。全周期序列只在计算阶段生成。

## 文件结构示例

下例只节选数据行以展示结构，不是可通过校验的完整文件。正式文件必须包含其来源语义所需的完整数据行。

```csv
# schema: ies.device-data
# schema_version: 2.0.0
# dataset_id: campus_electric_load_2025
# device_id: acme.device.electric_load
# source_mode: data_predict
# resolution: 1h
# unit.electric_demand: kW
step,electric_demand
0,48.3
1,46.7
2,45.9
```

## 文件结构

文件依次由三部分组成：

1. 以 `# ` 开头的元数据行；
2. 一行 CSV 表头；
3. 零行或多行数据。正式数据集至少一行，空文件只能用于非法样例测试。

元数据只能出现在表头之前，每个键只能出现一次。注释若不属于标准元数据，使用 `# note.<name>:`；数据区不允许穿插注释。

## 必需元数据

| 键 | 含义 |
|---|---|
| `schema` | 固定为 `ies.device-data` |
| `schema_version` | 文件契约版本 |
| `dataset_id` | 稳定数据集 ID，不等同于文件名 |
| `device_id` | 稳定设备 ID，不含设备独立版本；与 `schema` 字头共同决定允许绑定的 `predefined` interfaces |
| `source_mode` | 原始输入只能为 `data_repeat` 或 `data_predict`；`constant` 在装配绑定中直接给值，没有 CSV |
| `resolution` | 该文件每个 step 的采样间隔，例如 `15min`、`30min`、`1h`；必须与项目基线一致 |
| `unit.<column>` | 每个数值数据列的单位，必须与设备模型一致 |

`source_mode: data_repeat` 不另设 `period` 元数据；文件中的完整连续序列整体就是重复基线，可以是完整日、完整周或完整年。计算阶段从 `step=0` 循环使用该基线，达到项目基线点数时结束。

`source_mode: data_predict` 的预测目标类型以项目装配 `predefined_interfaces.<interface_id>.target_type` 为唯一权威，CSV 不重复声明。目标类型按计算公开契约规定允许的时间特征、自回归特征和外生协变量；数据绑定必须提供该类型要求的输入，不由预测器根据列名猜测。

CSV 元数据不能自行决定项目来源绑定。校验器必须同时消费已经过装配结构校验的显式绑定上下文，并精确核对 interface ID、`mode`、`data_ref`；`data_predict` 还要核对 `target_type`。缺少绑定、绑定模式与 `source_mode` 不一致、`data_ref` 不是当前固定数据资源身份，或出现属于其他模式的字段时均阻断。

## CSV 方言

- UTF-8；规范文件无 BOM，使用 LF；
- 分隔符固定为英文逗号；字符串按 RFC 4180 双引号规则转义；
- 小数点固定为 `.`，禁止千位分隔符；
- 布尔值只写 `true` 或 `false`；
- 数据字段不允许缺失值；空字段必须阻断；
- 禁止 `NaN`、`Inf`、`Infinity`、公式和区域化数字；
- 单元格以 `= + - @` 开始的文本在导出电子表格时必须防公式注入；输入解析器不得执行公式。

## 表头与列

第一列固定为 `step`。原始文件的 step 必须从 `0` 开始严格连续递增，不得缺口、重复或倒退。后续列 ID 必须与所固定设备内容中 `type: predefined` 的 interface ID 完全一致：

- 未声明的列拒绝；
- 重复列拒绝；
- 当前装配绑定要求的列缺失时拒绝；单个绑定文件不要求包含同一设备的其他 `predefined` 槽；
- 规范输出按设备模型中的 interface 声明顺序排列；
- 一份文件只绑定一个稳定设备 ID；不能用当前同 ID 内容解释旧数据。

每个 `unit.<column>` 必须与设备模型声明的量纲兼容。`kW` 与 `W` 可以在生成器边界显式换算，但 `kW` 与 `kWh` 不兼容，不能仅因都是数字而接受。

## 来源覆盖与计算序列对齐

原始输入序列不设统一的完整年度最低长度。每个来源必须：

- 与项目基线使用完全相同的 `resolution`；
- 在本文件内从 `step=0` 开始连续递增；
- 每个 step 都有有限数值，不存在缺失或占位值。

不同来源在计算阶段物化前不要求点数相同，也不要求原始 `step` 一一对应。任一来源自身不满足上述要求时，装配必须阻断并指出文件、列和 step。系统不尝试使用插值、聚合或融合修补来源；用户修正原始数据后必须形成新的数据版本。

`constant` 没有原始序列文件，在计算阶段按项目基线展开。`data_repeat` 接受完整日、周或年序列，并把文件中的完整连续序列整体作为重复基线；周期由序列本身表达，不另设 `period` 字段。

`data_predict` 在计算阶段生成。其目标类型决定可用的时间、自回归和外生协变量，具体算法和参数由 `CalculationConfig` 选择。训练目标、历史输入和未来已知协变量必须显式绑定，不得由列名或数值形态隐式猜测。

处理流程：

1. 校验训练输入、训练目标与预测输入；
2. 按计算配置选定的算法及精确版本训练，得到不可变训练模型产物；
3. 按项目基线生成全周期预测值；
4. 输出连续 `step` 计算序列、训练产物引用和训练/预测回执。

回执至少固定预测目标类型、算法 ID/版本及参数、特征/目标顺序、训练输入/目标引用、未来协变量引用、训练产物引用、随机种子和输出序列引用。学习得到的参数属于训练产物，不写入设备模型。相同规范输入、计算配置、固定依赖版本和项目基线必须生成可复现的训练产物、预测序列和回执；可信内部流程按既有引用交接，不重算或比对 hash。

计算阶段物化的 `constant`、`data_repeat` 和 `data_predict` 计算序列共同满足：

- `resolution` 与项目基线一致；
- `step` 从 `0` 开始连续递增且无重复；
- `point_count` 与普通年/闰年基线推导值一致；
- 每个值通过有限性、单位、有效区间和缺失策略校验；
- 原始来源、变换/训练回执、计算序列和项目基线之间的引用关系完整且可追溯。

日、周或年重复基线只是 `data_repeat` 的来源语义，不改变项目计算基线；计算结果仍使用项目基线推导的完整时间轴。

## 数值和质量

每个值先按目标 interface 的单位、`valid_range` 和有限性校验，再参与装配：

- 超范围值是阻断错误，不自动截断；
- 任一缺值都阻断装配；系统不用前值、零值或插值补齐；
- 用户在导入前做过任何清洗、插值、聚合或融合时，导入的结果作为新的原始数据版本，由用户对其准确性负责；
- 上传边界固定对象身份；同一可信本地流程不再次校验；
- 质量 warning 可以由用户确认，但不能替代阻断错误。

数据导入不得静默删除坏行、按零补齐、使用前一值填充或把解析失败变成空数据集。

## 校验与规范输出

校验器按以下顺序处理：

1. 识别编码、换行、元数据和固定 CSV 方言；
2. 解析 schema、设备 ID、来源模式、分辨率和单位；
3. 要求装配显式绑定上下文，精确核对 interface ID、mode、data_ref 和按需出现的 target_type；
4. 按 `device_id` 读取设备内容，并核对被绑定的 predefined interface、单位和有效区间；
5. 校验分辨率与项目基线一致、`step` 从零开始连续，并校验对应来源模式的覆盖要求；`data_repeat` 接受完整日、周或年序列；
6. 在项目装配时确认所有来源均可按其声明模式物化；原始来源间不校验点数相等，计算阶段物化后再统一点数和 `step`；
7. 生成边界所需的内容身份、质量结果和校验记录；全周期展开或预测由计算阶段另行完成。

装配 YAML 通过 `data_ref` 固定数据资源身份，不直接依赖上传文件名，也不另设列映射；绑定的 interface ID 必须与 CSV 表头中的同名列一致。文件更改后形成新数据版本，不能覆盖历史任务所引用的内容。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| step 缺口、重复或倒退 | 阻断并定位行，由用户修复原始序列 |
| `data_repeat` 不是完整日、周或年序列 | 阻断，由用户补齐该重复基线后重新导入 |
| 文件分辨率与项目不同 | 阻断，由用户在导入前转换 |
| 不同原始来源点数不同 | 合法；计算阶段按各自模式物化后统一对齐 |
| `electric_demand` 写成 `kWh` | 与设备模型核对量纲，不能靠换算放行 |
| 少一小时后自动补零 | 阻断并定位缺口，修复源文件或建立有记录的新版本 |
| CSV 中新增“备注”数据列 | 移到 `note.*` 元数据或由新 schema 明确声明 |
| 使用当前文件名作为身份 | 使用 `dataset_id`，文件名仅供人识别 |

## 完成标准

- 完整文件可以用普通文本编辑器编写并通过 `2.0.0` 校验；
- 日/周/年重复基线、分辨率一致、物化后点数/step 对齐、常量展开、目标类型预测、缺口和非法值均有契约测试；
- 同一语义输入得到相同规范文本；
- 数据来源和最终绑定可追溯；
- 装配、求解器和技术方程转换器不直接读取未经校验的原始 CSV。
