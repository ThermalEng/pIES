# 规范索引与文档边界

> 文档状态：生效；适用范围：正式产品文档、内部实施记录、Review 与历史归档。

本页明确各类文档的定位与唯一权威正文归属，避免相同规则在多处重复定义并产生漂移。

## 文档角色分工

| 目录 / 文档 | 权威内容 | 不包含的内容 |
|---|---|---|
| [架构宪法](ARCHITECTURE_CONSTITUTION.md) | 全局原则、模块边界与冲突裁决顺序 | 版本计划、任务切片、开发进度 |
| 开发者指南其余章节 | 长期架构设计、公共契约、文件格式与扩展方式 | 实施过程、Roadmap、当前完成度 |
| [使用者指南](../../user-guide/zh-CN/README.md) | 当前 GUI 可直接完成的操作流程与限制 | 后端实现、内部术语、未上线能力 |
| [`manual/changelog/`](../../changelog/README.md) | 已验收变更历史与版本开发计划（Roadmap） | 长期架构与格式规范 |
| `docs/development/` | 临时的实施交接与过程控制 | 长期公共契约与架构规则 |
| `docs/reviews/` | 带基线的代码/架构审查快照 | 现行实现规格 |
| `docs/archive/` | 已替代或废弃的历史材料 | 任何现行开发依据 |

## 唯一正文与引用原则

1. 每项稳定规范只在一处权威正文完整定义；其余文档只说明上下文并链接到该正文的对应章节，不重复粘贴完整的字段表、参数列表或计算公式。
2. 具体 HTTP 字段表以运行版本的 OpenAPI/Schema 为准，文档不人工维护第二份接口字段副本。
3. 专项跨文件契约归属：
   - 领域语义总览见[架构蓝图](architecture.md#领域语义与数学表达)；
   - 网络边界与 `system_equations` 见[网络边界与系统方程](formats/network-relations.md)；
   - 命名成本明细、金额、收付、资产与派生税见[命名金额、支付与资产](formats/finance-relations.md)；
   - 评价对比与冻结基准输入见[公共契约](contracts.md#评价范围与冻结基准)；
   - 求解声明、序列与财务事实映射见[Solver Bundle](formats/solver-bundle.md)；
   - 通用前置启发式缩域、两级漏斗热启动与最优性界校验见[计算生成与求解](modules/engines.md#通用前置启发式加速与两级漏斗协同)。
4. 规范变更时先更新权威正文，再核对引用处的链接和描述是否一致。

## 归档机制

凡属于以下情形的过程文档，应及时移入 `docs/archive/`，并在顶部标注状态、归档日期、归档原因与现行替代来源：

- 已完成或已被取代的实施计划、交接说明、调研报告或旧规格；
- 与现行架构宪法、开发者指南或 Roadmap 冲突的历史文档；
- 仅反映早期代码基线的审查材料。

归档文件保留历史原文，不将其作为现行规范反复改写；移动或删除文档时须同步修复现行文档、代码注释及测试中的引用链接。
