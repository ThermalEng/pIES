# 模型与算法扩展指南

> 文档状态：生效目标指南；目标产品版本：`1.1.0`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)；相关格式：[设备模型 YAML](formats/device-model-yaml.md)、[算法插件包](formats/algorithm-plugin-package.md)

## 这项能力解决什么问题

pIES 允许用户建立自己的设备模型和算法能力，并在项目中像使用系统内置内容一样选择经过校验的不可变内容。一级导航“模型与算法”包含：

- **模型库**：管理当前用户创建或安装的设备模型；
- **算法插件**：管理当前用户上传或安装的加工与求解插件；
- **共享园地**：浏览经管理员批准公开的模型与插件，并安装到自己的目录。

本章面向模型作者、算法插件作者和集成开发者，规定可依赖的文件、版本、选择和共享行为。页面内部状态、数据库、接口路径、容器编排和任务切片不属于本章的公共承诺。

## 共同原则

模型和算法插件都以文件为交付事实源：模型使用 `ies.device-model` YAML，算法使用 `ies.algorithm-plugin` ZIP。网页编辑器只是生成或修改这些文件的工具，不产生另一套只能由当前页面解释的格式。

每个可用内容都必须具有：

- 稳定的命名空间 ID；
- 文件 schema 与 schema 版本；
- SHA-256 内容摘要；
- 依赖、兼容能力和许可证；
- 可复核的校验结果。

设备模型不声明独立语义版本，项目和计算任务固定稳定 ID、发布 revision、schema 版本和内容摘要，不引用显示名称、文件名、列表位置或 `latest`。算法插件仍使用精确语义版本。已经发布的内容不可原地替换；修改设备模型形成新的不可变 revision 和摘要，修改算法插件发布新版本。

## 编写设备模型

### 三种入口

模型库提供三种等价入口：

1. **结构化表单**：通过网页表单填写设备身份、非时变技术 properties、序列 interfaces 和声明式 equations；
2. **在线 YAML**：直接编辑完整的设备模型 YAML；
3. **上传 YAML**：上传符合规范的 `*.device.yaml` 文件。

无论从哪个入口开始，最终保存和发布的结果都是同一份 `ies.device-model` YAML。表单与 YAML 之间不能无提示地丢弃字段；无法转换或校验失败时必须保留编辑内容并显示诊断，但不得把非法候选保存到项目正式模型目录。

### 校验后保存

模板实例化结果、表单结果和直接编辑结果都先作为候选模型提交后端。后端必须在项目正式落盘前完成安全 YAML、schema、字段类型、properties、五类 interfaces、预定义数据文件和 equations 校验，并一次返回可定位的诊断集合。

校验失败时，候选 YAML 和临时上传文件只能保留在编辑状态或临时隔离区：不生成正式模型文件，不进入选择器，不参与装配，也不占用 `_1`、`_2` 等项目模型编号。校验成功后才由后端分配只递增且不复用的后缀，将规范模型 YAML、配套数据、摘要、回执和项目模型清单引用原子保存。任一步失败都不能留下部分文件。

### 文件要求

设备模型必须遵守[设备模型 YAML](formats/device-model-yaml.md)，并且只描述：

- 稳定设备类型 ID 和名称；
- 不随时间变化的纯技术 properties、单位和值域；
- 序列 interfaces 的 carrier、单位、有效区间和五类接口语义；
- properties、接口序列与内部变量之间的受限声明式 equations。

YAML 只能表达声明式纯技术语义，不能包含 Python 模块、函数路径、shell、可执行命令、凭证、绝对路径或宿主机目录，也不能包含价格、成本、财务假设或计算精度。模型需要新的计算方法时，应另行提供算法插件，不能把代码藏进 YAML。

### 身份、revision 和内容摘要

用户模型使用系统分配的公开命名空间，例如 `user.<public_namespace>.device.<slug>`。`public_namespace` 在用户首次需要公开命名空间时，由系统使用密码学安全随机源生成 12 位小写 Crockford Base32 标识（60 bit），唯一冲突时重试；分配后终身不变、不可转让且不复用。命名空间不包含用户名、数据库 ID 或个人信息，账号改名不影响它。用户只选择符合命名规则的 `slug`，后端组合并校验完整稳定 ID；客户端不得自行指定或覆盖命名空间。稳定 ID 创建后不变，显示名称可以随 revision 调整。

既有用户在迁移中按相同规则一次性补分配命名空间。已发布且不符合新命名空间的稳定 ID 不得静默改写；必须经显式离线迁移生成旧 ID → 新 ID 映射、内容摘要和迁移回执，并原子更新全部引用。未完成该迁移的内容不得作为新的用户模型发布。

设备文件自身没有 `version`。每次发布固定单调递增的 revision、统一 `schema_version`、规范字节 SHA-256 和校验回执；相同规范内容的重复发布幂等返回同一不可变内容。破坏性格式变化提升统一设备 schema 的 MAJOR，不为每个设备分别提升版本。

### 进入系统建模

模型发布后会经过 schema、properties、五类 interfaces、单位、有效区间、预定义数据和 equations 校验。只有已安装到当前用户模型库且校验通过的内容 revision 才会出现在系统建模的设备选择器中。

选择器同时显示系统内置模型和用户已安装模型，并标明来源、稳定 ID、revision 和内容摘要。共享园地中的模型必须先安装到自己的模型库，不能直接跨目录引用。

## 开发算法插件

### 一个包包含两个阶段

算法插件 ZIP 同时交付：

1. **加工程序**：把 `ValidatedAssemblyArtifact` 和已固定资源转换成求解所需文件与输出声明；
2. **算法程序**：读取加工结果和已校验选项，完成计算并输出声明结果。

两部分打包和版本化在一起，但仍遵守标准计算链：

```text
ValidatedAssemblyArtifact
  → 插件加工程序
  → Solver Bundle
  → 插件算法程序
  → ExecutionReceipt
  → ResultAdapter
  → ComputeResult
```

加工程序承担业务单位到求解器内部单位的明确转换。算法程序不重新读取项目、模型库或最新数据，也不能绕过 Solver Bundle 与结果适配契约。

### 第一版交付格式

第一版只接受[算法插件包](formats/algorithm-plugin-package.md)规定的 Python ZIP，至少包含：

- `algorithm.plugin.yaml` manifest；
- 加工入口和算法入口；
- 带哈希的完整依赖锁；
- 算法选项和结果 schema；
- 最小合法输入、预期输出和自检样例；
- README、许可证和版本说明。

第一版不接受原生二进制、动态链接库、自带容器镜像、安装脚本、Git/URL 依赖、源码包或运行时在线下载。扩展字段不能绕过这些限制。

### 运行约束

插件代码只在系统提供的隔离环境中校验和执行，不会被 Web、API 或普通 Worker 直接导入。插件作者必须假定运行环境：

- 无公共网络和业务内网；
- 无数据库、对象存储或用户会话凭证；
- 无宿主机路径、仓库目录和业务数据目录；
- 只提供 manifest 声明的输入和独立临时工作目录；
- 强制 CPU、内存、进程数、文件大小、日志和执行时间上限；
- 依赖只能来自部署允许的离线 Python 包集合，并按哈希锁定。

插件不能依赖机器时区、环境变量、未声明文件、外部服务或调用顺序。确定性插件在相同输入、版本、依赖环境和种子下必须产生相同加工文件与结果摘要。

### 进入计算配置

上传包必须依次通过归档安全、manifest、依赖、入口、schema 和隔离自检。只有已安装、校验通过、环境兼容且未停用的精确版本才会出现在计算配置的算法选择器中。

选择插件后，任务会固定插件 ID、精确版本、ZIP 摘要、依赖环境、选项、随机种子和资源上限。插件后续发布新版本不会改变已提交任务。

## 在共享园地发布

### 申请共享

模型所有者可以对一个已经校验通过的不可变内容 revision 申请共享；插件所有者对精确版本申请共享。申请材料至少包括公开名称、说明、分类、适用范围、许可证、变更说明、内容摘要和校验结果。

管理员批准的是该精确设备内容或插件版本进入共享园地的资格，不是对计算结果的担保。设备新 revision 或插件新版本必须重新申请；同一条目的批准不能自动覆盖后续内容。

### 浏览和安装

所有已登录用户可以浏览已批准内容，并查看作者、许可证、兼容范围、设备 revision/插件精确版本、内容摘要和校验摘要。点击安装后，该内容进入用户自己的模型库或算法插件目录，随后才能在相应项目步骤中选择。

安装是对同一不可变版本的逻辑引用，不复制 YAML、ZIP、依赖锁、测试样例或运行环境。因此，同一版本被多个用户安装不会按用户数增加底层内容存储。

用户可以安装同一设备稳定 ID 的多个不可变 revision，也可以安装同一插件 ID 的多个精确版本。系统不会静默升级；采用新内容需要显式安装并在项目或计算配置中重新选择。

### 停止共享和卸载

停止共享只阻止新的浏览与安装，不自动删除其他用户已经安装的版本。发现严重安全问题时，管理员可以阻止该版本用于新任务，但历史项目、任务和证据仍按原摘要保留解释能力。

卸载只从当前用户目录移除选择资格，不删除仍被项目版本、任务快照或历史证据引用的内容。系统必须在卸载前提示当前引用影响。

## 权限与可见性

- 用户可以创建、上传、发布和停用自己的内容，并安装共享版本；
- 私有模型、插件、校验详情和文件只对所有者可见；
- 只有所有者可以申请共享自己的设备 publication 或插件精确版本；
- 只有管理员可以批准、驳回、停止共享或因安全问题阻止版本；
- 共享园地不会改变项目访问权限，也不能成为读取他人项目或数据的入口。

## 外部开发者交付检查

提交模型前确认：

- YAML 可由独立 schema 工具校验；
- properties、五类 interfaces、预定义数据、方程和单位完整；
- 稳定 ID、内容摘要和许可证明确；
- 文件没有独立设备版本、价格、成本或计算精度；
- 文件中没有代码入口、凭证或环境路径；
- 至少提供一个合法使用示例和预期 descriptor。

提交算法插件前确认：

- ZIP 目录和 manifest 符合公开格式；
- 加工程序与算法程序边界清楚，输入输出均有 schema；
- 依赖完整锁定且无需联网；
- 最小样例能在受限环境完成自检；
- 输出不含非有限数值、未声明文件、秘密或宿主机路径；
- 版本变化符合语义化版本规则。

## 兼容性和历史解释

设备内容 revision、插件版本、文件 schema 和产品版本分别演进，不能机械同步。系统无法识别的 schema MAJOR、缺失的精确依赖或不兼容能力必须明确拒绝，不会回退到同名内置内容或最新内容。

共享状态、安装状态和当前可用内容只影响新选择。历史项目和任务始终按当时固定的设备内容摘要、插件版本、环境与证据解释。

内部数据库、暂定 API 路径、容器编排、测试矩阵和开发切片不属于本指南的长期公共承诺。
