# 模型与算法扩展指南

> 文档状态：生效目标指南；目标产品版本：`1.2.0`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)；相关格式：[设备模型 YAML](formats/device-model-yaml.md)、[算法插件包](formats/algorithm-plugin-package.md)

本指南规定用户自定义设备模型、算法插件包与独立公共市场 **pIES Market**（规划于 `1.2.0` 交付）的长期交付标准、身份与多版本模型、运行模式、审批机制及隔离边界。

## 核心架构定位

模型与算法生态由**本地管理（`ThermalEng/pIES`）**与**独立公共市场（`ThermalEng/pIES-Market`）**共同构成：

- **本地模型与插件管理**：在 pIES 实例内管理设备模型（`ies.device-model` YAML 经基础信息/`properties`/`interfaces` 常用字段双向同步表单、在线 YAML 编辑器与 `.device.yaml` 文件导入/导出统一校验生成，复杂 `equations` 保持 YAML/表达式编辑）与算法插件（`ies.algorithm-plugin` ZIP 经隔离容器环境构建、断网自检与执行），并依托零后端依赖的极简独立包 `pies-sdk` 提供运行时契约及通用 `validate`/`pack` 工具。
- **pIES Market（公共市场）**：与各 pIES 部署实例解耦，由静态 JSON 索引（`index.json`）、制品分发与同源纯静态浏览/下载页（支持免登录筛选、查看说明/许可证/`sha256` 并直接下载离线包），以及独立可自托管的极薄无状态投稿网关（邮箱验证码校验 → 自动创建 GitHub PR → 人工 PR Review → 合并后自动校验、计算 `sha256`、发布制品并重生成静态索引与目录页）组成。公共市场**不得成为 pIES 本地计算的运行依赖**——市场关闭、不可用或断网时，本地已安装的模型、插件与离线导入导出功能均不受影响。
- **统一单页「模型与算法」视图与管理后台分工**：系统升级原自定义入口（`/custom`）为统一单页「模型与算法」，不设平行的“共享园地”页面，页面内部采用两个平级页签：
  - **「市场与已安装」**：统一呈现全部制品流，支持按制品/插件种类（设备模型及五类算法插件）分类筛选、切换同一稳定 ID 下的历史精确版本/修订，并为每个条目明确标注三类状态之一：
    - **`远端`**：仅联网模式下可见的公共市场可用制品；
    - **`本地（未安装）`**：本地目录已上架（制品与镜像已在实例级就绪），但当前成员尚未安装启用的制品；
    - **`本地（已安装）`**：当前成员已安装且可用于建模或计算的制品。
  - **「我的创作/草稿」**：承载个人自定义设备模型编辑（表单/YAML/文件导入导出、草稿保存与发布）以及个人向本地上传设备模型或算法插件的提交与审批记录。
  - **管理后台（`/admin`）**：集中承载实例运行模式切换（本地模式 / 联网模式）、市场索引与投稿网关地址、可选 pip 镜像/内网源、本地上传审批开关（`local_upload_requires_approval`）、待审批队列，以及本地已上架制品的停用与彻底卸载。

## 身份、不可变发布与多版本安装模型

### 稳定命名空间规则

| 来源类别 | 稳定标识格式 | 发布与分发固定规则 |
|---|---|---|
| 官方内置与官方市场制品 | `ies.<type>.<slug>` | 保留给官方维护与官方发布；版本或发布 `revision` 不可变 |
| 单实例本地个人自建草稿 | `user.<public_namespace>.<type>.<slug>` | `public_namespace` 由密码学安全随机源分配且终身不变；不对外强加跨实例冲突 |
| 公共市场社区/厂家制品 | `<publisher>.<type>.<slug>` | 使用贡献者、科研团队或设备厂家的稳定前缀（未指定时由市场在首次审核时分配）；经人工审核保证全市场唯一且发布后不可变更 |

- 跨实例从公共市场下载或通过离线包导入制品时，**原样保留其稳定 ID**，不改写原始命名空间；
- 设备模型按发布 `revision` 与校验回执固定（不设单设备语义版本）；算法插件按精确三段式语义版本固定；已发布内容不可原地静默覆盖，同一规范内容的重复发布保持幂等。

### 实例级共享缓存、多版本并存与快照冻结

- **禁止运行期热加载**：Web、API 与调度控制面进程永不加载或 `import` 用户插件源码；组合根仅在进程启动时静态注册受信任的执行桥接。
- **实例级去重缓存 + 成员级多版本并存安装**：底层制品对象与构建好的插件计算镜像在实例内按精确 `(id, version/revision)` 去重共享；是否安装启用按**当前成员**独立维护。同一稳定 ID 允许多个精确版本/修订在本地目录与成员已安装列表中并存（市场卡片默认展示最新版，详情支持切换历史版本），不同项目与计算配置可各自引用不同精确版本互不干扰。
- **安装即对后续计算可选**：已上架并安装的设备模型与算法插件作为数据库与受管对象存储中的不可变记录管理，安装或启停**无需重启服务**；项目与计算配置只能引用当前成员已安装且处于启用状态的精确版本/修订，禁止引用草稿或 `latest`。
- **提交冻结与变更隔离**：发起计算前在提交闸门完成兼容与参数校验，并一次性将精确 `(artifact_id, version, package_object_id, env_id, parameters)` 与生成的不可变输入文件冻结进不可变 `CalcSnapshot` 并建立对象引用，以保障可追溯性（不强行要求一次即毁的临时容器运行环境一致）。安装、停用或卸载**仅对之后新发起的计算生效**，不影响已在途计算，也不影响历史项目版本、快照与结果追溯。

### 外部完整性校验边界

- 外部市场索引在发布阶段生成并公开制品的 `sha256` 摘要；pIES 仅在**从外部市场下载或导入外部包进入系统的边界**一次性核验内容 `sha256` 与归档安全。
- 严格遵守[架构宪法](ARCHITECTURE_CONSTITUTION.md#26-校验只设在真实边界)：制品入库获得不可变 `ObjectId` 后，pIES 数据库、快照与运行期内部交接**不存储、不重算、不比对 SHA-256**，也不以内容摘要作为业务身份。

## 设备模型库规范

1. **纯技术语义与双模编辑**：遵循[设备模型 YAML](formats/device-model-yaml.md)，仅包含稳定标识、非时变 `properties`、五类 `interfaces`、可选模板 `inputs` 与受限声明式 `equations`；严禁夹带价格、成本、计算精度或代码路径。「我的创作/草稿」提供基础信息、`properties`、`interfaces` 常用字段表单与在线 YAML 的双向同步编辑及 `.device.yaml` 文件导入/导出，所有入口统一走同一后端权威校验。
2. **校验门禁与原子保存**：候选模型提交后须完整通过安全 YAML、Schema、单位、接口与方程校验；校验失败的候选仅留在编辑态或临时隔离区，不分配正式编号、不进入建模选择器。
3. **版本与面板可见性**：已安装且启用的设备模型直接出现在项目新建模型选择器中；项目内实际可见的已建模资产由当前草稿或所选项目版本声明的模型引用集合决定，历史版本恢复后不会混入其创建时刻之后新增的模型资产。

## 算法插件开发与运行约束

1. **五类插件统一支持与严格阶段解耦**：内置计算环节与外部算法插件均遵循[算法插件包](formats/algorithm-plugin-package.md)（`plugin.yaml`），统一支持 `predictor`、`generator`、`solver`、`evaluator` 与极简一体化 `algorithm` 五类插件在配置页动态选择与执行，并支持内部循环 `iteration` 接口。**严格保持阶段解耦边界**：`algorithm` 仅等价替代 `generator + solver` 拆分，绝不打破上游 `predictor` 与下游 `evaluator` 的职责边界——选配 `algorithm` 时仍按 `CalculationConfig.evaluator` 独立衔接解耦的后期财务评价环节（或显式置 `evaluator: null` 仅保留算法自身输出）。
2. **安装期自动构建、依赖源配置与断网自检门禁**：安装含 `requirements.txt` 的插件时，由白名单代理 `job_runner` 基于官方基础镜像 `pies-plugin-base` 自动构建专属计算镜像 `pies-plugin/<plugin_id>:<version>`（支持管理员配置可选 pip 镜像/内网源，留空走默认源）；无额外依赖的插件直接复用 `pies-plugin-base` 基础层零联网快速就绪。镜像构建完成后，若 `plugin.yaml` 声明了 `tests`，强制由 `backend` 经 `job_runner` 在 `--network=none` 容器中跑通全部自检样例后，方可将插件标记为可用。
3. **临时断网容器执行与受控镜像清理**：计算环节由 `backend` 经 `job_runner` 按步骤拉起断网临时容器（`/work/in → /work/out`），并在状态与有效产物持久化后清理容器与临时文件；运行环境无公网与内网访问权限、无数据库/对象存储凭证、无 Docker Socket 与宿主机仓库目录，并受部署资源（CPU、内存、超时、进程数、输出大小）强制约束，详见[部署与运行](deployment.md)。管理员彻底卸载某插件版本时，经 `job_runner` 受控白名单操作 `delete_plugin_image` 仅清理带 `pies.managed="true"` 标签的 `pies-plugin/*` 镜像，严禁清理内置基础镜像（`pies-builtin-stages`、`pies-plugin-base`）。
4. **确定性、输出边界与极简 `pies-sdk`**：相同输入、版本、依赖与种子须产生确定性结果；输出进入结果模型前须严格通过公开结果契约校验，仅含有限数值与受控日志；**平台仅校验公开结果契约合法性，不对任何插件的计算最优性或财务正确性背书**。独立参考插件须满足[扩展体系](extensions.md#边界划分与运行时模块化验收门禁)的四类运行时模块化门禁。`pies-sdk` 保持极简零后端依赖定位，仅提供契约/容器入口与覆盖全部五类插件的通用 `validate`（清单、目录安全与自检）和 `pack`（生成标准 `*.algorithm.zip` 并输出 `sha256`）命令，不附带脚手架或独立 PyPI 发布耦合。

## 运行模式、审批开关与生命周期

- **双角色与双账户彻底独立**：公共市场管理员通过 GitHub PR 负责公共制品的审核、合并发布与下架，不拥有任何 pIES 部署实例的管理权限，也不得访问用户工程数据；pIES 本地部署管理员在 `/admin` 管理本实例运行模式、市场与投稿网关地址、pip 镜像源、本地审批开关及本地目录状态；市场邮箱验证贡献者身份与本地 pIES 账号完全独立，不要求同步密码或用户信息。
- **本地模式 vs 联网模式**（由本地管理员在 `/admin` 切换）：
  - **本地模式**：关闭远端公共市场与外网投稿，不发起任何市场出网请求，目录不展示远端条目；普通成员既可安装本地已上架制品，也可向本实例上传/分享设备模型或算法插件，行为受管理员开关 **`local_upload_requires_approval`** 控制：
    - 开关**开启**时：普通成员的本地上传仅完成归档安全与契约静态校验并进入 `/admin` 待审批队列（此时不触发 Docker 镜像构建、不对其他成员公开），仅在管理员批准后才上架为本地可用条目并触发插件镜像构建与断网自检；
    - 开关**关闭**时：普通成员上传经静态校验通过后直接进入本地构建、自检与上架流程；管理员自身离线导入始终免审。
  - **联网模式**：所有登录成员均可浏览远端公共市场中的模型与插件，自由选择下载安装或离线导入（复用实例级镜像缓存并完成构建与断网自检），并可通过邮箱验证码经投稿网关向公共市场提交制品 PR。
- **隔离与引用保护**：未公开的个人设备模型草稿、待审批记录及被退回诊断仅对提交者本人（及审批管理员）可见；管理员可在 `/admin` 启用、停用或彻底卸载本地目录条目。成员取消安装或管理员彻底卸载仅解除目录可用引用（插件卸载可同步触发 `delete_plugin_image` 清理 `pies-plugin/*` 镜像），仍被历史项目版本、任务快照或证据引用的对象存储包不得物理删除，卸载前须明确提示引用影响。

## 外部交付自检清单

- **提交设备模型前**：确认通过 `1.0.0` Schema 校验、不含财务/精度/代码字段、具备稳定 ID、许可证与合法样例。
- **提交算法插件前**：运行 `pies-sdk validate` 与 `pies-sdk pack` 确认 ZIP 目录安全、清单合规及离线自检样例确定性通过；向公共市场投稿时附带清晰 `README.md`、明确许可证与至少一个无网络依赖的 `tests` 样例。
