# 模型与算法扩展指南

> 文档状态：生效目标指南；目标产品版本：`1.2.0`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)；相关格式：[设备模型 YAML](formats/device-model-yaml.md)、[算法插件包](formats/algorithm-plugin-package.md)

本指南规定用户自定义设备模型、算法插件包与独立公共市场 **pIES Market**（规划于 `1.2.0` 交付）的长期交付标准、身份版本模型、运行模式与安全边界。

## 核心架构定位

模型与算法生态由**本地管理（`ThermalEng/pIES`）**与**独立公共市场（`ThermalEng/pIES-Market`）**共同构成：

- **本地模型与插件管理**：在 pIES 实例内管理设备模型（`ies.device-model` YAML 经表单、在线 YAML 与文件导入统一校验生成）与算法插件（`ies.algorithm-plugin` ZIP 经隔离运行环境校验执行），并通过独立 SDK（`pies-sdk`，零依赖后端主程序）支持开发者构建与自检。
- **pIES Market（公共市场）**：独立于各 pIES 部署实例，承担公共制品的免登录浏览/下载、邮箱验证投稿、人工审核与版本分发。公共市场**不得成为 pIES 本地计算的运行依赖**——市场关闭、不可用或断网时，本地已安装的模型、插件与离线导入导出功能均不受影响。
- **统一单页市场视图**：系统不建设平行的“本地共享园地”页面，而是以单一市场视图统一呈现制品，支持按制品/插件种类分类筛选，并为每个条目明确标注三类状态之一：
  - **`远端`**：仅联网模式下可见的公共市场可用制品；
  - **`本地（未安装）`**：本地管理员侧已存在、但当前成员尚未安装启用的制品；
  - **`本地（已安装）`**：当前成员已安装且可用于建模或计算的制品。

## 身份、不可变发布与安装模型

### 稳定命名空间规则

| 来源类别 | 稳定标识格式 | 发布与分发固定规则 |
|---|---|---|
| 官方内置与官方市场制品 | `ies.<type>.<slug>` | 保留给官方维护与官方发布；版本或发布 `revision` 不可变 |
| 单实例本地个人自建草稿 | `user.<public_namespace>.<type>.<slug>` | `public_namespace` 由密码学安全随机源分配且终身不变；不对外强加跨实例冲突 |
| 公共市场社区/厂家制品 | `<publisher>.<type>.<slug>` | 使用贡献者、科研团队或设备厂家的稳定前缀（未指定时由市场在首次审核时分配）；经人工审核保证全市场唯一且发布后不可变更 |

- 跨实例从公共市场下载或通过离线包导入制品时，**原样保留其稳定 ID**，不改写原始命名空间；
- 设备模型按发布 `revision` 与校验回执固定（不设单设备语义版本）；算法插件按精确三段式语义版本固定；已发布内容不可原地静默覆盖，同一规范内容的重复发布保持幂等。

### 无热加载注册、安装与快照冻结

- **禁止运行期热加载**：Web、API 与普通 Worker 进程永不加载或 `import` 用户插件源码；组合根仅在进程启动时静态注册受信任的执行桥接。
- **安装即对后续计算可选**：已安装插件作为数据库与受管对象存储中的不可变记录管理，安装或启停**无需重启服务**；项目与计算配置只能引用已安装且处于启用状态的精确版本/修订，禁止引用草稿或 `latest`。
- **提交冻结与变更隔离**：发起计算前在提交闸门完成兼容与参数校验，并一次性将精确 `(artifact_id, version, package_object_id, env_id, parameters)` 冻结进不可变 `CalcSnapshot` 并建立对象引用。安装、停用或卸载**仅对之后新发起的计算生效**，不影响已在途计算，也不影响历史项目版本、快照与结果追溯。

### 外部完整性校验边界

- 外部市场索引在发布阶段生成并公开制品的 `sha256` 摘要；pIES 仅在**从外部市场下载或导入外部包进入系统的边界**一次性核验内容 `sha256` 与归档安全。
- 严格遵守[架构宪法](ARCHITECTURE_CONSTITUTION.md#26-校验只设在真实边界)：制品入库获得不可变 `ObjectId` 后，pIES 数据库、快照与运行期内部交接**不存储、不重算、不比对 SHA-256**，也不以内容摘要作为业务身份。

## 设备模型库规范

1. **纯技术语义**：遵循[设备模型 YAML](formats/device-model-yaml.md)，仅包含稳定标识、非时变 `properties`、五类 `interfaces` 与受限声明式 `equations`；严禁夹带价格、成本、计算精度或代码路径。
2. **校验门禁与原子保存**：候选模型提交后须完整通过安全 YAML、Schema、单位、接口与方程校验；校验失败的候选仅留在编辑态或临时隔离区，不分配正式编号、不进入建模选择器。
3. **版本与面板可见性**：项目内可用的模型选择器由当前草稿或所选项目版本声明的模型引用集合决定，历史版本恢复后不会显示其创建时刻之后新增的模型资产。

## 算法插件开发与运行约束

1. **统一简洁契约**：内置计算环节与外部算法插件均遵循[算法插件包](formats/algorithm-plugin-package.md)（`plugin.yaml`），支持 `predictor`、`generator`、`solver`、`evaluator` 与极简一体化 `algorithm` 五类种类，以及面向内部迭代循环的专用 `iteration` 接口；普通插件无需手写 `Dockerfile` 或拆分多文件工程。
2. **安装期自动构建不可变镜像**：安装含额外依赖的插件时，由白名单代理 `job_runner` 基于官方基础镜像构建专属不可变计算镜像，依赖准备与运行期彻底分离；无额外依赖的插件直接复用基础环境层。
3. **临时断网容器执行**：计算环节由 `backend` 经 `job_runner` 按步骤拉起断网临时容器（`/work/in → /work/out`），算完即毁；运行环境无公网与内网访问权限、无数据库/对象存储凭证、无 Docker Socket 与宿主机仓库目录，并受部署资源（CPU、内存、超时、进程数、输出大小）强制约束，详见[部署与运行](deployment.md)。
4. **确定性与输出边界**：相同输入、版本、依赖与种子须产生确定性结果；输出进入结果模型前须严格通过公开结果契约校验，仅含有限数值与受控日志。

## 运行模式、权限隔离与生命周期

- **双角色与双账户彻底独立**：公共市场管理员负责公共制品的审核、发布与下架，不拥有任何 pIES 部署实例的管理权限，也不得访问用户工程数据；pIES 本地部署管理员管理本实例运行模式、市场地址与本地安装状态；市场邮箱验证贡献者身份与本地 pIES 账号完全独立，不要求同步密码或用户信息。
- **本地模式 vs 联网模式**（由本地管理员切换）：
  - **本地模式**：关闭远端公共市场，不发起任何市场出网请求，列表不展示远端条目；普通用户的“分享”仅分享到本实例本地管理员级别，不开放向外部市场上传/投稿的权限；本地离线导入/导出与正常计算完全可用。
  - **联网模式**：所有登录用户均可浏览远端公共市场中的模型与插件，自由选择下载安装，并可通过邮箱验证码向公共市场上传投稿。
- **隔离与引用保护**：未公开的草稿与校验明细仅对所有者可见；管理员可启用、停用或卸载本地条目。用户或管理员卸载仅解除可用目录引用，仍被历史项目版本、任务快照或证据引用的对象不得物理删除，卸载前须提示引用影响。

## 外部交付自检清单

- **提交设备模型前**：确认通过 `1.0.0` Schema 校验、不含财务/精度/代码字段、具备稳定 ID、许可证与合法样例。
- **提交算法插件前**：确认 ZIP 目录、安全规则与清单合规，本地测试样例在离线隔离环境下可确定性通过并正确校验输出 Schema；向公共市场投稿时附带清晰 `README.md` 与明确许可证。
