# 模型与算法扩展指南

> 文档状态：生效规范；产品版本：`1.2.0`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)；相关格式：[设备模型 YAML](formats/device-model-yaml.md)、[算法插件包](formats/algorithm-plugin-package.md)、[计算配置](formats/calculation-config.md)

本指南规定用户自定义设备模型、算法插件包与独立公共市场 **pIES Market**（随 `1.2.0` 交付）的长期交付标准、市场索引与无状态投稿契约、身份与单当前生效版本模型、正交运行模式与审批机制及安全隔离边界。

## 核心架构定位

模型与算法生态由**本地管理（`ThermalEng/pIES`）**与**独立公共市场（`ThermalEng/pIES-Market`）**共同构成：

- **本地模型与插件管理**：在 pIES 实例内管理设备模型（`ies.device-model` YAML 经基础信息/`properties`/`interfaces` 常用字段双向同步表单、在线 YAML 编辑器与 `.device.yaml` 文件导入/导出统一校验生成，复杂 `equations` 保持 YAML/表达式编辑）与算法插件（`ies.algorithm-plugin` ZIP 经受控镜像构建、断网自检与单向容器流水线执行），并依托零后端依赖的极简独立包 `pies-sdk` 提供运行时契约及通用 `validate`/`pack` 工具。
- **pIES Market（公共市场）**：与各 pIES 部署实例解耦，由静态 JSON 索引（`index.json`）、制品分发与同源纯静态浏览/下载页（免登录筛选、查看说明/许可证/`sha256` 并直接下载离线包），以及独立可自托管的极薄无状态投稿网关组成。公共市场**不得成为 pIES 本地计算的运行依赖**——市场关闭、不可用或断网时，本地已安装的模型、插件与离线导入导出功能均不受影响。
- **统一单页「模型与算法」视图与管理后台分工**：系统升级原自定义入口（`/custom`）为统一单页「模型与算法」，不设平行的“共享园地”页面，内部采用两个平级页签：
  - **「市场与已安装」**：统一呈现制品流，支持按制品/插件种类（设备模型及五类算法插件）分类筛选与查看当前生效版本/修订，并为每个条目明确标注三类前端主状态之一：
    - **`远端`**：仅联网模式下可见的公共市场可用制品；
    - **`本地（未安装）`**：本地目录已就绪（状态为 `ready`），但当前成员尚未安装启用的制品；
    - **`本地（已安装）`**：当前成员已安装且可用于建模或计算的制品。
  - **「我的创作/草稿」**：承载个人自定义设备模型编辑（表单/YAML/文件导入导出、草稿保存与发布）以及个人向本地提交设备模型或算法插件的后台状态（`pending_approval` 待审批 / `building` 构建自检中 / `ready` 可用 / `build_failed` 构建或自检失败 / `disabled` 已停用）与诊断记录。
  - **管理后台（`/admin`）**：集中承载两个正交实例开关（运行模式 `market_mode` 与本地上传审批 `local_upload_requires_approval`）、市场索引与投稿网关地址、可选 `pip_index_url` 镜像/内网源、待审批队列，以及本地目录条目的启停与卸载清理。

## 身份、命名空间归属与单当前生效版本模型

### 稳定命名空间与所有权规则

| 来源类别 | 稳定标识格式 | 所有权、投稿转换与版本规则 |
|---|---|---|
| 官方内置与官方市场制品 | `ies.<type>.<slug>` | 保留给官方维护与官方发布；每 `(kind, stable_id)` 在实例目录仅保留 1 个当前生效版本或发布 `revision` |
| 单实例本地个人自建草稿 | `user.<public_namespace>.<type>.<slug>` | `public_namespace` 为系统分配的 12 位随机 Base32 字符串（60 bit 熵），终身不变，用于单实例自建与跨实例离线导包防撞名及账号名脱敏 |
| 公共市场社区/厂家制品 | `<publisher>.<type>.<slug>` | 投稿公共市场时统一收敛为可读 `<publisher>` 前缀；首次审核通过时在市场仓库静态文件登记 `<publisher>` 与验证邮箱加密哈希绑定（零明文邮箱），后续仅同一验证邮箱可发布该命名空间新版本/新修订 |

- **跨实例保留原始身份与版本**：从公共市场下载或通过离线包导入制品时，**原样保留其稳定 ID 与发布方分配的版本或整数 `revision`**（纯技术 `.device.yaml` 正文不内嵌版本字段，发布 `revision` 由市场索引或导出元数据携带；无元数据的裸单文件离线导入默认记为 `revision = 1` 或按导入参数指定），绝不重新编号。
- **冲突拒绝与显式覆盖升级**：本地目录按 `(kind, stable_id)` 仅维护 **1 个当前生效版本**：同一 `(kind, stable_id, version/revision)` 重复提交直接按 `409` 冲突拒绝（**严禁自动改名、自动递增修订号或静默覆盖**）；若提交同一 `(kind, stable_id)` 的新版本，则按显式**覆盖升级**处理——原地替换为新版本并尽最大努力清理旧插件镜像（清理失败仅记日志告警，不影响新版本使用）。**平台不设多版本共存，也不设版本兼容或自动迁移机制**——模型/插件升级到高版本后，既有项目或配置只有两种合法结果：**要么高版本插件/模型自身选择向后兼容低版本输入而继续正常运行，要么按当前契约与校验直接报错**；是否向后兼容完全由高版本插件/模型自身决定，平台不建设中间适配层或跨版本迁移工具。

### 实例级单版本缓存与快照冻结

- **禁止运行期热加载**：Web、API 与调度控制面进程永不加载或 `import` 用户插件源码；组合根仅在进程启动时静态注册受信任的执行桥接与平台基础能力。
- **实例级单当前生效版本共享 + 成员级安装启用**：底层制品对象与构建好的插件镜像在实例目录按 `(kind, stable_id)` 唯一维护当前生效版本；安装启用状态按**当前成员**独立维护。项目草稿与计算配置直接按稳定标识（及插件当前唯一版本引用）消费，不维护项目级历史版本固定表、草稿多版本切换，也不建设任何跨版本兼容适配层或平台迁移转换工具；升级高版本后能否兼容既有项目输入，完全由高版本模型/插件自身实现决定，不兼容则由预检或提交校验直接报错。
- **安装即对后续计算可选与提交冻结**：仅后台状态为 `ready` 且被当前成员安装启用的当前生效制品可被项目与计算配置引用（禁止草稿或未就绪版本）。任务提交闸门校验通过后，一次性将精确引用、阶段分槽参数与不可变输入冻结进 `CalcSnapshot` 并建立对象引用；制品升级、停用与卸载采用直接操作模型：管理员应自行选择适当操作时机，平台不保证制品变更后尚未进入相关计算阶段的在途任务能够继续完成；若所需插件或镜像已不可用，任务明确报错。已冻结输入与已持久化结果/证据不受影响。

### 外部完整性校验边界

严格遵守[架构宪法](ARCHITECTURE_CONSTITUTION.md#26-校验只设在真实边界)，仅在**公共市场远端下载**入库前核对一次 `index.json` 声明的 `sha256` 并执行归档安全与契约校验；本地上传与离线导入不要求、不校验 `expected_sha256`。

完成上述外部入口校验并写入受管对象存储获得不可变 `ObjectId` 后，pIES 数据库、快照与运行期交接**一律不存储、不重算、不比对 SHA-256**，也不以内容摘要作为业务身份。

## 公共市场索引契约与无状态投稿协议

### 静态市场索引契约（`ies.market-index@1.0.0`）

`ThermalEng/pIES-Market` 构建生成的 `index.json` 是同源纯静态浏览/下载页与各 pIES 客户端共同消费的**唯一公开制品清单契约**（不维护第二套列表）：

  "schema_version": "1.0.0",

      "kind": "device_model",

- **版本标识**：`kind: "device_model"` 使用正整数 `revision`；五类算法插件（`predictor` / `generator` / `solver` / `evaluator` / `algorithm`）使用三段式语义化 `version`；同一 `id` 的多个历史版本/修订并列保存在 `artifacts` 中。
- **下架隔离**：公共市场下架仅将对应条目从远端可分发索引移除（或标记停止分发），**绝不远程自动撤销或破坏各 pIES 实例本地已安装的制品**。

### 极薄无状态投稿网关协议

投稿网关不引入数据库或账号系统，以 GitHub PR 本身作为持久化审核记录：

1. **请求验证码**：提交邮箱地址，经 SMTP 发送短期一次性验证码并返回带服务端 HMAC 签名、绑定邮箱/随机盐与短期过期时间的无状态挑战凭证（可保留简单的验证码发送冷却时间或交由部署层限流，不建设复杂滑动窗口、分布式计数或风控系统）；
2. **无状态验权**：提交验证码与挑战凭证完成比对后，签发用途绑定且短期过期的无状态投稿凭证；
3. **上传与前置校验**：携带短期投稿凭证上传 `.device.yaml` 或 `.algorithm.zip` 及投稿说明，网关执行基本 ZIP 路径与总量边界、结构/清单 Schema 校验，并使用目标市场仓库的 `MARKET_HMAC_SECRET` 计算邮箱摘要核对 `publishers.yaml`（不扫描制品全部文本文件防邮箱泄漏）；
4. **创建 PR**：网关使用最小权限 GitHub App / Token 检查同一 `(id, version/revision)` 无重复未决 PR 后创建分支并提交 PR（已有冲突时明确报错，不建设复杂 GitHub 幂等恢复状态机）；**投稿邮箱仅用于验权与生成非明文绑定摘要，不写入公开 PR 正文或 `index.json`**；
5. **只读隔离自检与人工审核合并**：PR 触发只读 `pull_request` 工作流（禁用 `pull_request_target`，执行环境零 GitHub 写权限、零 SMTP/发布密钥，自检容器全程 `--network=none`）；人工审核合并后，由独立受信任发布工作流打包计算 `sha256` 并重生成 `index.json` 与纯静态目录页。**责任边界明确为：投稿网关只负责投稿流程与基本入口边界；`pIES-Market` 只负责制品结构、身份与公开契约格式；发布者对公开制品内容与领域正确性负责；第三方代码仅在隔离容器环境内执行。**

## 设备模型库规范

1. **纯技术语义与双模编辑**：遵循[设备模型 YAML](formats/device-model-yaml.md)，仅含稳定标识、非时变 `properties`、五类 `interfaces`、可选模板 `inputs` 与声明式 `equations`，严禁夹带价格、成本、精度或代码路径。「我的创作/草稿」提供常用字段表单与在线 YAML 双向同步及 `.device.yaml` 导入/导出，统一经后端权威校验。
2. **校验门禁与面板可见性**：未通过完整校验的候选仅留在草稿区；已安装且启用的本地生效设备模型出现在项目新建模型选择器中，提交后的计算任务通过 `CalcSnapshot` 冻结对应设备模型内容。

## 算法插件单向流水线、构建信任边界与运行约束

1. **框架零拷贝交接、极简子进程还原与并联可重试评价**：遵循[算法插件包](formats/algorithm-plugin-package.md)（`plugin.yaml`）与[计算配置](formats/calculation-config.md)，五类插件按 `冻结输入 → [predictions[]: 同层按插件分组执行] → (generator → solver → backend 极简子进程还原工程解 | algorithm) → [evaluators[]: 0..N 个独立评价器并联执行] → 结果` 单趟单向运行：
   - **单进单出容器与框架硬链接交接**：临时容器仅运行单输入单输出的可插拔计算插件，不承担文件搬运职责；跨环节只读上下文统一由调度框架经硬链接零拷贝组装进目标环节只读 `/work/in`；
   - **同层分组与多目标联合预测**：逻辑预测环节内部按所选 `predictor` 插件分组执行，同插件多目标一次联合预测以保留共享潜变量相关性，框架合并全部预测序列后送入下一环；含内部迭代寻优的算法统一在单容器内经 `iteration` 完成；
   - **`backend` 极简子进程还原与并联可重试评价**：分步模式 `solver` 按 0-based 输入原始列序输出原变量解后，由 `backend` 在极简 `spawn` 子进程内流式结合 `variable_map` 忠实还原为业务单位标准工程解（退出即释放内存，不替第三方求解器做重新验算；无可行解时跳过依赖可行解的评价器）；核心求解成功时顶层任务结局仅反映核心求解，下游并联运行 `0..N` 个独立 `evaluator`——局部评价器失败不破坏已封存工程解与其他成功评价块，并支持在结果页单独重试该失败评价器；官方财务评价器复用同源财务规则做全量正向财评，第三方评价器按自描述 `metrics` / `charts` / `tables` 协议由前端通用渲染；插件组合兼容以 `consumes` / `produces` 判定。
2. **构建阶段信任边界与单一指定源规则**：
   - 无 `requirements.txt` 的插件强制以 `--network=none` 直接基于本地 `pies-plugin-base` 构建；
   - 含 `requirements.txt` 的插件在 `job_runner` 内存受控上下文中构建，**严禁挂载宿主机业务目录、严禁注入数据库/Redis/密钥等业务凭证，并采用简单超时终止机制（构建在独立执行单元中进行，不深入 Docker SDK 私有对象、底层 socket 或响应流内部建设额外中断逻辑）**；`pip_index_url` 留空走默认公网 PyPI，**非空时仅传 `--index-url <pip_index_url>`**（不拼接 `--extra-index-url`，防多源混合选版与企业内网依赖混淆；上游代理回退由镜像服务端自身负责）；依赖安装失败时后台标记 `build_failed` 并明确弹窗提示具体缺失依赖/插件名称及“请联系管理员安装或配置依赖源”。
3. **安装期断网自检门禁与状态区分**：镜像构建成功后，若 `plugin.yaml` 声明了 `tests`（同时支持单 JSON 简写与 `in/` → `expected/` 完整目录多文件样例），强制经 `job_runner` 在 `--network=none` 容器内全部跑通后才将后台状态由 `building` 置为 `ready`（失败置为 `build_failed`）。**自检通过仅代表通过作者样例与公开契约结构检查，平台不对任何第三方插件的工程最优性或财务正确性背书**。
4. **极简 `pies-sdk`**：保持零后端依赖定位，仅提供运行时契约/入口及覆盖全部五类插件的通用 `validate`（清单、基本路径与离线自检）与 `pack`（打标准 `*.algorithm.zip`）命令。

## 正交运行模式、审批开关与直接卸载

管理员在 `/admin` 维护两项**相互正交**的实例级策略：

| 管理设置 | 控制范围与生效规则 |
|---|---|
| `market_mode`（`local` / `online`） | 控制是否连接远端 `pIES-Market`：本地模式零市场出网请求、隐藏远端条目并禁用外网投稿；联网模式开放远端浏览、下载与邮箱验证投稿 |
| `local_upload_requires_approval`（`true` / `false`） | **在本地模式和联网模式下统一生效**：联网模式下从已审核公共市场直接下载的制品免本地审批；但**任何非管理员成员自行上传或离线导入**的本地制品均受本开关约束（开启时仅做静态结构与契约校验并进入 `pending_approval` 队列、不触发构建，批准后才转入 `building → ready`；关闭时直接进入构建与上架；管理员自身操作免审）。 |

**单步停用与镜像清理**：

- 管理员停用/卸载本地制品时，直接将目录条目标记为 `disabled` 阻止新任务选择，并尽最大努力经 `job_runner` `delete_plugin_image` 清理带 `pies.managed="true"` 标签的 `pies-plugin/*` 镜像（严禁触碰 `pies-builtin-stages` 与 `pies-plugin-base`；镜像删除失败仅记录告警并清空状态引用，不维护后台重试或阻断状态机）；
- **对象引用保护**：仍被历史项目版本、任务快照或证据引用的对象存储包受 `ObjectOwner` 保护不得物理删除。

## 外部交付自检清单
