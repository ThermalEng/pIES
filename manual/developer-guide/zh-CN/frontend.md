# 前端与帮助中心

> 文档状态：生效蓝图；代码边界：`frontend/src/`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)

前端负责将后端公开契约映射为清晰可用的交互界面，管理未提交表单与界面展示偏好，不持有权威业务状态，也不在客户端复现领域计算或授权判断。

## 目录分层与依赖方向

```text
app / pages → features → shared
```

| 层级 | 职责 | 约束 |
|---|---|---|
| `app` | 路由装配、全局 Provider、会话生命周期与错误边界 | 不包含具体业务表单逻辑 |
| `pages` | 组织路由级用户工作流与多 Feature 组合 | 不直接拼装后端 DTO 或调用底层 HTTP 客户端 |
| `features` | 拥有单个业务能力的 `contracts`、`model`、`form`、纯 `mappers`、查询/变更 Hook 与组件 | Feature 之间不互相导入内部表单或缓存 |
| `shared` | 与具体业务无关的 HTTP 客户端、错误解析、格式化、i18n 与通用 UI 组件 | 不依赖任何业务 Feature |

## 前后端数据映射边界

- **类型隔离**：严格区分 `ResponseContract`（服务端 JSON 输出）、`RequestContract`（提交请求 DTO）、`FrontendModel`（前端领域视图）与 `FormState`（未提交输入文本）。
- **纯 Mapper 边界**：百分比显示转换（如 `8` ↔ `0.08`）、表单字符串解析与简单展示单位换算集中在纯 Mapper 中完成并附单元测试；后端返回的规范业务数据直接消费，不在客户端重复校验已通过后端边界的内部字段。
- **外观与本地偏好**：统一通过语义 CSS 变量支持浅色/深色主题及中英文切换（`color-scheme` 与 `document.lang` 同步跟随）；语言与外观选择保存在浏览器本地存储，与账号及项目数据独立，页面首帧前恢复。

## 状态管理与失败处理

| 状态类型 | 权威所有者 | 示例 |
|---|---|---|
| 服务器事实 | Feature 查询/缓存层 | 项目、草稿、任务、结果、设备目录 |
| 未提交编辑 | Feature 表单状态 | 参数输入框文本、待上传文件、临时连线编辑 |
| 瞬时 UI 状态 | 组件本地状态 | 弹窗开关、当前选中行、目录折叠 |
| 导航定位 | Router / URL | 当前项目 ID、任务 ID、帮助章节 ID |

核心交互纪律：

1. **区分状态而非猜空态**：明确区分“加载中”“成功空集合”“离线”“权限不足”“版本冲突（409）”与“服务异常”。请求失败时展示错误与重试入口，绝不将失败伪装为“暂无数据”。
2. **乐观锁与编辑保护**：并发冲突（409）或校验失败（400/422）时必须保留用户未提交输入；字段级诊断贴近字段展示并保留摘要总览，冲突由用户决定主动重载最新修订或强制覆盖。
3. **会话与异步任务**：仅由可见页面的真实用户交互触发空闲会话续期，后台轮询与自动刷新不保活；任务列表与结果页轮询在离开页面或任务进入终态后停止；逐时曲线分页加载支持取消过期请求，防止旧响应覆盖新选择。
4. **不可变结果展示**：结果页指标、财务明细、建设状态、月度需量账单及图表全部读取所选任务的封存事实，不在前端重算财务指标或用当前项目草稿补齐字段。

## Schema 驱动 GUI 与通用建模

遵循[模型文档与后端为中心](architecture.md#模型文档与后端为中心)：

- **表单与文档共存**：结构化表单服务常用参数编辑，完整 YAML/JSON 编辑器承载完整契约（如 `step_relation`、`system_equations`、`amount_relation`、命名财务关系与多期规则）。两者操作同一后端文档，视图切换时保留合法字段与精确十进制原文，不按表单白名单静默裁剪。
- **通用设备与画布**：设备面板、属性表单与端口类型完全由后端 `DeviceDescriptor` 生成；画布仅维持端口连线的基础几何与类型规则（禁止自环、重复边、`blind` 端口连线，`predefined` 端口仅配置数据源），按后端真实实例与端口 ID 提交命令。
- **统一保存入口**：前端表单、模板实例化或在线编辑生成的模型、财务及配置文档，序列化为完整文档后经同一后端解析接口校验落盘。

### 浏览器探索与自动回归

浏览器级验收统一在 Docker 中运行真实 Chromium，所有操作从页面入口开始并使用无障碍语义定位器，禁止通过状态注入绕过被测流程：

- **Agent 探索**：新功能上线或交互发生实质重构时，通过真实浏览器操作探索用户路径、异常提示与恢复体验，将确认通过的关键路径固化为 Playwright 测试用例。
- **自动回归**：本地开发与 CI 共享同一套 Playwright 用例、测试数据工厂与业务断言，仅通过环境变量适配运行编排；日常提交按变更影响范围选择直接相关及邻接用例回归，发布或重大架构调整时运行完整套件。任何运行报告须注明提交基线、实际执行范围与未覆盖部分。

## 帮助中心机制

产品顶部导航的“帮助中心（Help Center）”在前端构建阶段（`frontend/scripts/generate-help.mjs`）直接读取仓库 `manual/` 生成只读 `manifest.json`：

- `manual/SUMMARY.md` 登记可用语言，`manual/SUMMARY.<locale>.md` 定义“使用者指南”“开发者指南”“更新日志”三棵一级目录树，页面 ID 取自文件 basename（跨语言稳定一致）。
- 支持深链接、标题锚点、前后翻页、移动端折叠导航与键盘焦点管理；渲染层严格过滤原始 HTML、脚本及不安全协议链接。
- 运行期完全静态托管，后端或数据库不可用时仍可正常浏览；目标语言缺失时明确提示可用语言列表，不以其他语言内容静默替代。

## 完成标准

- Feature 内部 `contract`、`model`、`form` 与 `mapper` 职责清晰分离，Mapper 关键边界具备单元测试；
- 加载、空数据、权限不足、冲突、离线与服务器错误状态均可区分且保留未提交表单；
- 画布交互、文件导出、深链接导航、主题/语言持久化及键盘/移动端适配均通过 Docker Playwright 验收；
- 用户可见行为变更同步更新使用者指南与更新日志。
