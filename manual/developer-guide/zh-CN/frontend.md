# 前端与帮助中心

> 文档状态：生效蓝图；规范版本：1.1.0；代码边界：`frontend/src/`；上位规范：[架构宪法](ARCHITECTURE_CONSTITUTION.md)

## 作用

前端把公开业务 contract 转换成用户可以理解和操作的页面。它负责输入体验、状态呈现、导航、本地化和可访问性，但不拥有项目、任务、结果和权限等服务器事实。

开发一个前端功能时，应能够从“用户要完成什么”一路追到“提交哪个 DTO、显示哪个应用结果、失败后如何恢复”。页面不是后端资源的字段堆叠，也不能通过额外请求和本地 Map 猜出后端没有承诺的关系。

## 输入与输出

| 方向 | 内容 | 前端保证 |
|---|---|---|
| API → 前端 | 响应 DTO、错误信封、版本与 revision | 按公开 DTO 直接消费，不猜测兼容形状，不把失败当空数据 |
| schema → GUI | 设备 properties、interfaces、单位、范围、方程与算法能力 | 使用通用组件呈现，不复制类型映射 |
| 用户 → 表单 | 文本、选择、拖放、文件和确认 | 保留未提交状态，给出即时反馈 |
| 表单 → API | 规范 DTO、幂等键、revision 和文件 | 通过纯 mapper 转换，字段一一对应 |
| 应用结果 → 用户 | 成功、进度、冲突、诊断和下载 | 显示可观察结果与恢复动作 |

表单状态是前端输入，响应 DTO 是服务器输出；两者不能共用一个宽松类型。

服务器已通过业务边界形成的响应属于可信内部交接，不在客户端重新逐字段校验、比对摘要或补默认值。删除兼容猜测应改为消费唯一公开 contract，而非增加第二套运行期验证器；用户输入的即时提示、请求失败和业务诊断展示仍保留。

## 前端分层

前端按业务 feature 垂直切分，依赖方向为：

```text
app / pages → features → shared
```

`shared` 只包含通用 HTTP、会话、错误解析、展示组件、格式化和基础类型，不依赖业务 feature。跨 feature 工作流由页面或显式应用 hook 组织，不能藏在底层 HTTP 客户端中。

一级导航包含面向所有已登录用户的“模型与算法”。该入口不属于某个项目工作台，也不与管理员“系统设置”混合；内部固定提供“模型库”“算法插件”“共享园地”三个入口。目标 feature 为 `features/customizations/`，路由页面只组合对应目录、编辑器、上传、版本、共享申请和逻辑安装；模型画布与计算配置只消费它公开的可选择目录 contract，不导入其内部表单或缓存。

每个 feature 应区分：

- 与 HTTP JSON 一一对应的 contract；
- 前端领域模型；
- 尚未提交的表单状态；
- 纯 mapper；
- 查询、mutation 和用例 hook；
- 展示组件。

页面与组件不能直接拼请求 JSON。mapper 不访问网络、缓存或 React 状态。

### 每层怎样思考

- `app`：装配路由、全局 provider、错误边界和会话启动；
- `pages`：组织一个路由级用户工作流，决定多个 feature 的先后关系；
- `features`：拥有一个业务能力的 contract、model、form、mapper、请求和组件；
- `shared`：提供不知道具体业务也成立的 HTTP、格式化、i18n 和基础 UI。

现有代码仍在从页面集中结构迁移到 feature 结构。迁移时先抽离 contract 与 mapper，再抽离请求和状态，最后拆组件；不能只移动文件而保留页面直接拼 DTO 的依赖。

## 一个交互的处理流程

```text
加载页面
  ↓ feature query 获取 ResponseContract
mapper → FrontendModel
  ↓ 初始化或更新 FormState
用户编辑 / 即时校验
  ↓ 提交时 mapper
RequestContract + revision/idempotency key
  ↓ mutation
成功：更新/失效服务器状态并显示确认
失败：保留表单，显示结构化错误与恢复动作
```

加载、保存中、成功、空集合、权限不足、冲突、离线和服务器失败是不同状态。只有服务器明确返回成功的空集合才能显示“暂无数据”。

## 状态与失败

计算配置的静态相容性使用所选生成器公开描述符的事实，包含计算模式、精度、求解器和输出能力；不支持的选择应在保存或提交的公开输入边界明确反馈，不留到任务执行后才发现。前端不硬编码单个生成器的支持清单，后端仍为权威；静态能力检查不生成计算包，也不复制数学降级检查。

数据绑定成功后，界面必须更新显示绑定关系所依赖的权威项目状态，表格徽章、按钮和可选数据版本保持一致。读回失败时明确区分“写入成功但状态读取失败”，不伪装为未绑定或鼓励重复提交；不建立另一份永久绑定事实。

服务器状态有一个明确缓存来源，并显式定义 query key、失效、轮询、取消和竞态策略。React 本地状态只保存表单、选择项和弹窗等瞬时状态。

主请求失败必须展示错误和重试入口。权限、契约或服务器失败不能被解释成“暂无数据”；模块级 Map 不能成为业务事实。

### 状态所有权

| 状态 | 所有者 | 示例 |
|---|---|---|
| 服务器事实 | query/cache 层 | 项目、任务、结果、设备目录 |
| 未提交输入 | feature/form | 参数文本、选项、上传文件 |
| 瞬时界面状态 | 组件 | 当前弹窗、选中行、目录展开 |
| URL 状态 | router | 当前项目、任务、帮助章节、筛选 |

同一服务器资源只能有一个缓存权威。mutation 成功后按明确策略更新或失效；轮询结果要处理页面离开、旧请求迟到和任务进入终态。

### 错误展示

- 字段诊断显示在字段附近，并保留总览；
- 资源冲突显示服务器 revision 和重新加载入口；
- 会话失效进入重新认证，不清空未提交输入后伪装成功；
- 离线时暂停自动写入，恢复后先重新取得服务器状态；
- 未知内部错误显示 request ID 和报告路径，不展示堆栈；
- 业务错误展示后端公开错误信封中的具体原因与字段诊断；翻译键缺失或通用模板未给出具体原因时，使用已公开的业务详情，不显示原始消息键或未替换占位符。无公开详情时显示受控通用错误与错误码／request ID，不暴露内部异常。

## Schema 驱动 GUI

遵循[模型文档与后端为中心](architecture.md#模型文档与后端为中心)：结构化表单覆盖常用操作，完整文档／自定义约束编辑承载正式契约允许的其余关系，两者使用同一业务文档和后端保存入口。表单编辑、文档编辑与切换不得静默删除表单未呈现但契约合法的内容；无法无损表达的部分保留在文档编辑中，不强制改写为专用栏目。

设备 properties、单位、五类 interfaces、方程诊断和算法兼容性来自公开 schema。前端只保留与具体设备无关的交互规则，例如禁止自环、重复连线和接口类型不匹配；`blind` 不可连接，`predefined` 只展示其数据来源配置。

画布使用服务端提供的真实 interface ID。拖放、连线、property 编辑、导航和错误状态统一通过 Docker 中的 Playwright 浏览器验收。

规划变量、成本与计量绑定等实例选择使用后端公开的实例引用与显示名对应关系，显示可本地化名称，提交真实引用。选择器与文档编辑使用同一引用；前端不以显示名、列表位置或自行生成的 slug 替代它。缺少对应关系时补齐公开接口，不以名称建议列表冒充引用绑定；列表读取失败明确展示。

跨实例逐步关系通过规划的通用文档／自定义约束编辑入口填写，字段以[装配格式](formats/assembly-yaml.md#逐步技术约束)为准。完整引用映射与表达式必须无损保存和重开；常用选择器仅辅助填写真实实例和端口，不为防逆流、设备类型或特定业务另建必填表单。

### 浏览器探索与自动回归

新功能或交互发生实质变化时，由 Agent 通过真实浏览器探索用户流程、异常反馈和恢复方式，把已确认的关键操作与结果固化为 Playwright 用例。已有用例覆盖的局部修改按影响范围回归，不要求每次提交重新进行 Agent 探索。脚本不能替代对未知使用障碍的探索，探索成功也不能替代可重复的回归证据。

本地与云端共享业务代码、测试用例和断言，只按运行环境调整启动编排、资源与证据收集。两者均在 Docker 中启动真实浏览器及被测服务；无界面运行不等于接口模拟。云端按脚本执行，不依赖常驻 Agent 自行探索，也不需要另建长期测试分支或第二套业务断言。

按变更选择直接相关用例与必要邻接回归，全量测试用于发布或明确需要的重大变更。结果必须注明提交基线、实际执行范围及未验证部分；冒烟通过仅证明其覆盖的基础流程，不表示画布、计费、求解或完整业务验收通过。失败的既有用例仍须跟踪，不能因本轮未选中而视为已修复。

## 开发一个 feature

1. 从使用者场景写出入口、操作、成功结果和失败恢复；
2. 找到对应 API contract；若 contract 不足，先修正后端边界，不在前端猜测；
3. 定义 `RequestContract`、`ResponseContract`、前端 model 和 form 四类不同类型；
4. 编写 DTO↔model、form↔DTO 的纯 mapper 及边界值测试；
5. 定义 query key、加载、失效、轮询、取消和竞态策略；
6. 构建语义化、可键盘操作的组件；
7. 处理全部已知错误信封、权限和冲突；
8. 用页面级浏览器流程验收，并同步使用者指南与更新日志。

一个 feature 对外只暴露页面组合真正需要的 model、hook 和组件。其他 feature 不应导入它的内部 contract、form 或缓存实现。

## 典型工作流

### 管理模型与算法

“模型库”支持 property/interface/equation 表单、在线 YAML 编辑和 YAML 上传，三种入口显示同一草稿并在发布时生成同一规范文件。“算法插件”支持上传符合 `ies.algorithm-plugin` 的 ZIP、查看静态校验、隔离自检、依赖、版本和运行兼容性。“共享园地”展示管理员已批准的精确设备发布或插件版本；安装只增加目录引用，页面不得展示为复制文件。

页面必须分别展示草稿、校验中、校验失败、私有可用、申请共享、审核中、已共享、共享驳回、不可用和已停用状态，并显示 revision、schema、依赖和诊断；插件另显示语义版本。只有后端返回 `selectable=true` 且已安装到当前用户目录的精确发布才出现在相应业务选择器中；前端不得把“已上传”解释为“可运行”。模型画布固定稳定设备 ID，算法选择固定插件 ID 与精确版本；两者都不保存显示名、列表位置或 `latest`。

### 编辑项目图

设备目录提供统一 schema 和 descriptor，前端据此生成设备面板、property 表单和真实 interfaces。用户拖放、编辑或连线后，mapper 发送带 revision 的明确命令；服务器返回新 revision 或冲突。前端只保存画布布局与交互状态，不自行决定 interface 业务兼容性，也不把价格、成本或计算精度写入设备表单。

同一画布的连续属性修改按提交意图顺序保存，合并最新已确认修订，不以旧参数整包覆盖后续修改。保存回包更新未继续编辑的字段，保留更新的本地输入；侧栏关闭重开或切换设备后，仍须协调已保存值与本次新编辑，参数、名称和来源编辑保持一致。未发生编辑的聚焦／失焦不重复写回旧值。表单错误在对应字段附近明确展示并保留输入，修正后可继续提交；示例不得冒充默认值，后端仍为领域校验权威。

### 新建并保存项目模型

模板实例化、结构化表单和直接 YAML 编辑必须生成同一种完整配置文件，并汇合为同一个候选校验/保存用例。前端可以做即时提示，但不得直接组装后端领域对象；“可保存”只由后端正式文件解析器决定：

1. 编辑状态保留候选 YAML、未提交表单和临时上传；
2. 将表单状态序列化为完整配置文件字节，连同项目 revision 和幂等键提交；数据关键字值只写已位于项目目录的 CSV 相对路径；
3. 校验失败时保持编辑内容，按 YAML 行列和字段路径展示全部诊断，不显示“保存成功”；
4. 校验成功后以后端返回的最终 `_N` ID、规范 YAML 和项目 revision 替换编辑状态；
5. 只有此时模型才进入项目模型列表并允许进入装配。

前端不得预分配 `_1`、`_2` 编号，不得把本地合并结果直接写入项目文件夹，也不得把上传完成解释为模型已经保存。模型保存失败时必须保留原配置文件并提供修复和重试入口。

该流程必须有往返契约测试：前端表单生成的完整文件必须可被后端正式解析器直接读取。转换结果中每个关键字都要核对业务值；未知关键字、缺失必填项、错误类型、不存在或不可读的 CSV 及 CSV 内容错误必须返回稳定错误码和可定位诊断，不得变成 500、空对象、默认值或部分保存。

### 提交并跟踪任务

提交页发送任务类型、配置选择和幂等信息；收到 202 后以任务 ID 轮询公开状态。进入终态后停止轮询。重试调用明确的重试用例，不复制旧请求并重新读取当前表单。

### 查看历史结果

结果页以 task/evidence 标识加载固定结果。指标、逐时数据、评估和导出都来自该来源；不得用当前项目缓存补缺失字段，也不得在前端重算财务或评估公式。

### 财务配置与税务结果

项目财务编辑沿已有 FinanceProfile 选择／登记与 FinanceOverrides 接口提供入口，完整文档编辑与保存采用正式财务格式，不在前端另建税种公式或政策默认值；财务文档与封闭 CalculationConfig 分开提交。保存失败保留编辑内容并展示后端字段诊断，版本冲突由用户选择重载，不静默覆盖。

需量费目录的结构化编辑与完整 JSON 编辑共享同一文档，项目覆盖只修改画像已登记费项的费率。实例成本、能源计费和需量计量绑定沿同一草稿修订保存，计量关系由用户显式选择，不按设备类型推断。会替换编辑内容的保存、画像切换及重读期间统一锁定相关编辑，结束后恢复；冲突不丢弃未提交输入。

税务结果按[封存评价块](modules/finance.md#封存评价块-financial_evaluation)展示：明确区分税款结算前运行净额与完整税后现金流，VAT实缴、退款确认／到账／留抵及所得税、折旧、亏损余额使用各自的池／规则／期间身份。无适用规则与缺少财务结果分别展示，不把期末留抵或期后应收加成现金收益。Excel报告使用同一任务的封存字段及单位，保留明确期间与税务明细，不在下载时重新计算税务或评价。

需量月账单与年度需量费同样直接消费封存事实，保留计费身份、自然年月、财务年及单位；无绑定与零费率分开展示，不从曲线重新取峰或从当前费率重算。页面与 Excel 均按所选任务读取冻结来源，项目版本与设备摘要不取当前可变工作状态。

## 帮助中心

`manual/` 是帮助中心唯一正文来源。构建阶段读取 `SUMMARY.<locale>.md` 生成只读内容清单，运行时不读取宿主机文件，也不调用后端转换 Markdown。

每个语言目录有三个并列一级节点：使用者指南、开发者指南、更新日志。帮助中心必须支持深链接、标题锚点、前后章节、当前节点、移动目录和键盘导航。

Markdown 禁止执行原始 HTML、脚本、内联事件或不安全 URL。语言缺失时明确列出可用语言，不静默展示另一语言。

帮助 manifest 中的产品版本来自后端产品元数据，目录来自 `SUMMARY.<locale>.md`，正文来自同一 `manual/` 文件。增加章节时要保证 basename 形成的 page ID 在所有语言和全部章节中唯一。

## 必须遵循的规范

- 前端 contract 与 HTTP JSON 字段一一对应，ID 不参与算术；
- 百分数、输入字符串和简单展示单位只在 mapper 边界转换；
- 不复制设备、interface、算法、诊断或单位业务映射；
- 页面不直接调用底层 HTTP 客户端；
- 权限隐藏只改善体验，所有写操作仍由后端授权；
- 原始 HTML、不安全 URL、秘密和内部路径不得进入帮助或错误展示；
- 中英文 UI 的同一业务状态必须使用同一消息键和参数。

## 完成标准

- contract、model、form 和 mapper 职责分离；
- mapper 的百分比、单位、ID、空值和错误边界有单元测试；
- 加载、空数据、失败、离线、冲突和权限状态可区分；
- 桌面、移动、键盘、深链接和刷新行为通过浏览器验收；
- 画布拖放和 interface 连接通过真实浏览器交互验收；
- 页面行为与使用者指南一致，帮助中心能在业务后端不可用时静态阅读。

代码阅读从路由页面确认用户工作流，再进入相应 feature 的 contract、mapper 和 hook；迁移期页面集中代码应按上述依赖方向逐步拆分，而不是成为新功能继续堆叠的位置。

## 文档同步

- 页面、字段、单位、错误处理或用户流程改变时，同一变更更新使用者指南；
- 公共 contract、扩展或部署方式改变时，更新开发者指南；
- 用户可感知变更记入更新日志；
- 未实现能力不得在指南中伪装成现有功能。
