# 概念、单位与当前限制

## 六种容易混淆的“版本”

| 名称 | 含义 | 用户应如何使用 |
|---|---|---|
| 产品版本 | pIES 程序版本，例如 `0.1.0` | 报告问题和判断功能范围 |
| 项目草稿 | 当前可编辑的模型、绑定和配置 | 日常编辑，自动保存不等于永久版本 |
| 项目版本 | 项目在某个时点固化的内容 | 追溯计算输入；当前 GUI 没有独立发布按钮 |
| 数据集版本 | 同一数据集每次上传形成的版本 | 核对质量后明确绑定 |
| 计算配置版本 | 每次成功保存的配置修订 | 提交任务前核对 |
| 计算快照与证据 | 任务实际使用的冻结输入及结果依据 | 解释历史结果，不用当前草稿替代 |

## 单位

页面字段旁显示的单位决定数值含义。常见功率使用 kW，能量使用 kWh，温度使用 °C，比例字段通常以 `%` 显示，金额使用项目币种。

- 不要把单位文字写入只接受数值的输入框；
- 不要自行把 kW 和 kWh 互换；
- 百分数 `8%` 在百分比输入框填写 `8`；
- 数据上传时必须为每个字段声明单位；
- 同一项目的金额不自动换汇。

## 时间

数据集版本对其通用时间戳使用一个固定 UTC 偏移声明，不使用夏令时切换；项目本身不设置时区。全年行数由项目创建时固定的运行起始年按公历确定（闰年多一日点数），分辨率不同也会改变每年行数，上传前应使用页面给出的期望值核对。

## 财务评价和 IRR

项目评价使用覆盖建设和运营的完整现金流一次算出，不做“基准方案双重求解”。结果中的 IRR 是评价输出，必须与其状态一起解释（正常、无解、多解、退化、超出定义域、数值失败）；没有唯一正常解时，不应只引用一个数值，更不存在“最低 IRR”之类的阈值输入或硬约束。

当前任务评价链尚未接通完整税务和折旧处理，已有 NPV、IRR 和回收期不能直接作为经过税后处理的投资结论。输入价格标为“含税”不代表已计算税后现金流；与税后收益测算表比较时，必须先补齐相同核算主体、税务规则和现金流口径，不能把现有结果换标签后比较。

## 费用口径与当前限制

- 固定运维费：按装机容量的年度费用（`annual_fixed_om`，投产后逐年扣减）与按显式发生年扣减的大修/换新清单（`maintenance_expenses`），均保留；
- 使用运维费：按实际运行量/发电量（如 kWh、m³）与单价计取（`period_variable_om`），由仿真调度按年度实际量直接归集，能力全部保留；燃气等体积计量已验证（`m³`/`m³/h`），`Nm³` 暂未进入单位词汇，填写时以页面单位为准；
- 无年份、无时间维度的标量全期运维金额会被装配拒绝（不自动均摊），请改用上述三类之一表达；
- 可选建设叠加正固定建设费当前会被明确拒收（已批准的版本限制，将来是否支持另行裁决）；静态实例与必建容量的固定建设费不受此限，可正常计入。

## 当前 `0.1.0` 限制

- 产品仍处于正式发布前阶段，公开契约可能按 Roadmap 一次性收敛；
- 项目包导入只有上传提案与确认导入入口，尚无提案列表与取消提案接口；
- 数据行级预览可能不可用；
- 人工评估输入尚未提供，只支持系统评估；
- 管理员可在“审计日志”只读查看已记录操作（无修改/删除能力）；管理页尚未提供备份恢复和维护操作；
- GUI 尚未提供一级“模型与算法”入口，当前不能使用模型库、算法插件或共享园地；
- 正式帮助文档当前只发布简体中文。

后续开发顺序以 [Roadmap](../../changelog/roadmap.md) 为准；未列在当前 GUI 中的功能不要当作已交付能力。
