# 概念、单位与当前限制

## 六种容易混淆的“版本”

| 名称 | 含义 | 用户应如何使用 |
|---|---|---|
| 产品版本 | pIES 程序版本，例如 `0.1.0` | 报告问题和判断功能范围 |
| 项目草稿 | 当前可编辑的模型、绑定和配置 | 日常编辑，自动保存不等于永久版本 |
| 项目版本 | 项目在某个时点固化的内容 | 追溯计算输入；当前 GUI 没有独立发布按钮 |
| 数据集版本 | 同一数据集每次上传形成的版本 | 核对质量后明确绑定 |
| 计算配置版本 | 每次成功保存的配置修订 | 提交任务前核对 |
| 计算快照与证据 | 任务实际使用的冻结输入及结果依据 | 解释历史结果，不用当前草稿替代 |

## 单位

页面字段旁显示的单位决定数值含义。常见功率使用 kW，能量使用 kWh，温度使用 °C，比例字段通常以 `%` 显示，金额使用项目币种。

- 不要把单位文字写入只接受数值的输入框；
- 不要自行把 kW 和 kWh 互换；
- 百分数 `8%` 在百分比输入框填写 `8`；
- 数据上传时必须为每个字段声明单位；
- 同一项目的金额不自动换汇。

## 时间

项目和数据集使用固定 UTC 偏移。当前全年数据按 365 天非闰年处理，不使用夏令时切换。分辨率不同会改变每年行数，上传前应使用页面给出的期望值核对。

## 财务基准和 IRR

财务基准是“不新增建设、仅使用现有设备”的对比方案。最低 IRR 是硬约束。结果中的 IRR 必须与其状态一起解释；没有唯一正常解时，不应只引用一个数值。

## 当前 `0.1.0` 限制

- 产品仍处于正式发布前阶段，公开契约可能按 Roadmap 一次性收敛；
- GUI 没有独立创建或恢复项目版本的入口；
- GUI 没有完整项目包导入入口；
- 数据行级预览可能不可用；
- 候选方案应用与历史结果追溯仍需在 `1.0.0` 前完成一致性验收；
- 人工评估输入尚未提供，只支持系统评估；
- 管理页尚未提供完整审计、备份恢复和维护操作；
- GUI 尚未提供一级“模型与算法”入口，当前不能使用模型库、算法插件或共享园地；
- 正式帮助文档当前只发布简体中文。

后续开发顺序以 [Roadmap](../../changelog/roadmap.md) 为准；未列在当前 GUI 中的功能不要当作已交付能力。
