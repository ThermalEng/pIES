# 0.15 对抗式实例验收现场

日期：2026-10-22。临时过程控制，不是产品规范；基线06418ae（0.14.5退出）。正式范围以manual/changelog/roadmap.md为准，规则以现行宪法和模块/格式正文为准。

## 角色与首轮

- 主审Codex：资料保管、缺陷脱敏、版本冻结、产品规则裁决和独立验收。只由主审把通用缺陷转交开发者，不允许两角色直接交换私有文件或参数。
- 用户侧：Herdr wG:pN，Gemini 3.8 Flash；工作树 `.claude/worktrees/pies-015-adversarial-user`，分支acceptance/0.15-adversarial-user。真实归档副本仅在此树docs/acceptance-private/0.15，原归档不变。不改生产实现，先做明确与未决输入盘点、当前公开入口可表达性和首个黑盒问题报告；税务/时间轴等未决不能自造。
- 开发侧：Herdr wG:p1，MiniMax M3.1 Flash；工作树 `.claude/worktrees/pies-015-adversarial-dev`，分支slice/0.15-adversarial-dev。仅交付docs/developer-input两个合成文件及公开规范，不复制真实数据/策略/参数/参考结果。首轮只读公开契约与合成样例，等待主审脱敏问题，不先按猜测建设功能。

## 循环

冻结提交→用户从真实公开入口验收→私有报告给主审→主审分清用户输入/未决规则/通用产品缺陷→必要时用独立合成最小复现派工→开发定向Docker验证→主审审查冻结新提交→用户重测及保密扰动。真实数据不得进入开发回归fixture、生产分支或可见报告。

真实案例容器与开发容器用独立Compose项目/卷/账号，不把私有文件、数据库或对象卷挂到开发测试。用户侧不得mock或注入数据库/前端状态，不把历史调度当作最优解；最优性以真实可行性、目标与界/差距证据判断。不能为了让案例通过而特判文件名、客户、数值、时间或容量。

当前两个OpenCode运行在同一宿主用户下；工作树、输入投递及容器挂载分离属于流程盲测，不是对恶意同账号进程的操作系统安全沙箱。不声称已实现强制文件读取隔离。开发者的工具授权范围只包含自己的工作树、公开规范与自己的Docker测试，不授权读取其他工作树、主树私有资料、Herdr用户侧滚屏或其他测试卷。

只在本轮已有真实需求和证据上改实现，执行者不修改正式指导，主审维护长期规则。所有构建测试只用Docker；独立功能复审后提交，不自行合并/推送。当前不启动1.1模型库/运行期插件热加载。
