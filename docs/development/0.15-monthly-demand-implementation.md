# 0.15 月最大需量计费实施交接

日期：2026-10-24。状态：待实施；对应 0.15 ISSUE-04。本文件是一次实施计划，不是稳定规范，不定义第二份字段或数学规则。

## 原因与交付目标

现有能源计价按电量，不表达各自然月的最大购电功率费用。新增能力必须让用户明确配置计量点和费率，费用参与同一次优化，并能从月账单、年度净额、税务、评价与导出追溯到同一任务解；不能只在最终结果上补一笔账单。

## 顺序与边界

1. **D1 输入、绑定与冻结**：落实财务三件套及装配目标版本，覆盖费率覆盖、显式计量、规划分量识别、草稿、任务冻结、包往返及能力门禁。已有样例与定向测试一起更新；尚未具备求解能力的 provider 不发布需量支持标记，不允许提交后忽略费用。完成独立 PR，由主审复核后进入 D2。
2. **D2 同次求解与封存**：复用公历运营月界，完成真实月峰、费用、税务、现金流与公开财务事实，连通版本化适配及评价封存。数学建模和输出必须一起闭环；真实 HiGHS 定向用例通过后才能声明生成器支持该能力。独立 PR 复核。
3. **D3 用户入口与报告**：扩展现有财务／计量入口、结果页和 Excel，消费同一冻结事实；同步用户说明及更新日志。补浏览器用例，本轮末统一执行 Docker Playwright。

不扩展周期价格、规模关联维护、合同需量、阶梯罚款、计量窗口或跨表自动合并。任何超出既定核心规则的需求先报告，不自行添加默认值、内部重复校验或兼容分支。原 ISSUE-05/03 的待执行浏览器回归一并保留，不写成已通过。

## 定向验证证据

- 输入与冻结：合法／非法单位和引用、费率覆盖、同点不同费项、重复绑定、无电量价格的独立需量点、空需量配置及项目包往返；历史任务不随当前配置变化。
- 数学与现金：各月峰值不同、平年与闰年、不同分辨率和建设期偏移；手算月费与年费；改变可调运行方案能改变费用；零费率和不以经济量为目标的情形仍输出真实峰值。
- 税务与展示：合成含税／不含税、可抵／不可抵及所得税显式范围，证明现金只扣一次；月明细、年度费用、NPV、页面与 Excel 使用同次解事实。

所有编译和测试只在 Docker。执行环境不具备条件时提交源码与测试并如实列为待执行，由主审按风险安排验证；测试文件存在不代表验证通过。完成后只清理本切片生成的测试资源，不影响现有服务或基础镜像。

三个切片均复审并完成约定验证后，才判断 ISSUE-04 是否完成；本计划不宣告 0.15 完成。稳定规则修改由主审处理，执行者按已提交的指导版本实现和测试。
