## 1. 目标与交付边界

P1 把现有构模过程改为“先收齐可分析的关系，再统一处理，再展开并输出”，消除设备遍历顺序对转换时机的影响，并减少重复的表达式遍历和临时对象。它不是重做模型语言或把所有领域迁入一个全局引擎。

完成时必须得到四项可验证的成果：

1. 技术、网络、规划和现有财务关系进入同一次构模的关系集合，边界相关转换在集合完整后执行。
2. 同一方程结构只做必要次数的解析／编译，逐步绑定各自系数、常数与变量索引；仍生成原有独立决策。
3. 状态初值、相邻步、跨月／跨年、税务余额及年度聚合在重构后保持含义。
4. 输入中的实例、关系、绑定及财务条目能对应到生成诊断、求解行列和现有结果声明；构模各阶段有可复现的性能基线。

权威规则先读：[宪法](../../manual/developer-guide/zh-CN/ARCHITECTURE_CONSTITUTION.md)、[架构蓝图](../../manual/developer-guide/zh-CN/architecture.md#领域语义与数学表达)、[生成器](../../manual/developer-guide/zh-CN/modules/generators.md)、[技术贡献](../../manual/developer-guide/zh-CN/modules/modeling.md)、[Solver Bundle](../../manual/developer-guide/zh-CN/formats/solver-bundle.md)。新公开字段由主审先修所属正式契约；本文件中的内部概念名不是新增 YAML 字段或强制类名。

### P1 与后续阶段的分界

| 本轮完成 | 不混入本轮 |
| --- | --- |
| 完整关系收集、符号／单位／索引绑定、分析入口、边界需求定位；迁移现有推导与转换 | P2 的新全局界传播算法、模型域交集语义升级、建设激活、新互斥求解策略 |
| 现有母线关系进入关系集合 | P3-N 的端口网络新语义、来源流追踪 |
| 现有费用、税务、现金流与恢复声明统一引用构模符号 | P3-F 的命名费用协议、基准评价或新增税种／金额来源 |
| 模板复用、批量填值、减少副本 | P4 的年份压缩、共享调度、典型期近似 |
| 来源定位和既有结果链保持；必要的生成诊断传递 | 专用业务表单、全站 UI 重做、完整工程盲测 |

**P1 不承诺原先缺有限界的案例已经可解。** 它必须让完整关系可被分析、让不足可定位，并为 P2 提供真实接入点；不得为宣称通过而猜界、删约束、提高时限或改变测试设备模型。

## 3. 总体结构与关键路径

```text
现有六项冻结输入（公开接口保持不变）
  │
  ├─ 设备技术贡献 ──┐
  ├─ 当前网络关系 ──┤
  ├─ 规划与步约束 ──┼─ 声明符号、关系族、聚合与输出引用
  └─ 当前财务关系 ──┘              │
                                 ▼
                 收集完成：符号与关系均可按身份引用
                                 │
                 单位／索引绑定、系数计划与依赖分析
                                 │
                 统一边界查询入口及待转换需求
                                 │
                 现有精确转换（P2 后续替换／增强）
                                 │
                 按步／期间分块填值、分配行列
                                 │
                 线性模型 + 来源映射 + 结果声明
                                 │
                 MPS／参数／Bundle → Runtime → Adapter
```

关键路径是 **先把关系变成数据，而非“稍后执行的旧构模函数”**。仅把旧方法顺序调整或包成回调列表，仍无法在转换前看到约束内容，不算完成。

### 3.1 中间表示只承载编译所需事实

在生成器内部复用或补充少量类型化表示，区分：

- **符号声明**：来源身份、角色、业务单位、标量／步／月／年索引、已有边界来源；规划标量与技术属性接管引用指向同一符号。
- **关系族**：原始关系身份、涉及符号、比较方向、索引域和方程结构；不先复制 N 份 AST。
- **系数计划**：确定常数、输入序列取值、期间映射及已知量算术；与求解变量清楚分开。
- **聚合与待转换关系**：求和、峰值、互斥及当前税务分段等，保留输入／输出符号、期间和所需条件；不能提前散成缺来源的辅助变量。
- **输出引用**：已有技术序列、财务分量和现金流引用这些符号；最终列名由同一分配过程回填。

这些是一次 generate 调用内的编译产物，不持久化完整中间模型，不进入 `core` 作为全局注册表，不包装或替换六项权威输入。阶段出口保持只读；避免同时常驻“全展开原始关系、全展开中间关系、最终矩阵”三套副本。

### 3.2 如何汇集后统一分析

1. **声明优先**：登记所有实例、规划接管和期间索引，取得稳定符号身份；声明关系需要的语义输出，如月峰、税额及余额。此时不求具体解，不判断整个模型可行。
2. **收集关系**：设备方程、容量限制、现有母线、标量／逐步规划关系、计量聚合、财务关系都以可遍历形式加入。禁用关系沿既有规则不参与数学集合；未使用财务条目不被无端激活。
3. **统一绑定**：把局部引用绑定到符号，区分已知输入与决策量，沿现有规则转换单位及时间索引。已签发输入不重复做 YAML／Schema 校验。
4. **分析使用关系**：记录某个符号被哪些关系使用、哪些转换需要有限界、哪些输出依赖哪些聚合；分析能看到所有来源。普通联立等式允许成环，不能把物理反馈环误判为非法引用环。
5. **推导与转换分离**：P1 把现有界计算集中到统一查询入口，保留其计算能力；P2 再增加关系派生。需要界的转换统一提出需求并获得值或“未能确定”的结果，不各自读旧属性或猜数。
6. **转换后展开**：已有互斥、月峰与税务分段按现有规则产生辅助符号和线性关系，再分配实际行列。新增辅助关系继续进入同一来源与映射链。

财务余额有期间递推，峰值有时段聚合；这些依赖按其语义输出连接，不按函数调用顺序建立。辅助变量的界可能依赖前一阶段推导，应允许明确的依赖次序，但不能把尚未生成的列当作不存在的业务量。全部输入关系收齐不等于预先分配全部辅助整数列。

分析阶段可以按需读取某步／期间的已知系数来判断转换条件；不必等最终矩阵展开才读取，也不需要先保存全量系数矩阵。依赖图记录编译所需的引用和生成次序，不要求把求解中的联立约束强行排成可顺序求值的 DAG。

**P1/P2 接缝的最低验收**：把一个限制关系放在设备、系统或规划收集器的先后位置，收集完成后的分析视图都能看到同一个约束；待转换互斥在此之前不执行。P1 用现有可求界模型验证转换；新增自动派生界的通过用例归 P2，不以空接口冒充实现，也不要求 P1 顺便完成通用界传播。

## 4. 结构复用与逐步变化如何同时保留

### 4.1 编译的是结构，不是某一步的数值

例如：`output[t] = capacity × input[t]`。模板保留一个输出列槽、一个容量列槽及系数来源 `input[t]`；在各步分别填系数。不能取第 0 步的输入复制到后续，也不能因输入重复而让不同步共享 output 决策变量。

模板中的依赖分三类：

| 依赖 | 实例化方式 |
| --- | --- |
| 确定常数、固定属性、单位比例 | 每次实例绑定算一次；仍保留来源 |
| 已物化的设备输入／价格及已知期间系数 | 按实际 step 或期间读取；已有 SI 缓存继续复用 |
| 规划变量、运行变量、状态变量、税务决策 | 保留符号引用，不当常数计算 |

技术 AST 与规划表达式可以有不同前端表示，但输出相容的仿射模板；不用为统一而重新解析为自由公式。序列常数的乘除属于系数计算，变量乘变量仍按原能力处理。

模板复用范围由结构、符号角色、单位与绑定方式决定。固定容量实例与规划容量实例不能错误共用已代常数的结果；同一模型的不同参数可共享结构，不共享参数值。首次只需单次构模内的复用，不建跨任务缓存或内容 hash。

### 4.2 系数影响结构的情况须保留

- 系数在某一步为零，只消除该步对应项，不消除整条关系族。
- 系数符号变化，区间计算的上下侧随之变化；不能用首步的符号决定全期处理。
- 系数作为除数时，发生零值的实际步应给出来源定位，不能只检查首步。
- 常量关系、恒零互斥等已有特化按实际绑定值生效，不提前套用到所有时步。
- 月长度、闰年、税务余额到期、首步初值等形成不同的合法模板实例或边界分支，不能强行视为一张固定稀疏矩阵。

只沿当前语言已支持的关系设计这些处理，不借模板重构新增运算符、时区或任意索引语法。

### 4.3 状态连接与分块边界

以通用递推为例：`s[t] - s[t-1] - a[t]u[t] + b[t]v[t] = 0`。普通步模板保留前步偏移；在第 0 步，把 `s[-1]` 替换为冻结初值表达式。若初值依赖规划规模，该仿射引用继续参与同次求解，不能代入参考容量。

分块只改变构建内存与处理批次：下一块第一步仍连全局前一步；月界、年界均不自动重置状态。VAT 留抵、亏损结转等期间状态保持相同原则和原有到期规则。建设现金时点不当成运行步，年费不因运行步数变化被多算或少算。

不得新增末时状态、年末闭合或人为重复运行决策。当前接口只支持的 `[t]`、`[t-1]` 也不因内部索引重构扩大为新语言能力。

### 4.4 稀疏生成与结果出口

模板先引用符号槽，再按稳定规则分配实际列；可以批量填充或分块提交系数，避免每行重新复制整张符号表。边生成边维护结果引用，既有 `unit_map`、`step_series`、`components`、`financial_facts` 都来自该次构模。

优先保留现有线性模型与 writer 出口，减少其上游中间副本。若测量表明 writer 转置、字符串或 Bundle 字节副本成为主要成本，在现有协议内定向优化；不把磁盘流式协议、压缩文件或 Runtime 重构塞入 P1。至少分别测量数学构建、MPS 写出、元数据与 Bundle 组装，不能只把耗时移到另一个函数。

## 5. 模型来源定位贯穿整条链

### 5.1 在收集时保留，而非出错后猜

来源使用冻结输入已有身份：实例 ID、模型引用／revision、方程或约束 ID、财务条目／税则／绑定 ID，以及字段路径。实例来源与模板来源分开，同一模型的两实例不能合成同一错误位置。语法行号若上游已有可附带；不重新读原文件猜行号。

时变系数还应对应其冻结输入绑定与实际索引；沿用输入中已有的数据／价格对象引用，不另造身份或回读当前对象指针。定位应能区分“模型关系不支持”与“某步已知系数导致转换失败”。

来源链应覆盖：

```text
冻结文档中的对象／字段
  → 关系族及符号
  → 单位换算、初值替换、聚合／条件转换
  → 实际 step／月份／评价年
  → 求解行列
  → 诊断或既有序列／财务结果声明
```

一条原关系产生多行时保留父关系及转换角色；多个来源合成一条聚合时保留其引用，而不是任选一个设备名。引用去重是减少重复存储，不是丢弃参与来源。

### 5.2 诊断、封存与结果的分工

- **生成失败**：具体关系、实例、相关符号及时间位置可定位；说明是当前转换缺条件还是不支持的形式。通过现有诊断链传递，不发布半份 Bundle，不把所有异常包装成用户输入错误。
- **生成成功**：行列映射与该次 Bundle 一起固定，采用关系族／来源表加索引的紧凑表示；不为每个时间步复制完整 YAML、表达式文本和冗长来源链。
- **结果恢复**：继续用明确列引用恢复值；来源说明引用同一映射。不能分割列名猜业务 ID，不能从当前项目草稿解释历史结果。
- **求解不可行**：可定位已知生成关系不代表已有最小冲突集／IIS。P1 不伪造“某条约束就是根因”，不扩展为完整不可行诊断引擎。

实施前在 S1 盘点现有来源字段的承载能力。行列来源需要新增持久化字段时，方案限定为生成器／适配器配套的最小来源映射，由主审先修正式 [Bundle 格式](../../manual/developer-guide/zh-CN/formats/solver-bundle.md)及必要诊断契约，再开发消费者。不要私自给六项输入加包装，也不要在 Worker 建第二套来源注册表。

来源定位必须有真实失败链和成功恢复链验收，不能仅在单元测试里给行对象附一个属性就宣称贯通。

## 6. 开发切片与依赖

采用四个有边界的切片，均走公开生成入口；不同时维护两套生产构模器。对照实现只保留在基线提交或测试工具中，不设运行期 fallback。

| 切片 | 实施任务 | 可合并的交付标准 |
| --- | --- | --- |
| P1-S1：基线、声明与来源骨架 | 固定合成对照输入与测量入口；分开全局符号声明和设备逐步转换；确定内部关系表示、来源承载和必要版本变化 | 原支持模型仍可经 generate／Adapter 执行；实例排序不改变符号绑定；形成实测基线及提交主审的字段影响清单。此时不宣称全部关系已汇集 |
| P1-S2：完整关系汇集与统一分析 | 迁移技术、网络、规划、需量、现有税务／财务为可分析关系；移动边界相关转换到收集完成后；现有算法改为统一查询 | 不再有设备遍历中提前触发互斥／月峰／税务界失败的路径；分析可定位跨来源使用关系；保持已有物理、税务与现金含义 |
| P1-S3：模板复用与分块展开 | 技术及步约束结构复用，绑定时变系数；首步与期间状态特殊处理；批量行列与同源输出 | 系数变化、规划接管、跨块状态、月年边界均有数值对照；实际减少重复编译与临时对象，报告端到端构模资源变化 |
| P1-S4：来源闭环与集成收口 | 按已批准格式固化最小来源映射；贯通生成诊断及成功恢复；检查停止、确定性及阶段资源；删除被替代构模路径 | 失败可定位到模型关系和实际期间，成功值对应同一主解；既有 Worker／Adapter 链定向验证，P1 全部退出项满足 |

关键路径：**S1 的符号与来源身份 → S2 的完整关系集合 → S3 的模板与绑定 → S4 的执行证据闭环**。来源收集与性能测量从 S1 开始，不拖到 S4 临时补丁。

S1 确定接口后，合成用例／性能工具可与关系迁移并行；公共 builder、符号身份和行列分配由同一个开发主线维护。P2／P3 可提前研究，但不得在 P1 分支落入新业务语义。每个切片 PR 只扩展其必要消费者，不把上述四项一次性打包成不可审查的大改。

开发者首轮执行 P1-S1，提交实际基线、内部表示设计及最小迁移结果供审查，通过后接续 S2。单个切片 CI 通过只证明该切片，不等于 P1 整体完成。

## 7. 定向验证与性能证据

### 正确性矩阵

| 要证明的性质 | 必要合成用例 |
| --- | --- |
| 汇集与顺序无关 | 调换无业务顺序含义的设备／关系／约束映射顺序，约束和目标等价；同年维护顺序、亏损扣除优先级等有语义顺序必须保留 |
| 符号复用正确 | 同模型两实例、不同参数；固定与规划容量；规划标量在所有步共用一个决策而运行变量各步独立 |
| 系数确实逐步变化 | 非常数出力、分时价格、零值与符号变化；后续步的除零可定位；同形结构不能只用第一步数值 |
| 状态与时轴 | 仿射初值、首步、跨块相邻步、跨月／跨年状态、闰年月份聚合、建设期与运行期映射 |
| 边界与转换不变 | 已有恒零互斥、有限界互斥、月峰、VAT 结转、所得税亏损及初建／换新折旧；仍缺必要界时准确报告而非猜值 |
| 来源闭环 | 原方程、容量限制、系统约束、计量聚合、税务辅助行各至少一个来源断言；故意失败与成功主解恢复各一条公开链 |
| 结果与生命周期 | 年度现金、税额、净收付及目标同源；同输入同版本生成确定字节；协作取消不返回半成品、不重建第二次模型 |

正确性先做小型手算和真实 HiGHS 对照。等价单位模型应产生等价内部数学问题；不得要求业务单位映射相同。多最优解比较可行性、目标与各自同次解财务一致性，不要求调度逐点相同。

复用现有测试入口：`test_linear_lowering.py`、`test_project_model.py`、`test_step_relations_s2.py`、`test_highs_readiness.py`、`test_finance_s2_execution.py` 等，按实际影响选择；不重写大量业务夹具以迁就重构。不在生产路径增加第二轮求解后完整性校验；新旧对照属于测试。

### 性能测量方法

- 同一镜像、CPU／内存限制、配置与合成输入对照基线；记录提交、运行命令、样本规模及重复结果，区分冷启动和构模。
- 小规模模板／展开用例可使用少量步；公开 provider 集成必须使用合法运营时域，不能为了快测绕开年限契约。
- 合成规模逐级增加时域和实例数：分别观察短模型、单年、多年；先完成只构模测量，大模型不以必须求得最优为 P1 性能门槛。小模型承担真实求解正确性证明。
- 至少报告物化（上游单列）、收集／绑定、分析／转换、展开、MPS 写出、元数据／Bundle、求解、恢复各阶段；无法低成本拆分的阶段明确合并范围，不伪造精细计时。
- 统计峰值内存、变量／约束／非零系数／整数变量数、产物体积、模板编译次数与绑定次数。固定结构增长时，编译次数不应随步数线性重复，绑定和最终矩阵规模可以随步数增长。
- 性能数据写入独立测量产物或 PR 评论，不把实时时长写入确定性 Bundle。不为日常执行新增一套遥测服务。
- S1 提供基线后由主审与开发者固定代表规模和资源预算；S3/S4 给出同环境前后证据。不能把性能验收留成“看起来更快”，也不预定任意机器都数秒完成。

构模规模仍可能受最终 MPS／参数体积限制，应如实记录残余瓶颈交 P4；P1 必须证明已避免重复遍历／多份中间展开，不能仅改目录结构。

## 8. 版本、交接与开发纪律

1. 首个切片可在本计划 PR 分支继续，保留 P0 规范和计划提交；后续切片从已合入前置工作的最新 master 建独立分支，先核对基线差异。本地工作树用仓库内持久目录。不要触碰现有独立案例现场或运行数据。
2. 保持用户 YAML、财务规则和现有网络语义；不借 P1 修模板上限或激活新公开能力。内部重构不机械提升所有 schema。输出字节、配套元数据或诊断契约有变化时，先说明版本影响并由主审确认正式文档。
3. 编译与测试使用 Docker／现有 CI。远程没有环境时不安装宿主依赖，明确哪些未本地执行，把必要定向项接入 CI；不能用“无环境”代替未运行声明。
4. 启动 CI 后停止轮询，间隔 15 分钟再看；通过后停止并交审，失败则读日志、修复并重复该流程。PR 评论列明提交、范围、验证命令／结果、性能证据及剩余限制，不自合并。
5. 本轮是后端构模基础，不逐轮跑完整 GUI／工程案例；若诊断公开链实际改动前端行为，补相应定向浏览器验收。完整独立工程实测仍属于后续集成验收。
6. 正式指导文件由主审维护。开发者在 PR 提供需要修订的契约建议，不自行扩张语义；必要契约获批后再实现。无私有工程数据、业务参数或历史盲测材料进入开发输入及 PR。

### P1 最终交接给 P2／P3 的内容

- 单一、可遍历的关系集合与稳定符号身份；包含现有技术、网络、规划及财务贡献，不留黑盒回调旁路。
- 已有界来源及统一查询、需求定位入口；P2 可在不重写所有消费方的情况下增强推导。
- 可绑定的方程结构、时间索引及来源映射；P3 可增加相应领域贡献，不修改 Runtime 或复制行列分配。
- 同次解恢复与性能对照证据；明确哪些缺口尚属 P2／P3／P4，不能把 P1 完成等同于完整工程问题解决。

本计划实施完成后，将其归档；稳定结论只进入所属正式规范，实际完成事实进入更新日志。
