# 模型与算法实施交接清单

> 文档类型：内部实施控制模板；状态：生效；不属于帮助中心或长期产品规范。
>
> 长期架构、用户行为和公共契约分别以[架构宪法](../../manual/developer-guide/zh-CN/ARCHITECTURE_CONSTITUTION.md)、[模型与算法扩展指南](../../manual/developer-guide/zh-CN/customization-center.md)、相关格式标准和模块手册为准；版本范围、顺序与完成状态只以[Roadmap](../../manual/changelog/roadmap.md)为准。

本文件不再复述设备模型字段、插件安全规则、HTTP 端点、数据库表、算法参数或产品信息架构。创建具体任务交接时，只填写下列清单，并链接到唯一的权威章节。

## 交接模板

```text
Roadmap 事项：<稳定版本与未完成事项>
目标：<本次可独立验收的能力>
权威规范：<宪法/开发者指南/格式契约的精确链接>
范围：<要新增或修改的公开能力>
明确排除：<本次不得触碰的能力与版本边界>
数据与迁移：<无 / 迁移、回填、回滚策略>
验证：<Docker 测试、人工验收、静态检查>
提交边界：<一个独立、可回滚的提交>
```

## 执行要求

1. 开始前阅读架构宪法、任务引用的稳定规范和当前 Roadmap 事项；实现不得以本文件替代这些来源。
2. 一次交接只覆盖一个可独立验收的事项；复杂工作使用独立工作树，完成 review 后单独提交。
3. 所有安装、编译、迁移验证、测试和浏览器验收在 Docker 中进行；画布拖放与接口连接由人工验收。
4. 实现不得提前引入后续 Roadmap 能力，不得用临时兼容、静默默认或运行期热加载绕过正式契约。
5. 若发现稳定规范缺失、冲突或需要修宪，停止实现并提交问题；不得在交接文档中自行定义第二份规则。
6. 完成时记录实际执行的 Docker 验证、已知基线失败和归档/文档同步结果。

## 维护规则

- 具体任务完成后，交接内容应随任务删除、替换或归档；不得把已完成切片长期留作现行要求。
- 需要长期保留的结论先进入 `manual/` 对应正式章节，再归档其过程材料。
- 被替代的交接材料移入 `docs/archive/`，并声明归档日期、原因和替代来源。
