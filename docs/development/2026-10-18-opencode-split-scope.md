## 为什么分开

独立 HTTP 探针证明：项目模型保存返回 201，但其 `_N` 类型不在画布目录，建模命令返回 PROJ-CMD-005；同项目内置类型对照成功。这是既有消费断点，不是原四批改动引入的回归。保存测试和内置设备求解测试分别通过，不能合成为自建模型完整通过。

独立证据见主工作树 `docs/reviews/2026-10-18-codex-independent-project-model-gap-check.md`。新工作树没有被忽略的 docs，须用主工作树绝对路径阅读，不强制纳入 Git。

## CSV 预检误拒的限定裁决

2026-10-18：代码核查确认 builder 接受数据来源映射，而预检对 predefined 槽仍调用仅接受数值的 constant 校验，存在形态不一致。GUI 提交受预检阻断，尚须定向实测保存准确诊断及公开提交对照。

原实例选择“现有公开路径验收、记录缺口”，不附带修改生产预检，也不交给项目模型实例顺带重构。允许公开 API 完成来源绑定及任务提交，继续验证真实 CSV 消费；这只证明该公开 API 路径，不是 GUI 提交验收，更不是对缺陷的豁免。必须保留 GUI 失败证据，不能隐藏诊断、改成 constant 绕开数据输入、跳过闸门或声称整条用户流程/0.15 已完成。报告后由 Codex 独立安排有限修复；不要自行递归增加任务。
