# ADR-0006：设备文件收敛为纯技术统一契约

> 状态：已批准、文档已实施、代码待 Roadmap 迁移、已归档  
> 决策日期：2026-08-28  
> 批准依据：项目所有者在设备业务流程人工审查中明确批准  
> 决策基线：`4d287c4940b67f8114fa5295067b2d4b5a18c4d5`  
> 修订条款：架构宪法第 3、4、5、7、9、12、14、15、16、19 节

## 问题

现行 `ies.device-model` 把设备身份、设备独立语义版本、参数 schema、端口、数据输入、状态、模型方法、计算精度、能力和建模命令同时放在一份文件中。相同事实被多个字段重复表达：载能集合可以从端口推导，状态性和精度属于计算模型，存量/新增同时出现在设备实例与参数标记，价格引用又把项目经济假设混入设备技术定义。结果是设备文件不能作为所有设备共同遵守的最小技术抽象，也难以区分物理事实、序列交互、计算选择和财务假设。

## 决策

1. 所有设备使用同一 `ies.device-model` 文件语义；文件顶层固定为 `schema`、`schema_version`、`device`、`properties`、`interfaces` 和 `equations`。
2. 设备文件不再携带设备自身 `version`。`schema_version` 只版本化统一文件契约；设备内容以稳定 ID、规范字节 SHA-256、发布 revision 和校验回执固定，历史快照不引用 `latest`。
3. `device` 只描述稳定身份和显示信息；`properties` 只描述不随时间变化的技术常量；价格、成本、税、折旧和其他经济假设禁止进入设备文件。
4. 只有时序交互数据进入 `interfaces`。接口统一使用 `in`、`out`、`bidirectional`、`predefined`、`blind` 五种类型；未声明类型时规范值为 `blind`。
5. `in`、`out` 和 `bidirectional` 参与设备间连接；`predefined` 不连接其他设备，其输入只允许 `constant`、`data_repeat` 或 `data_predict`；`blind` 既不连接其他设备，也不接收预定义数据。
6. `equations` 以受限声明式方程表达属性、接口序列和内部变量的技术关系。计算精度、算法选择、求解器状态和运行策略不属于设备文件。
7. `data_inputs` 合并进 `interfaces`；`parameters` 改为顶层 `properties`；删除设备层的 `fidelity`、`model_method`、`stateful`、`energy_carriers`、`capabilities`、`states`、`model_commands` 和强制 `extensions`。
8. 新增设备与存量设备仍是不同项目实例语义：存量容量固定且不重复计入新增投资；候选新增容量由规划配置决定。该实例语义不写入设备类型文件。
9. 设备技术方程不读取价格。规划计算使用独立经济配置参与容量和运行优化，财务模块再基于规划结果与财务参数形成现金流、NPV、IRR 等评价。

## 影响

- 设备文件变为纯技术、统一、内容寻址的声明，不再因市场价格、项目币种或计算精度变化而产生另一种设备定义。
- GUI 可从 `properties` 生成常量表单，从 `interfaces` 生成序列绑定与连接交互；不能再从旧参数能力标记推断规划变量。
- 设备数据 CSV 改为绑定一个 `predefined` 接口及其内容摘要，不再绑定设备独立版本或 `data_inputs` 列表。
- modeling/assembly 需要解释受限方程、内部变量和五类接口；实现不得通过设备 ID 分支或私有命令映射恢复旧语义。
- 当前 JSON Schema、内置 YAML、解析器、DTO、数据库和测试仍是旧实现，必须按 Roadmap 一次性迁移；文档变更不宣称代码已经支持目标契约。

## 被否决方案

- 保留现行顶层字段但把它们都设为可选：仍会保留重复事实和多种等价表达。
- 把价格、单位投资成本和费率继续作为设备 property：相同技术设备会因项目、地区和年份不同而改变定义，且存量沉没成本与新增投资容易重复计算。
- 只保留设备 ID 与连接端口，由中心代码按设备类型补方程：会恢复静态设备映射，新增设备仍需修改核心代码。
- 让 `fidelity` 继续属于设备：计算精度是算法/模型选择，不是设备物理事实。
- 让接口同时使用 `direction` 和 `connection`：两组字段可以组合出无业务定义的状态，无法形成唯一规范语义。

## 迁移与回滚

Roadmap 在 GeneratorProvider 迁移前先完成新设备契约的 schema、解析器、规范化、目录、装配、CSV、前端和内置目录迁移。旧 `1.0.0` 文件仅作为显式迁移输入；迁移必须生成回执，禁止双读、静默 fallback 或运行期兼容分支。任务快照继续保留旧内容摘要与旧解析证据。

若新契约在实现前被否决，可以撤销本 ADR 对正式指南和架构宪法的修订；一旦新 schema 和项目数据开始生成，只能通过新的破坏性 schema 版本和显式迁移回退，不能把旧字段重新解释成新字段。
