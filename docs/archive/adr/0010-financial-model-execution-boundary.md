# ADR-0010：财务模型与执行框架边界

> 状态：用户于 2026-10-18 批准，指导文件已落实并归档；归档日期：2026-10-18。
> 归档原因：稳定原则已进入宪法 §4.6 与财务模块指南；本记录不作为并行规范。
> 现行来源：../../../manual/developer-guide/zh-CN/ARCHITECTURE_CONSTITUTION.md 与 ../../../manual/developer-guide/zh-CN/modules/finance.md。

## 问题与决策

只允许配置税率等参数、却固定财务计算方法，会使不同核算主体和财务规则被实现为程序特殊分支。用户明确批准：程序提供通用框架，具体方法在财务模型中规定，项目选择模型并提供参数。

修订宪法 §4.6，财务模型定义计算关系；通用数学能力可复用，内置模型为可替换模板。影响优化的关系必须参与求解，并与评价共用冻结规则。不把两个真实案例或主体名称写成程序分支，不新增任意代码执行入口、内部重复校验或运行期热加载。

## 影响与替代方案

选择开放且最小的模型契约，而非固定方法加参数开关；不为此提前建设完整财务语言、商城或插件平台。实际表达形式留给独立契约切片，现有 YAML 2.0.0 语义不变。通用框架、具体规则与参数分工清楚，但不要求新增配置副本或任务输入类别。

## 实施、验证与回滚

本次仅同步宪法、模块指南、格式边界、Roadmap 与更新日志，无代码、数据库、前端或公共 schema 迁移。后续按公开契约、模型执行、求解、展示与导出分步实现；以合成手算与独立真实实例验收，不泄露真实案例给开发方。文档检查包括本地链接、格式及相反条款检索；回滚需用户重新裁决并同步上述指导文件，不以代码兼容分支恢复旧边界。
