# ADR-0001：统一正式文档与版本计划

> 状态：已批准、已实施、已归档  
> 决策日期：2026-08-22  
> 批准依据：项目所有者明确要求  
> 修订条款：架构宪法第 1、6、15、17、18 节

## 问题

原治理把 `manual/` 正式指南与 `docs/` 活跃规格、方案和 Roadmap 分开维护。随着开发推进，稳定设计意图、当前实现、未来顺序和历史 Review 在多份文档中重复并冲突，开发者难以判断唯一依据；同时使用者指南无法按 GUI 完成完整工作流。

## 决策

1. `manual/` 成为唯一长期正文来源，包含三个并列入口：使用者指南、开发者指南、更新日志。
2. 开发者指南承担长期设计蓝图，吸收架构宪法和 Review 中经裁决后的稳定意图。
3. 更新日志包含倒序版本历史与独立 Roadmap。
4. `docs/` 只保留 Review 导航和只读 archive，不再维护活跃规格、合同或实施计划。
5. 产品采用三段式版本；当前基线 `0.1.0`，首个正式版 `1.0.0`。
6. 未实现功能只写入 Roadmap；正式指南不得把目标状态描述成现有 GUI 能力。

## 被否决方案

- 继续让 `docs/spec`、旧合同和 Roadmap 与开发者指南并行生效：会维持双事实源。
- 直接把 Review 原文复制进开发者指南：会带入已废止的 fallback、热加载和兼容设计。
- 删除旧材料：会丢失审查证据和决策背景。

## 迁移与回滚

旧资料整体移入 archive，Review 移入 reviews；正式结论经过提炼后写入 `manual/`。如需回滚目录结构，可通过版本控制恢复文件位置，但不得恢复多份文档同时作为权威来源的治理方式。

本 ADR 的规范内容已进入架构宪法和正式指南，因此归档后不再单独维护。
