# ADR-0012：评价确认独立进入生成器

> 状态：用户批准后归档；归档日期：2026-10-20。
> 归档原因：用户确认财务时点与运行步序列职责不同，批准评价确认独立直传；稳定结论已进入宪法 §4.5、财务及生成器模块指南。
> 现行替代来源：`manual/developer-guide/zh-CN/ARCHITECTURE_CONSTITUTION.md`（1.16.0）、`modules/finance.md`、`modules/generators.md` 及 `contracts.md`。本文件仅记录决策，不作为实现规格。

## 问题、证据与裁决

C0 核实生成器原五项输入缺少快照中已冻结的建设期、折现率、付款计划和维护清单，无法形成正确税后全周期目标。将其平铺进物化集合虽能保持五个参数，却把财务时点与运行步长混在一起。用户批准按职责独立传递评价确认，而非维持固定参数数量。

§4.5 增加已冻结评价确认的独立直接输入，保留纯生成、无外层包装、无第二事实源等限制。输入值对象归 finance，application 恢复同一快照后传递；不新增用户输入、不改变评价 HTTP 或冻结块字段。

## 替代方案与影响

未采用混入运行序列、财务三件套、封闭计算配置或改写已签发装配的方案。显式输入使 provider 可替换、Bundle 可确定重建，不引入共享可变状态；内部不重复校验。该调用协议为破坏性变更，生成器升主版本，调用者一次迁移，无旧签名兼容；通用 runtime 与未改变的结果协议不跟随升版。

## 迁移、验证与回滚

先提交正式指导，再同步公共值对象、调用链及直接消费者，以冻结恢复、预测轮次传递和真实模型时域构建验证。数据库、用户表单及历史文件格式不因本次指导变更而变。文档及后续代码均独立提交，需要回滚时使用反向提交，不改写历史或删除开发工作树；版本元数据须与配套代码一同回退。
