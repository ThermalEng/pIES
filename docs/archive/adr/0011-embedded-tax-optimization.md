# ADR-0011：必要税务关系嵌入同一次规划求解

> 状态：用户批准后归档；归档日期：2026-10-19。
> 归档原因：用户已选择嵌入式方案并要求同步指导文件，稳定结论已进入正式正文。
> 现行替代来源：`manual/developer-guide/zh-CN/ARCHITECTURE_CONSTITUTION.md` §4.6 与 `manual/developer-guide/zh-CN/modules/finance.md`「税务参与规划与现金流」。本文件只作决策追溯，不作为实现规格。

## 原因与裁决

回退到已验收主线后，宪法仍将税务与折旧排除在财务范围外。用户重新比较嵌入式求解与税前最优邻域搜索后，选择前者，并批准按公式作用分类、明确增值税留抵关系；本次仅同步原则和模块正文，不恢复此前撤回的通用财务语言及字段设计。

## 边界与替代方案

财务关系通过生成器参与同一次优化；只实现明确需要的系数、当期关系和跨期余额，不扩大到申报、融资或资本金评价。未选用税前邻域敏感性／插值作为正式税后优化保证；它仍可作为明确标注的方案分析。继续遵守公开边界校验、模块自治和冻结输入，不新增内部重复验证。

## 影响、迁移与验证

本次无代码、数据库、API 或 schema 迁移；现有税目登记不自动获得计算能力。后续实现先确定必要的版本化输入，再分步接通生成器、同源评价与页面／导出；验证按风险使用合成手算、税务状态及对应用户流程，不向现有能力追认税后标签。
