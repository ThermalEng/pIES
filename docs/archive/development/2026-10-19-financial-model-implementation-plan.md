## 一、为什么做，最终得到什么

当前财务三件套主要表达成本、价格和税目登记；真实任务链通过固定的分量归集形成现金流，尚未形成自定义财务方法和完整税后优化链。只补税率开关，仍会把不同财务方法写成程序分支。

目标是：用户提供或选用一份声明式财务模型，填写该模型需要的参数，绑定实际建设量、运行量及计费事实。程序执行同一份模型关系完成方案求解和逐年评价，封存税前/税后现金流与指标，页面和导出读取该任务的封存结果。

最终应做到：在已公开支持的数学能力内，更换收入、折旧或计税关系只需修改模型文件，而不改 API、Worker、前端业务分支或生成器里的专属税务公式。超出公开能力的模型明确报告不支持，不退回固定旧算法，也不承诺任意公式均可求解。

不新增第六类核心输入，不改项目工作区/不可变任务语义，不另造财务任务系统、模型商城、插件热加载或通用编程语言。建设选择、容量和运行量仍是规划决策；“参数明确”不等于事先固定决策变量。

## 二、可保留的基础与需改变的边界

基线代码定位证据（实施时重新确认调用路径，不把路径变成长期规范）：

| 位置 | 当前作用 | 本计划的处理 |
| --- | --- | --- |
| `backend/iesplan/finance/triplet.py` 的 `EffectiveFinanceConfig` / `merge_effective` | 财务参数合并及不可变有效配置 | 沿既有财务输入边界扩展，不平行建立第二份有效配置 |
| `backend/iesplan/computation/generators/project.py` 的 `build_project_model` | 合并技术关系、财务分量与规划目标 | 经 finance 公共契约加入模型数学关系，不自己维护税务业务公式 |
| `backend/iesplan/application/worker/compute_cases.py` 的 `build_financial_evaluation` | 从冻结输入和同次解组织财务评价 | 保留应用编排职责，具体方法移交模型执行；不在 Worker 添加税种分支 |
| `backend/iesplan/finance/evaluation.py` | 从现金流计算指标 | 复用通用数学能力，不要求每个模型重写 NPV/IRR |
| 配置修订、任务快照、结果与项目包链 | 固定、消费和交换输入输出 | 逐个迁移消费者，保留同任务追溯和历史不变语义 |

旧 `FinanceParams`、`compute_financials` 等简化路径不能因已有税率/折旧公式就视为目标实现；先查真实消费者，替换后删除已无用途的旧规则及对应测试，不为兼容重新接回默认值与 fallback。

## 三、顺序与独立交付

阶段按依赖串行推进，每阶段可拆成多个小提交；公开输入或一个消费者迁移通过审查后独立提交，不能把整阶段强行塞成一次大改。阶段验收通过不等于整体完成。

### F1：先定最小公开契约

**范围**：只做契约设计、正式文档和可独立理解的合成样例，不做业务实现。

必须解决以下设计点，而不是只写“支持自定义”：

1. 模型身份和不可变修订、文件字头与版本，以及如何随现有财务输入进入 `EffectiveFinanceConfig`；不机械复制设备模型库生命周期。
2. 模型规则、项目参数、运行事实三者的归属和引用方式；财务三件套与评价确认已有的参数不重复存两份，规划配置仍选择优化目标。
3. 最小声明式关系：输入/中间量/输出、类型、单位、时间轴、年度归集、跨年状态与初值；明确允许的运算和依赖关系。先审计现有公共数学能力可复用部分，不把财务规则塞入设备技术方程或穿透私有实现。
4. 收入与节省费用、固定/使用运维、维护换新、税款、折旧及资产处理如何通过关系表达；核算主体是模型的口径，不是程序里的固定枚举分支。具体适用税率与政策由选定模型及项目显式提供，不制定软件默认税法。
5. 模型需要的计税基础、抵扣/结转和资产账面变化，如何表达并进入同一现金流；不适用的规则由模型明确，不强迫所有模型填写无关税目。
6. 模型输出如何被规划目标引用、如何形成财务明细和税前/税后结果；生成器如何声明数学能力，不能表示时在哪个公开提交边界拒绝。
7. 模型规则和参数如何冻结、随项目包携带，以及结果版本如何与输入版本对应；列出受影响 schema 和消费者，破坏性变更明确升主版本，不预留旧格式双轨。

**产物**：正式财务格式/模块/公共契约的必要修订、完整合法文件样例、非法样例、手算预期与消费者迁移清单；权威 schema 如已维护，则同步更新，不手写第二套字段表。未完成实现时明确目标契约状态，使用者指南不声称已交付。

**出口**：独立审查者仅凭正式契约即可写出模型、绑定参数并解释每项输出；至少能用两个不同方法的合成模型证明“不是固定算法加参数开关”。字段形状、时间与符号语义不能留给开发者猜。必要产品选择向用户说明影响后裁决；已有业务规则不重复提问。

**与真实案例的衔接**：F1 定稿后，验收方可从归档副本恢复实例准备，补齐所选模型的显式参数和剩余用户裁决。真实案例资料不进入开发背景；不能因为案例尚未启动就省略通用契约需求，也不能在 F1 预设隐藏案例参数。

### F2：模型解析与纯执行闭环

**依赖**：F1。

- 在 finance 内实现唯一正式文件解析入口、类型化模型和最小执行能力。
- 输入校验只针对公开模型/参数边界的实际语法、引用、类型、单位、时间及核心业务约束；内部传递不再验文件、摘要或同一规则。
- 已给定建设与运行事实时，模型可以生成逐年分量和现金流；通用指标继续复用。
- 只提供当前模型所需的通用数学原语，不新增针对某税种、设备或客户的执行分支。

**验证**：合成手算对照、参数变化和方法变化都影响输出；年度状态、建设/运行时点、含税金额与税后结果区分；非法公开输入给可定位诊断。参考答案独立手算，不能调用被测实现生成。

**出口**：文件→模型→给定事实→财务明细可复核。这一步只证明纯执行，不宣称税后优化已经接通。

### F3：接入已有财务修订与任务冻结

**依赖**：F2。

- 按 F1 选定的载体接通财务配置保存、合并、精确修订引用和任务快照；优先迁移一个公开保存/提交消费者，再推进相邻消费者。
- 所需模型参数缺失在输入/提交的真实业务边界阻断，不补默认税率、折旧年限、优惠或最新模型。
- 保持当前项目工作区可编辑；仅在发起计算时把模型和参数固化进任务。切换历史任务不修改原输入输出。
- 计算中的容量等决策仍为变量，不要求用户为“确认参数”填入求解结果。

**验证**：保存与文件往返、缺参/错单位拒绝；提交后修改模型或参数不改变原任务；模型内容与参数沿既有有效财务事实传递，没有第二权威配置。

**出口**：任务能完整固定所选模型及参数，生产计算路径尚未迁移完成时不能对外宣称支持完整新模型。

### F4：模型关系进入全周期求解

**依赖**：F3。

- finance 提供求解器无关的公开关系，由 GeneratorProvider 接到同一全周期模型中；求解器文件、内部单位转换仍归 generator，不交给 finance/Worker。
- 优化目标引用模型输出；税务、折旧等影响决策的关系真正参与方案选择，不在税前求解完成后补算冒充税后最优。
- 对状态结转、正部/分段等非线性关系说明精确建模与能力边界；不能用“目标会自动压低辅助变量”当作任意目标下等价的证明，不能猜 epsilon、big-M 或最小建设量。
- 不借机扩大到融资、资本金评价、非当前所需算法或重写整个技术计算链。

**验证**：真实 solver 的小型合成问题可穷举方案独立复核；至少一例税前与税后最优选择不同；改变财务模型而不改程序应改变关系和方案。检查求解方向、边界、状态与最优性证据，不只检查成功返回。

**出口**：选定支持能力内的模型可用于真实全周期优化；无法表达的用户请求有明确不支持诊断，不静默降级。不因通过此阶段就宣称所有财务方法均支持。

### F5：结果适配、评价和封存同源

**依赖**：F4；本阶段按适配、应用封存、读取逐个消费者提交。

- 从同次求解结果和冻结模型形成税前/税后逐年明细与指标；共用模型关系，不在结果适配器或应用层抄写计税公式。
- 延续现有 DB 事务封存任务结果、对象元数据、引用与证据；不夸大外部 Blob 的跨资源原子性。
- 明确结果口径和缺席/失败状态；没有可用结果时不伪造空现金流或税后指标。
- 查询与导出读封存事实，不读当前模型重算历史结果。

**验证**：以 F4 同次解核对分量、完整现金流和指标；结果不可用、任务切换与配置后改场景；仅复用实现函数比对自己不算独立正确性证据。对比属于测试，不成为生产期重复核验。

**出口**：模型输入、求解目标与财务结果可追溯至同一任务，没有求解一套、评价另一套的业务公式。

### F6：用户入口、同任务报告与项目包

**依赖**：F5；输入、展示、导出、项目包各为独立可审阅切片。

- 优先复用现有财务配置入口，提供模型文件和参数的真实用户操作；首版不要求另造可视化公式编程器或模型商城。
- 表单如存在，直接生成正式配置文件；人工文件和表单共用同一后端解析入口，不建简化协议。
- 展示模型声明的必要明细、税前/税后现金流和指标；避免按模型 ID/客户名称写前端字段映射分支。
- 报告与导出仍针对所选已完成任务；未完成任务不显示或导出其他任务结果。
- 项目包携带该工作状态及历史任务解释所需的精确模型/参数依赖，支持在没有同名内置模型的环境中恢复；不静默替换为新模板。

**验证**：Docker Playwright 从真实公开页面输入文件/参数、发起求解、查看切换、导出；定向项目包往返及缺依赖错误。不得注入数据库或前端状态绕过被验收步骤。

**出口**：用户能通过公开入口使用自定义模型，查看及导出同一任务结果，并保存可解释的项目现场。示例模型和用户模型走同一路径。

### F7：清理旧路径与独立退出审查

**依赖**：F6。已被替代的小块旧代码应在各切片迁移时及时删除，不全部拖到本阶段。

- 查实际调用链和运行证据，清除已替代的固定业务公式、隐式默认、旧响应与兼容路径及其无效测试；不因文件名“旧”就删仍复用的通用数学能力。
- 检查是否新增了多层无人消费的抽象、内部重复校验、双配置源或过度文档。
- 以冻结的合成验收矩阵做一次影响范围集成审查；每轮不重建全仓问题清单，不把无关既有失败自动变成本切片缺口。
- 更新使用者指南、更新日志和剩余 Roadmap；稳定内容进入正式规范，完成后的本计划归档。

**出口**：模型可替换、参数可配置、求解和结果同源、用户路径闭环。真实案例再以独立验收完成 0.15 相应退出标准，不能用本计划阶段通过替代真实验收或整个 0.15 其他事项。

## 四、派工、审查与防止原地转圈

1. F1 已完成；下一步只启动 F2。后续每次派工写明阶段、已批准基线、一个交付目标、允许改动范围、明确排除项、验收证据和停止点。
2. F1 和第一次 F4 求解接通属于关键串行工作。契约冻结后，同一波可并行做互不改同一事实源的合成测试参考、文档/界面准备；依赖未具备时不靠猜字段提前开发后续生产消费者。确需 agent 并行时，各自使用主仓库内持久独立工作树。
3. 执行者报告不作为完成证明。审查者对照本阶段出口、真实 diff、调用路径、测试输入及关键断言独立裁决；已有可用测试证据不无意义重跑。
4. 每阶段保留固定验收矩阵及明确未完成项。发现问题先区分：本次引入、当前阶段必须补齐、后续已规划、无关既有问题；只给执行者一个有边界的修正清单。
5. 只修改当前切片必需的测试；公开字段/事务/关键业务变更做定向及直接受影响集成回归，GUI 用真实浏览器。不要每次局部变更都跑全仓，也不能用“局部范围”跳过被改动的公开消费者。
6. 测试和编译只用 Docker。清理本任务创建的测试镜像，不删基础镜像、归属不明镜像、用户容器或数据卷。验证脚手架与生产模型规则严格分开。
7. 此计划和 `docs/` 仍被 Git 忽略。执行交接只提供本计划、权威手册和合成数据，不开放真实案例归档；共享给独立工作树时显式复制必要文件，不解除整个 `docs/` 的忽略。
