## 1. 本切片的完成含义

S1 已把规划声明、全部实例静态绑定、逐步列展开和技术关系转换分开，并建立内部 `CompilerInventory`。当前关系族只收集设备 AST；母线、规划、需量、税务及财务关系仍由后续函数直接构造。

S2 将这些现有关系纳入同一个可分析集合，随后统一绑定和分析，再执行原有精确转换。公开生成入口实际消费该集合，最终模型、目标和结果声明同源。

完成标准是：转换开始前能看见全部输入关系，转换所需的符号、期间、已有界与来源可明确取得；不以运行某个旧函数才能知道它生成了什么关系。

本轮保持现有模型业务语义。P2 的新增界传播、有效域语义迁移及建设激活，P3 的网络和财务新能力，P1-S3 的批量模板展开，以及 S4 的来源持久化分别接续推进。

## 2. 关键路径与运行结构

```text
现有六项已冻结输入
  ↓
声明符号、关系族与语义输出
  ├─ 设备方程、状态初值与容量关联
  ├─ 当前母线守恒
  ├─ 标量规划、逐步约束与目标
  └─ 当前费用、计费聚合、需量、维护、税务和现金流
  ↓
绑定引用、单位、已知系数、运行／财务期间
  ↓
完整关系集合（只读视图）
  ↓
统一分析：使用关系、表达式依赖、已有界与转换需求
  ↓
按明确依赖执行现有精确转换，生成辅助符号／关系
  ↓
现有逐步展开、行列分配与同次解声明
  ↓
LinearModel → writer → 既有 Bundle／Adapter
```

这里的“统一”发生在单次生成器编译中。技术关系仍来自 modeling，财务关系仍按 finance 规则产生；不创建全局注册表，也不让 modeling 解释税务或 Runtime 解释业务。

关键依赖：**完整可分析关系 → 统一的引用及边界需求视图 → 原有条件转换 → 实际行列与结果引用**。来源和协作停止贯穿各阶段。

## 3. 关系集合要包含什么

| 来源 | 收集内容与边界 |
| --- | --- |
| 技术贡献 | 原设备 AST、状态初值、规划 property 接管与容量限制。初值保留常量或仿射符号关系；S1 的来源及已知系数分类继续使用 |
| 网络 | 按当前版本的母线归组收集守恒关系，引用原接口符号；本轮不改变设备两侧的网络解释 |
| 规划 | 启用的标量约束、逐步约束、目标和局部端口绑定；规划变量为全期共用标量，逐步端口保持实际 step |
| 成本与计费 | 现有成本分量、能源购售、固定年费及可变运维的仿射表达和期间聚合。购售方向、年率及积分语义不变 |
| 维护与净收付 | 逐笔发生年及来源表达式、已定义净现金项目；现金、税额与恢复引用同一金额关系 |
| 月需量 | 计量点、实际自然月范围、峰值输出与现有精确最大值操作；不能只保存一个不可检查的月峰构造器 |
| VAT | 现有进销项基础、建设／维护进项、抵扣池月度状态、实缴与退款，以及分段转换条件 |
| 所得税与折旧 | 应税基础、资产折旧、亏损批次与到期顺序、正负分段、领取操作、税额及年度扣付；不改变现有税盾或扣除规则 |
| 结果与目标 | 普通目标／NPV 与 `components`、`step_series`、`financial_facts` 的符号引用。普通目标也保留原有财务事实输出 |

不同领域不必伪装成设备 `MathRelation`。内部表示可使用技术 AST、已编译规划表示、仿射关系、聚合及现有条件操作的类型化组合；它们共同暴露参与符号、索引、已知系数依赖、原关系及转换需求。类名由开发者选择，避免把所有结构塞进自由字典或自由公式字符串。

关系集合允许物理联立约束成环。只有编译表达式和辅助输出的生成依赖需要明确求值次序；不能把物理反馈环当成非法依赖。税务余额按期间和批次连接，不能依靠字典或方法遍历顺序决定扣除顺序。

语义层先声明“月峰”“当期税额”“期末余额”等输出。精确转换引入的二元及辅助连续变量可以稍后生成，不要求收集阶段先猜出它们的数值界或全部实际列。

## 4. 统一分析与现有算法的接法

### 4.1 绑定与使用关系

局部设备名、规划别名、计量绑定、财务分量和期间引用绑定为稳定符号；规划接管后的属性不再被当作已知系数。设备预定义输入和价格仍消费冻结物化值，按原规则转换内部单位。

为真实分析建立符号使用关系：可以查询某个容量、端口、聚合或金额参与哪些关系，以及哪些转换依赖它。使用索引是可重建的编译数据，不能成为第二权威源。

输入在原公开边界已完成的结构、引用合法性和量纲校验不再重跑；本阶段执行的是实际数学绑定、单位换算与依赖求解。已禁用的关系不进入有效数学集合，未使用的价格或费用条目不产生额外约束。

### 4.2 边界查询与转换需求

本轮把现有生效界及现有区间计算统一接入分析入口。互斥、月峰、VAT 和所得税转换由该入口取得所需表达式的上／下界，不再各自散读旧属性、局部变量字典或自行计算不同版本的区间。

统一入口至少能表达：查询对象及其期间、哪条原关系提出需求、取得的界和来源，或“当前分析未取得所需条件”。对象可以是变量、仿射表达式或聚合；不能只支持变量名。

P1-S2 复用现有区间推导能力，不新增从任意等式／不等式传播界的算法，不把规划 null 上界替换为模板参考大数。普通线性变量可以没有有限上界；无法取得某转换需要的界，仍报告当前生成能力不足。

这条入口必须由生产中的真实消费者使用。新增类但继续让互斥、月峰和税务使用各自原来的隐藏界算法，不算完成。P2 应能增强这一个分析入口而不重写所有领域转换。

### 4.3 有依赖次序，不再边遍历边降级

现有金额及聚合先形成符号关系；需量、税务按其输入和输出建立明确依赖。分析可以按需取某步系数，随后条件操作生成精确线性表示及辅助变量的界，再供依赖操作使用。

不能先运行 `_build_monthly_demand` 或 `_build_income` 生成所有行，再将生成结果倒填 inventory 宣称“先收齐”。也不能把这些方法包装成回调队列。收集完成视图应已经说明原关系、语义输出和转换条件，最终线性辅助行则在转换阶段产生。

财务、目标和结果声明引用同一金额／聚合输出；不在输出恢复阶段重建财务模型。当前的零界特化、月峰精确性、亏损扣除次序及费用发生时点全部保留。

## 5. 来源、时间和规模控制

沿 S1 的来源身份给新关系标注约束、绑定、税则、池、维护条目或现金项目的归属。辅助行保留父关系与转换角色；聚合可关联多项来源，不能只归给最后访问的设备。

时间维度明确区分标量、运行步、结算月、运营年与评价年。首次状态引用、跨月／年连续状态、建设付款、换新计提起点和损失批次到期保持原语义；按块构造也不得断开相邻期间。

本轮来源保留在内部编译链，继续使用既有诊断与 Bundle 输出。新的持久化来源字段归 S4，由主审先完成正式契约；不临时追加 `source_map`、ComputeResult 字段或新的诊断码。

关系族保留索引域、系数来源及原表达式，避免为“完整收集”先复制全期 AST 和长字符串。按实际消费取得系数，不先展开一套完整原始模型再复制一套线性模型。S2 可以继续使用既有逐步降级，S3 再系统实现模板复用与批量实例化。

## 6. 实现顺序与审查点

| 步骤 | 主要任务 | 审查点 |
| --- | --- | --- |
| A：扩展内部表示 | 在 S1 的 inventory 上接入现有仿射、聚合及条件操作，明确符号与输出身份、时间维度和来源 | 所有结构可检查；初建／运行／税务语义不被通用结构抹掉；公开输入保持原契约 |
| B：收齐技术、网络和规划 | 设备关系、容量行、当前母线、标量／逐步规划和目标进入集合 | 此时不要宣称完整 S2；财务还需后续接入。设备和规划收集顺序不影响引用绑定 |
| C：收齐当前财务关系 | 费用、计量、需量、维护、VAT、所得税、折旧、净现金及恢复声明接入同一集合 | 条件操作不提前生成求解行；时间、批次和金额归属可遍历，保持同次解 |
| D：统一分析并切换生产入口 | 完成关系收集后统一绑定、查询已有界，按依赖转换、展开及输出；迁移全部消费者 | `generate` 真正走新链，删除被替代路径，不维护旧构模器 fallback；协作停止及确定性保持 |
| E：定向集成与对照 | 小型手算、已有真实求解链、S1 基线及选择器验证 | 取得可核查证据，说明实际覆盖及剩余 P2／S3／S4 工作 |

以上步骤在同一个 S2 PR 内推进。开发中可以分提交；交审时以本切片完整执行链为单位，不将半迁移标为 S2 完成。公共结构与主生成入口由同一开发主线维护。

## 7. 验收要求

1. **汇集屏障**：通过实际 generate 链检查，条件转换调用时全部已启用的技术、网络、规划和现有财务关系已收集。至少有跨来源符号使用的合成用例，不能只断言集合数量或函数调用顺序。
2. **顺序与身份**：反转不具有业务顺序含义的设备／约束映射，得到等价问题；保持维护同年位置和亏损优先顺序。两个实例共享模型时仍分别绑定，规划标量与所有步共用同一容量符号。
3. **统一界入口**：实际互斥、月峰、VAT 和所得税从同一分析入口取条件。现有有限界／恒零场景保持结果，缺有限界仍定位原关系；不要求新增界传播用例在本轮求解通过。
4. **时变与状态**：非常数输入和电价、仿射初值、跨年运行状态及税务余额保持正确；当前月份日价格按原公历映射，建设和维护支付时点不变。
5. **数学与财务对照**：小规模模型核对可行性、目标、峰值、VAT、所得税、维护／净收付与年度现金；真实 HiGHS 和既有 Worker／Adapter 链使用同次主解。多最优解可有不同曲线，不能强求曲线完全相同。
6. **真实消费者回归**：按影响保留电池规划、线性降级、项目模型、逐步约束、NPV、需量、VAT、所得税、维护／财务执行及全周期链覆盖；直接受内部函数拆分影响的测试同步迁移，不恢复旧兼容入口、删业务断言或改设备模板。现有选择器按必要消费者补齐，保持定向运行。
7. **资源证据**：沿 S1 的公开 campus 合成输入和同环境测量方法报告规模、构模／MPS／元数据耗时及峰值内存，标明 tracemalloc 开销和累计 RSS 口径。模型规模、整数数量或产物体积有变化时说明原因并验证数学含义；新增关系集合的内存应随关系结构增长，而非额外常驻一套全时域 AST。

本轮不设任意秒数通过线，也不能只交结构设计而不给实际运行证据。由合成输入验证公共能力，独立工程盲测继续留到集成阶段。

## 8. 远程交付流程

- 在本计划 PR 分支承接实现，保留计划及主审文档提交。正式指导由主审维护；发现确需改变公开契约时，在 PR 评论提出具体消费者、字段和版本影响，由主审补齐正式规范后再实现。
- 远程无本地环境时使用现有 Docker CI，不安装宿主依赖；合成测量由 CI 中的已有测试入口提供，明确哪些未本地运行。
- 启动 CI 后停止轮询，间隔 15 分钟再检查；失败则读日志修复并重复，通过后停止交审，不自行合并或进入 S3。
- PR 正文与评论说明精确提交、各类关系的收集／分析／转换落点、真实测试结果、资源证据及剩余限制。现有诊断链和来源协议的约束不靠新建交接文档替代。
- 本轮以后端定向测试为主，遵守现有 CI 选择；没有新增界面流程时不额外派完整 GUI 探索或工程案例验收。工作流选中的浏览器项照常执行。

主审按上述范围独立复审，完成后记录实际交付并启动 S3。P1 的整体完成仍以总计划退出要求为准。
